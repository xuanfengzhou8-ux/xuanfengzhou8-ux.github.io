# 带头结点的单链表

## 为什么需要头结点

单链表指针域只有一个方向（要么保存上一个节点，要么保存下一个节点）。

- **不带头结点**：首节点就是第一个数据节点
- **带头结点**：有一个额外的头结点，保存 `first` 和 `last` 指针

### 带头结点 vs. 不带头结点的对比

| 对比维度 | 带头结点 | 不带头结点 |
|---------|---------|-----------|
| 空表表示 | 头结点指针域为 NULL | 头指针为 NULL |
| 插入/删除首节点 | 无需修改头指针，统一处理 | 需要特殊处理，修改头指针 |
| 代码统一性 | 首节点操作与普通节点一致 | 首节点需单独判断和编写代码 |
| 函数参数 | 无需传二级指针 | 插入/删除首节点需传二级指针或返回新头 |
| 额外空间 | 多一个头结点空间（常数级） | 无额外开销 |
| 遍历起始 | 从头结点 next 开始遍历 | 从头指针直接开始遍历 |

**带头结点的优势**：插入和删除操作的代码更统一，不需要单独判断首节点的特殊情况；空表和非空表的处理逻辑一致。

**不带头结点的优势**：节省一个节点的存储空间；链表结构更直观，头指针直接指向第一个数据节点。

> 在嵌入式场景中，代码的简洁性和可维护性往往比节省一个节点的空间更重要，因此带头结点的实现方式更常见。

### 哨兵节点（Sentinel Node）模式

头结点本质上是一种**哨兵节点（sentinel node）**设计模式。哨兵节点是一个额外的节点，不存储实际数据，仅用于简化边界条件的处理。

哨兵节点的核心思想是：**用空间换逻辑统一性**。其主要好处包括：

1. **消除空表特判**：即使链表为空，头结点依然存在，`first == NULL` 即可表示空表，头结点本身不会消失
2. **统一插入/删除逻辑**：在任意位置（包括头部）插入或删除节点时，不需要对第一个节点做特殊处理
3. **简化遍历**：遍历总是从 `head->next` 开始，不关心链表是否为空

```c
// 不带头结点的插入 ———— 需要单独处理首节点插入
void insert_without_head(struct node **head, int data) {
    struct node *new_node = malloc(sizeof(struct node));
    new_node->data = data;
    if (*head == NULL) {        // 特判：空链表
        *head = new_node;
        new_node->next = NULL;
        return;
    }
    // 普通插入逻辑...
}

// 带头结点的插入 ———— 统一处理，无需特判
void insert_with_head(struct h_node *head, int data) {
    struct node *new_node = malloc(sizeof(struct node));
    new_node->data = data;
    // 无论链表是否为空，逻辑完全一致
    new_node->next = head->first;
    head->first = new_node;
    if (head->last == NULL) {
        head->last = new_node;
    }
}
```

### 在嵌入式固件中的应用

在嵌入式 C 语言开发中，带头结点的单链表有着重要的实际意义：

**1. 简化空链表边界情况**

嵌入式系统中常使用链表管理动态资源（如内存块、任务队列、消息缓冲区）。带头结点后，空链表和非空链表的操作代码完全一致，减少了因空表特殊处理而引入的 bug 可能性。

**2. 中断安全（Interrupt-Safe）的链表操作**

在嵌入式系统中，主循环和中断服务程序（ISR）可能同时操作链表。带头结点可以简化临界区保护逻辑：

```c
// 中断中向链表尾部追加节点
void isr_append(struct h_node *queue, struct node *new_node) {
    // 只需关中断保护 last 指针的修改，逻辑简洁
    new_node->next = NULL;
    if (queue->first == NULL) {
        queue->first = new_node;
        queue->last = new_node;
    } else {
        queue->last->next = new_node;
        queue->last = new_node;
    }
}
```

**3. 固定头结点地址**：头结点通常作为静态或全局变量分配，地址固定，便于 ISR 或 DMA 等硬件模块通过固定地址访问链表。

### 链表问题中的"哑节点"技巧

在算法和面试题中，**哑节点（Dummy Node）**是头结点思想的一种推广。哑节点是一个临时的头结点，用于简化插入和删除操作，最后再将其跳过。

典型应用场景：

```c
// 使用哑节点删除链表中所有值为 val 的节点
struct node *remove_elements(struct node *head, int val) {
    struct node dummy;
    dummy.next = head;
    struct node *prev = &dummy;
    struct node *curr = head;

    while (curr != NULL) {
        if (curr->data == val) {
            prev->next = curr->next;
            free(curr);
            curr = prev->next;
        } else {
            prev = curr;
            curr = curr->next;
        }
    }
    return dummy.next;  // 跳过哑节点
}
```

哑节点使得删除头节点时无需额外判断，统一了删除逻辑。这一技巧在合并链表、链表分区等问题中同样适用。

struct h_node *Great_node(struct h_node *l)

## 面试练习题

### 带头结点和不带头结点的区别与优缺点

**来源**：虚拟搜索公司丁 2020 校招

**回答要点**：

| 维度 | 带头结点 | 不带头结点 |
|------|---------|-----------|
| 空表状态 | `head->first == NULL`，头结点始终存在 | `head == NULL`，头指针为空 |
| 插入首节点 | 与普通节点逻辑一致，无需修改头指针 | 需单独判断并修改头指针 |
| 删除首节点 | 与普通节点一致，统一处理 | 需更新头指针指向下一个节点 |
| 代码复杂度 | 较低，边界条件统一 | 较高，需要特判第一个节点 |
| 函数签名 | 传一级指针即可修改链表 | 需传二级指针或返回新头指针 |
| 空间开销 | 多一个头结点 | 无额外开销 |
| 遍历方式 | `p = head->first` 开始 | `p = head` 开始 |

**核心结论**：
- 带头结点使代码更简洁、更健壮，尤其在需要频繁插入/删除首节点时优势明显
- 不带头结点节省一个节点空间，适合对存储极度敏感的场景
- 面试中，涉及插入/删除首节点的问题，推荐先创建哑节点（dummy node）统一边界

```c
// 带头结点 ———— 插入首节点
void head_insert(struct h_node *h, int val) {
    struct node *p = (struct node *)malloc(sizeof(struct node));
    p->data = val;
    p->next = h->first;   // 无论 first 是否为 NULL，均可工作
    h->first = p;
    if (h->last == NULL) {
        h->last = p;
    }
}

// 不带头结点 ———— 插入首节点
void nohead_insert_front(struct node **head, int val) {
    struct node *p = (struct node *)malloc(sizeof(struct node));
    p->data = val;
    p->next = *head;      // OK，next 指向旧头
    *head = p;            // 必须更新头指针
}
```

### 原地逆置带头结点的单链表

**来源**：虚拟互联网公司丙 2021 秋招

**题目**：给定一个带头结点的单链表，在不开辟新空间（不能使用数组或 malloc 新节点）的前提下，将其原地逆置。

**解题思路**：使用头插法思想，遍历原链表，将每个数据节点从原位置取下，头插到新链上。带头结点的情况下，操作更为简洁。

```c
void reverse_linklist(struct h_node *h) {
    if (h == NULL || h->first == NULL || h->first->next == NULL) {
        return;  // 空链表或只有一个节点，无需逆置
    }

    struct node *prev = NULL;         // 已逆置部分的头
    struct node *curr = h->first;     // 当前正处理的节点
    struct node *next = NULL;

    while (curr != NULL) {
        next = curr->next;   // 保存下一个节点
        curr->next = prev;   // 反转指针方向
        prev = curr;         // prev 前移
        curr = next;         // curr 前移
    }

    // 更新头结点的指针
    h->last = h->first;      // 原首节点变为尾节点
    h->first = prev;         // prev 指向原尾节点，成为新首节点
}
```

**复杂度分析**：
- 时间复杂度：O(n)，只需一次遍历
- 空间复杂度：O(1)，仅使用三个指针变量

**关键点**：
- 使用 `prev`、`curr`、`next` 三指针配合，逐步反转链表
- 需要显式更新头结点的 `first` 和 `last` 指针
- 用 `next` 保存后续节点，防止链表断裂

### 删除链表中最小值节点

**来源**：虚拟电商公司乙 2019 实习 / 常见面试题

**题目**：给定一个带头结点的单链表，设计算法删除其中数据域值最小的节点（假设最小值唯一）。要求只遍历一次链表。

**解题思路**：遍历链表，同时记录当前最小值节点及其前驱节点。由于是带头结点，即使最小值在首节点也能统一处理。

```c
void delete_min_node(struct h_node *h) {
    if (h == NULL || h->first == NULL) {
        return;  // 空链表
    }

    struct node *prev = h;               // 头结点作为 dummy
    struct node *curr = h->first;
    struct node *min_prev = h;           // 最小值节点的前驱
    struct node *min_curr = h->first;    // 最小值节点

    while (curr != NULL) {
        if (curr->data < min_curr->data) {
            min_prev = prev;
            min_curr = curr;
        }
        prev = curr;
        curr = curr->next;
    }

    // 删除最小值节点
    min_prev->next = min_curr->next;

    // 如果删除的是尾节点，更新 last 指针
    if (min_curr == h->last) {
        h->last = min_prev;
    }

    free(min_curr);
}
```

**复杂度分析**：
- 时间复杂度：O(n)，一次遍历即可找到最小值并完成删除
- 空间复杂度：O(1)

**关键点**：
- 用头结点作为 dummy，统一删除逻辑 — 最小值在首节点时无需特判
- 需要同时记录最小值节点及其前驱节点，才能完成删除操作
- 带头结点情况下，`min_prev` 初始化为 `h` 而非 `NULL`，避免空指针问题

### 合并两个升序链表（保持升序）

**来源**：虚拟生活服务公司戊 2022 校招

**题目**：给定两个带头结点的升序单链表，将其合并为一个新的带头结点的升序单链表。要求不额外开辟新节点，直接使用原有节点。

**解题思路**：使用双指针 + 尾插法。创建一个新的头结点（或复用其中一个头结点），用两个指针分别遍历两个链表，每次将较小节点取出，尾插到结果链表中。

```c
struct h_node *merge_sorted_lists(struct h_node *ha, struct h_node *hb) {
    // 创建新头结点
    struct h_node *result = (struct h_node *)malloc(sizeof(struct h_node));
    result->first = NULL;
    result->last = NULL;

    struct node *pa = ha->first;
    struct node *pb = hb->first;

    // 尾插辅助指针
    struct node *tail = NULL;

    while (pa != NULL && pb != NULL) {
        struct node *selected = NULL;
        if (pa->data <= pb->data) {
            selected = pa;
            pa = pa->next;
        } else {
            selected = pb;
            pb = pb->next;
        }

        // 尾插到结果链表
        selected->next = NULL;
        if (result->first == NULL) {
            result->first = selected;
            tail = selected;
        } else {
            tail->next = selected;
            tail = selected;
        }
    }

    // 将剩余节点直接接上
    struct node *remaining = (pa != NULL) ? pa : pb;
    if (remaining != NULL) {
        if (result->first == NULL) {
            result->first = remaining;
        } else {
            tail->next = remaining;
        }
    }

    // 更新 last 指针：找到尾节点
    if (result->first == NULL) {
        result->last = NULL;
    } else {
        struct node *p = result->first;
        while (p->next != NULL) {
            p = p->next;
        }
        result->last = p;
    }

    return result;
}
```

**哑节点优化版本（简洁写法）**：

```c
struct h_node *merge_sorted_dummy(struct h_node *ha, struct h_node *hb) {
    struct node dummy;          // 栈上的哑节点
    struct h_node result;
    result.first = &dummy;      // 利用哑节点统一尾插
    result.last = NULL;

    struct node *tail = &dummy;
    struct node *pa = ha->first;
    struct node *pb = hb->first;

    while (pa != NULL && pb != NULL) {
        if (pa->data <= pb->data) {
            tail->next = pa;
            pa = pa->next;
        } else {
            tail->next = pb;
            pb = pb->next;
        }
        tail = tail->next;
    }
    tail->next = (pa != NULL) ? pa : pb;

    // 跳过哑节点
    result.first = dummy.next;

    // 更新 last
    if (result.first == NULL) {
        result.last = NULL;
    } else {
        struct node *p = result.first;
        while (p->next != NULL) p = p->next;
        result.last = p;
    }

    return &result;  // 注意：实际应用中应动态分配或传入结果结构体
}
```

**复杂度分析**：
- 时间复杂度：O(m + n)，其中 m 和 n 分别为两个链表的长度
- 空间复杂度：O(1)，只使用常数个指针

**关键点**：
- 每次选择较小的节点尾插，保持升序
- 最后处理剩余节点（直接拼接，省去后续比较）
- 哑节点（dummy node）技巧避免了空链表特判

### 负数前置问题（链表 Partition）

**来源**：虚拟互联网公司甲 2021 / 经典面试题

**题目**：给定一个带头结点的单链表，将所有数据域为负数的节点移动到链表的前半部分，正数节点在后方。负数之间、正数之间不要求保持原有顺序。

**解题思路**：创建两个哑节点链表（负数链表和正数链表），遍历原链表，根据正负将节点拆到两个链表中，最后将正数链表接到负数链表尾部。

```c
void negative_front(struct h_node *h) {
    if (h == NULL || h->first == NULL) {
        return;
    }

    // 负数链表的哑节点
    struct node neg_dummy;
    neg_dummy.next = NULL;
    struct node *neg_tail = &neg_dummy;

    // 正数链表的哑节点
    struct node pos_dummy;
    pos_dummy.next = NULL;
    struct node *pos_tail = &pos_dummy;

    struct node *curr = h->first;
    struct node *next = NULL;

    while (curr != NULL) {
        next = curr->next;      // 保存下一个节点
        curr->next = NULL;      // 断开当前节点

        if (curr->data < 0) {
            neg_tail->next = curr;
            neg_tail = curr;
        } else {
            pos_tail->next = curr;
            pos_tail = curr;
        }
        curr = next;
    }

    // 连接两部分：负数链表 + 正数链表
    if (neg_dummy.next != NULL) {
        h->first = neg_dummy.next;
        neg_tail->next = pos_dummy.next;
    } else {
        h->first = pos_dummy.next;  // 没有负数节点
    }

    // 更新 last 指针
    if (pos_dummy.next != NULL) {
        h->last = pos_tail;
    } else {
        h->last = neg_tail;
    }
}
```

**拓展（稳定性版本）**：如果需要保持正负数内部的相对顺序，只需在拆链时保持尾插即可，上述尾插实现天然保持稳定性。

**复杂度分析**：
- 时间复杂度：O(n)
- 空间复杂度：O(1)，使用栈上的哑节点，未分配新节点

**关键点**：
- 哑节点大大简化了空链表边界处理
- 断开当前节点的 next 再重新拼接，避免形成环
- 最后更新头结点的 first 和 last

### 已知 px 指向中间节点，如何删除该节点

**来源**：某软件厂商面试题变体 / 经典面试题

**题目**：已知 `struct node *px` 指向单链表中的一个中间节点（注意：不是首节点也不是尾节点），且只给定了这一个指针，没有链表头结点的任何信息。请设计算法删除 `px` 指向的节点。

**解题思路**：传统的单链表删除需要知道待删除节点的前驱节点，但这里没有头结点信息，无法遍历找到前驱。使用"狸猫换太子"技巧 — 将后继节点的数据复制到当前节点，然后删除后继节点。

```c
void delete_mid_node(struct node *px) {
    if (px == NULL || px->next == NULL) {
        return;  // 无法处理尾节点或空指针
    }

    struct node *to_delete = px->next;  // 待删除的实际上是后继节点

    // 将后继节点的数据复制到当前节点
    px->data = to_delete->data;

    // 跳过后继节点
    px->next = to_delete->next;

    // 释放后继节点
    free(to_delete);
}
```

**示意图**：

```
删除前:  A -> [B] -> C -> D
                ^
                px 指向 B

步骤1: 将 C 的数据复制到 B，B 就变成了 C'
步骤2: 让 B 的 next 指向 D
步骤3: 释放原来的 C 节点

删除后:  A -> C' -> D
                ^
                px 指向（原来的 B，现在存储的是 C 的数据）
```

**限制条件**：

| 条件 | 是否可行 | 说明 |
|------|---------|------|
| px 指向中间节点（非尾） | 可行 | 核心解法 |
| px 指向尾节点 | 不可行 | 无后继节点可复制数据 |
| px 指向首节点 | 可处理 | 有后继节点，但需更新头指针 |
| 双向链表 | 直接删除 | 因为有前驱指针，无需此技巧 |

**复杂度分析**：
- 时间复杂度：O(1)，仅需常数次指针操作和数据复制
- 空间复杂度：O(1)

**关键点**：
- 利用"节点数据转移"的思想，操作的是节点内容而非节点本身
- 前提是后继节点必须存在，因此无法处理尾节点
- 数据复制在 data 域较大时（如存储结构体）会有性能开销
- 在嵌入式场景中，如果节点数据量较大，此方法的复制开销不可忽视
