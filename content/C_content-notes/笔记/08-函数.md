## 一、函数的直觉理解

### 1.1 从生活类比理解函数

想象一家餐厅的后厨：

- **函数定义** = 菜谱（写明食材、步骤、成品）
- **函数声明** = 菜单上的菜名（告诉顾客有什么菜，但不写做法）
- **参数传递** = 服务员把顾客的点菜单传给厨师
- **返回值** = 做好的菜端回给顾客
- **栈帧** = 每个厨师的工作台，用完清理

**核心直觉：函数是一种"命名过的操作序列"——给它起个名字，下次只需喊名字就能执行整套操作。**

```c
// 菜谱（定义）
int make_coffee(int sugar, int milk) {
    return 200 /*ml coffee*/ + sugar * 5 + milk * 10;
}

// 菜单（声明）
int make_coffee(int, int);

int main(void) {
    int cup = make_coffee(2, 1);  // 点单：2份糖，1份奶
    return 0;
}
```

## 二、函数的定义与声明

### 2.1 定义（Definition）—— 完整的实现

```c
// 完整定义：返回类型 + 函数名 + 参数列表 + 函数体
int max(int a, int b) {
    return (a > b) ? a : b;
}
```

一个函数在**整个程序中只能定义一次**（One Definition Rule, ODR）。

### 2.2 声明（Declaration）—— 仅告知签名

```c
// 函数声明，也称为函数原型（Function Prototype）
int max(int a, int b);   // 带参数名，可读性好
int max(int, int);       // 可省略参数名，编译器只看类型
```

声明可以出现**多次**，通常放在头文件中。

### 2.3 声明 vs 定义 —— 一句话区分

> **定义 = 声明 + 函数体**

编译器只需声明就知道"这个函数长什么样"，调用时按签名生成正确的调用指令；链接器则需要定义来找到函数的实际代码地址。

```c
// 正确的做法：先声明，后调用，再定义
#include <stdio.h>

int max(int, int);               // 声明

int main(void) {
    printf("%d\n", max(3, 7));   // 调用
    return 0;
}

int max(int a, int b) {          // 定义
    return (a > b) ? a : b;
}
```

### 2.4 旧式声明问题（Implicit Function Declaration）—— 面试高频坑

**C89/C90** 允许调用一个未声明的函数，编译器会隐式推断其签名为：
```c
int function_name();  // 隐式声明：返回 int，参数未知
```

```c
// 旧式风格 —— C89 可能"碰巧能编译"，但 C99 起是错误
#include <stdio.h>

int main(void) {
    double result = sqrt(100.0);  // 未包含 <math.h>，无显式声明
    printf("%f\n", result);
    return 0;
}
```

此代码在 C89 中隐式声明 `sqrt` 返回 `int`，导致返回值被截断；在 C11 中使用 `-Wall -Wextra` 会报 `implicit-function-declaration` 错误。

**gcc 编译验证**：
```bash
$ gcc -std=c11 -Wall -Wextra -Wpedantic -o test test.c
test.c:7:22: warning: implicit declaration of function 'sqrt' [-Wimplicit-function-declaration]
```

**实际项目影响**：2021年某开源项目因缺少头文件导致隐式声明将返回 `int`（截断指针），引发了难以定位的内存破坏——修复仅需一行 `#include <math.h>`。

> **最佳实践**：始终在调用前提供显式声明（通过包含对应的头文件），编译时开启 `-Wall -Wextra -Wpedantic` 捕获此类问题。

## 三、参数传递

### 3.1 传值调用（Call by Value）—— C语言唯一的传参方式

**直觉理解**：你让朋友帮你复印一份文件，你把原件给他。他在复印件上乱画——你的原件完好无损。这就是传值调用。

```c
#include <stdio.h>

void modify(int x) {
    x = 100;            // 修改的是形参（副本），不影响实参
    printf("函数内: x = %d\n", x);
}

int main(void) {
    int a = 10;
    modify(a);          // a 的值被复制给 x
    printf("函数外: a = %d\n", a);  // a 仍然是 10
    return 0;
}
```

**输出**：
```
函数内: x = 100
函数外: a = 10
```

### 3.2 传指针——模拟"传引用"

如果想在函数内修改实参，必须传递指针：

```c
#include <stdio.h>

void swap(int *px, int *py) {
    int temp = *px;
    *px = *py;
    *py = temp;
}

int main(void) {
    int a = 10, b = 20;
    printf("交换前: a = %d, b = %d\n", a, b);
    swap(&a, &b);       // 传递地址（仍然是传值，但传的是地址的值）
    printf("交换后: a = %d, b = %d\n", a, b);
    return 0;
}
```

**重要区分**：传指针**仍然是传值调用**——传递的是指针变量中存放的地址值（副本），通过该副本可以间接访问原变量。C语言中没有真正的"传引用调用"。

### 3.3 数组参数退化为指针

**直觉理解**：你把一箱书的地址告诉朋友，说"书在那里，你自己去看"。朋友不需要搬走整箱书（那太慢了），他只需要知道地址。

```c
#include <stdio.h>

void print_array(int arr[], int n) {  // arr[] 等价于 int *arr
    printf("sizeof(arr) = %zu\n", sizeof(arr));  // 8 (指针的大小), 不是数组的大小
    for (int i = 0; i < n; i++) {
        printf("%d ", arr[i]);
    }
    printf("\n");
}

int main(void) {
    int data[] = {10, 20, 30, 40, 50};
    printf("sizeof(data) = %zu\n", sizeof(data));  // 20 (5 * 4)
    print_array(data, 5);  // data 退化为指针
    return 0;
}
```

**`int arr[]` 作为形参时完全等价于 `int *arr`**，这是 C 语言的语法糖。因此：
- 函数内无法通过 `sizeof(arr) / sizeof(arr[0])` 获得数组长度
- 必须额外传递数组长度参数
- 函数内修改 `arr[i]` 会影响原数组（因为操作的是同一块内存）

### 3.4 结构体传参

**传值（拷贝整个结构体）**：

```c
#include <stdio.h>

typedef struct {
    int x;
    int y;
} Point;

Point add_point(Point a, Point b) {     // 传值：拷贝整个结构体
    Point result;
    result.x = a.x + b.x;
    result.y = a.y + b.y;
    return result;
}

int main(void) {
    Point p1 = {1, 2};
    Point p2 = {3, 4};
    Point p3 = add_point(p1, p2);
    printf("(%d, %d)\n", p3.x, p3.y);   // (4, 6)
    return 0;
}
```

**传指针（推荐，尤其结构体很大时）**：

```c
void move_point(Point *p, int dx, int dy) {
    p->x += dx;
    p->y += dy;
}
```

**工程建议**：
- 结构体很小（≤ 16字节）且只需读取 → 传值（清晰、无副作用）
- 结构体较大或需要修改 → 传指针（高效）

## 四、返回值

### 4.1 return 机制

`return` 语句做两件事：
1. 立即终止当前函数的执行
2. 将表达式的值传回调用点

```c
#include <stdio.h>

int divide(int a, int b) {
    if (b == 0) {
        return 0;       // 提前返回，函数立刻结束
    }
    return a / b;       // 正常返回
}
```

### 4.2 返回局部变量地址的危险 —— 经典悬空指针问题

```c
#include <stdio.h>

int* bad_function(void) {
    int local = 42;          // 局部变量，位于当前栈帧
    return &local;           // 危险！函数返回后栈帧被回收
}                            // local 的内存变为"自由"状态

int main(void) {
    int *p = bad_function();
    printf("%d\n", *p);      // 未定义行为：访问已释放的栈内存
    return 0;
}
```

**直觉理解**：你让朋友去你家拿一本书。朋友到了你家（函数调用），你给了书（返回地址）。然后你搬家了（函数返回，栈帧销毁），朋友拿着你旧家的地址去找——什么都找不到。

**gcc 编译会警告**：
```
warning: function returns address of local variable [-Wreturn-local-addr]
```

**正确的做法**：将结果写入调用者提供的缓冲区，或使用动态分配（调用者负责释放）。

```c
// 安全做法一：调用者提供缓冲区
void safe_function(int *out, int value) {
    *out = value * 2;
}

// 安全做法二：使用 static 变量（但注意线程安全）
int* static_function(void) {
    static int val = 42;    // 静态存储期，函数返回后不会销毁
    return &val;
}
```

### 4.3 返回结构体

C99 起允许直接返回结构体（通过值拷贝），这是安全的：

```c
typedef struct {
    double real;
    double imag;
} Complex;

Complex make_complex(double r, double i) {
    Complex c = {r, i};
    return c;                // 结构体的内容被拷贝回调用者
}
```

现代编译器对返回小结构体会优化为通过寄存器传递，不一定会拷贝整个结构体到栈上。

## 五、函数与栈帧

### 5.1 栈帧结构

每次函数调用，系统在调用栈（Call Stack）上分配一个**栈帧（Stack Frame）**。

**ASCII 栈帧示意图**：

```
     高地址
     ┌────────────────────┐
     │    主调函数的局部变量     │
     ├────────────────────┤
     │    实参（从右到左入栈）    │  ← 调用者的数据
     ├────────────────────┤
     │    返回地址            │  ← 被调函数结束后跳回的位置
     ├────────────────────┤  ←─── 栈帧边界 (RSP/ESP)
     │    被调函数的局部变量     │
     │        ...               │
     │    临时存储区             │
     └────────────────────┘
     低地址
     栈顶 (SP 指向这里)
```

### 5.2 调用约定概念

调用约定（Calling Convention）规定了函数调用时参数如何传递、栈由谁清理等细节。

| 约定 | 参数传递方式 | 栈清理者 | 常见平台 |
|------|-------------|---------|---------|
| `cdecl` | 从右到左压栈 | 调用者 | x86 (Linux, Windows) |
| `stdcall` | 从右到左压栈 | 被调函数 | x86 (Win32 API) |
| `fastcall` | 部分参数通过寄存器传递 | 被调函数 | x86 优化编译 |
| 默认 (SysV AMD64) | 前6个参数通过寄存器 | 调用者 | x86-64 (Linux, macOS) |

**平台声明**：以上调用约定主要在 x86 32位架构上显式命名。在 x86-64 上，System V ABI 是 Linux 和 macOS 的默认标准。

### 5.3 递归与栈溢出

递归调用时，每层调用创建新的栈帧。栈空间是有限的（通常 1MB ~ 8MB），递归过深会耗尽栈空间。

```
递归深度过大时的栈状态：
     ┌──────┐
     │ f(1) │  ← 栈顶
     ├──────┤
     │ f(2) │
     ├──────┤
     │ f(3) │
     ├──────┤
     │ ...  │
     ├──────┤
     │ f(n) │  ← 栈底方向
     └──────┘
     当递归深度超过栈容量 → 栈溢出 (Stack Overflow)
```

## 六、main 函数的标准形式

### 6.1 两种标准形式

```c
// 形式一：无参数（最简单的形式）
int main(void);

// 形式二：带参数（处理命令行输入）
int main(int argc, char *argv[]);

// 形式三：带环境变量（POSIX 扩展，C标准中未强制要求）
int main(int argc, char *argv[], char *envp[]);
```

### 6.2 argc 和 argv

- **argc**（argument count）：命令行参数的数量（包括程序名自身）
- **argv**（argument vector）：字符串数组，每个元素是一个参数字符串

```c
#include <stdio.h>

int main(int argc, char *argv[]) {
    printf("程序名: %s\n", argv[0]);
    printf("参数个数: %d\n", argc);

    for (int i = 1; i < argc; i++) {
        printf("参数 %d: %s\n", i, argv[i]);
    }
    return 0;
}
```

```bash
$ ./greet Alice Bob Charlie
程序名: ./greet
参数个数: 4
参数 1: Alice
参数 2: Bob
参数 3: Charlie
```

### 6.3 环境变量

第三个参数 `envp` 是一个以 NULL 结尾的字符串数组，每个元素是 `"KEY=VALUE"` 格式：

```c
#include <stdio.h>

int main(int argc, char *argv[], char *envp[]) {
    for (char **env = envp; *env != NULL; env++) {
        printf("%s\n", *env);
    }
    return 0;
}
```

**平台声明**：`envp` 是 POSIX 扩展，C标准不强制要求支持。跨平台代码应使用 `getenv()` 函数获取特定环境变量。

### 6.4 main 的返回值

- `0` 或 `EXIT_SUCCESS` → 程序正常结束
- `EXIT_FAILURE` → 程序异常结束
- 其他值 → 由操作系统解释，通常用于 shell 脚本判断

```c
#include <stdio.h>
#include <stdlib.h>  // EXIT_SUCCESS, EXIT_FAILURE

int main(void) {
    if (/* 一切正常 */) {
        return EXIT_SUCCESS;   // 或 return 0;
    } else {
        return EXIT_FAILURE;   // 或 return 1;
    }
}
```

在 shell 中通过 `$?` 检查返回值：`echo $?`。

## 七、标准库函数概览

### 7.1 <stdio.h> —— 输入输出

| 函数 | 功能 | 要点 |
|------|------|------|
| `printf` | 格式化输出 | 返回值是输出的字符数 |
| `scanf` | 格式化输入 | 参数需要地址（取地址 &） |
| `fopen` / `fclose` | 文件打开/关闭 | 返回 `FILE*`，失败返回 NULL |
| `fgets` / `fputs` | 字符串读写 | `fgets` 会读取换行符 |
| `fprintf` / `fscanf` | 文件格式化读写 | 与 printf/scanf 类似 |

### 7.2 <stdlib.h> —— 通用工具

| 函数 | 功能 | 要点 |
|------|------|------|
| `malloc` / `free` | 动态内存分配/释放 | 必须检查 NULL 返回值 |
| `atoi` / `atof` | 字符串转数值 | 没有错误检测，推荐 `strtol` |
| `qsort` | 快速排序 | 接受函数指针作为比较器 |
| `bsearch` | 二分查找 | 要求数组已排序 |
| `abs` / `labs` | 绝对值计算 | 注意 `INT_MIN` 的溢出 |

### 7.3 <string.h> —— 字符串操作

| 函数 | 功能 | 陷阱 |
|------|------|------|
| `strlen` | 获取字符串长度 | 不包括 `\0`，O(n) 复杂度 |
| `strcpy` / `strncpy` | 字符串复制 | `strcpy` 可能缓冲区溢出，推荐 `strncpy` 或 `snprintf` |
| `strcat` / `strncat` | 字符串连接 | 目标缓冲区必须足够大 |
| `strcmp` / `strncmp` | 字符串比较 | 返回 0 表示相等 |
| `memcpy` / `memmove` | 内存复制 | `memcpy` 不允许重叠，`memmove` 允许 |
| `memset` | 内存设置 | 常用于置零结构体 |

### 7.4 <ctype.h> —— 字符分类

| 函数 | 功能 |
|------|------|
| `isalpha` | 检查是否字母 |
| `isdigit` | 检查是否数字 |
| `isalnum` | 检查是否字母或数字 |
| `isspace` | 检查是否空白字符 |
| `toupper` / `tolower` | 大小写转换 |

> **注意**：这些函数的参数是 `int` 类型，接受 `unsigned char` 或 `EOF`。切勿传入 `char` 类型的负值（在未指定 signedness 的平台上会导致未定义行为）。

## 八、函数的模块化设计

### 8.1 单一职责原则（Single Responsibility Principle）

**核心思想：一个函数只做一件事，并且把它做好。**

```c
// 违反单一职责 —— 一个函数做三件事
void process_data(int *data, int n) {
    // 1. 读取数据
    // 2. 处理数据
    // 3. 输出结果
}

// 符合单一职责 —— 拆分为三个函数
int* read_data(const char *filename, int *n);
void process_data(int *data, int n);
void print_result(const int *data, int n);
```

**判断标准**：如果无法用一句话（不超过20个字）描述一个函数的功能，它可能职责过多。

### 8.2 接口与实现分离

```c
// ============ math_ops.h (接口——只放声明) ============
#ifndef MATH_OPS_H
#define MATH_OPS_H

int add(int a, int b);
int subtract(int a, int b);
int multiply(int a, int b);
double divide(int a, int b);

#endif

// ============ math_ops.c (实现——放定义) ============
#include "math_ops.h"

int add(int a, int b) { return a + b; }
int subtract(int a, int b) { return a - b; }
int multiply(int a, int b) { return a * b; }

double divide(int a, int b) {
    if (b == 0) return 0.0;
    return (double)a / b;
}
```

**工程意义**：
- 接口（.h）是契约：告诉外部"我能做什么"
- 实现（.c）是细节：告诉编译器"怎么做"
- 修改实现不需要重新编译调用方的代码

## 九、内联函数（inline）

### 9.1 基本概念

`inline` 关键字是 C99 引入的，建议编译器将函数体直接展开到调用点，避免函数调用开销。

```c
// C99 标准内联函数
inline int square(int x) {
    return x * x;
}
```

**`inline` 只是建议**，编译器可以忽略。现代编译器会根据优化级别自动决定是否内联，即使不加 `inline`。

### 9.2 inline 与宏的区别

| 特性 | `inline` 函数 | 宏（`#define`） |
|------|--------------|----------------|
| 类型检查 | 有（编译器检查参数类型） | 无（纯文本替换） |
| 副作用 | 表达式只求值一次 | 参数可能被多次求值 |
| 调试 | 支持（断点、单步执行） | 不支持 |
| 作用域 | 遵守函数作用域规则 | 预处理阶段，影响全局 |
| 优先级 | 遵循运算符优先级 | 必须加括号避免优先级问题 |

```c
// 宏的经典陷阱 —— 参数被多次求值
#define MAX(a, b) ((a) > (b) ? (a) : (b))
int x = 5;
int y = MAX(x++, 3);  // 展开为: ((x++) > (3) ? (x++) : (3)) — x 被自增两次！

// 内联函数则安全
inline int max(int a, int b) {
    return (a > b) ? a : b;
}
int z = max(x++, 3);   // x 只自增一次
```

### 9.3 工程建议

- 只有非常小（通常 1-3 行）且频繁调用的函数才值得 `inline`
- 对于包含循环、递归或复杂逻辑的函数，`inline` 没有意义
- 将 `inline` 函数的定义放在头文件中，因为所有翻译单元都需要看到函数体才能展开

## 十、函数指针

### 10.1 直觉理解

**函数指针**就是指向函数入口地址的指针变量。普通指针存数据地址，函数指针存代码地址。

```c
// 函数本身
int add(int a, int b) { return a + b; }

// 声明一个函数指针
int (*func_ptr)(int, int);

// 赋值
func_ptr = add;          // 或 &add

// 调用
int result = func_ptr(3, 4);   // 或 (*func_ptr)(3, 4)
```

### 10.2 函数指针的声明语法

```c
返回类型 (*指针名)(参数类型列表);
```

> **括号不能省略**：`int *func(int, int)` 是返回 `int*` 的函数，不是函数指针。

### 10.3 作为参数传递 —— 回调函数模式

函数指针最常见的用途是实现**回调（Callback）**—— 将一个函数作为参数传递给另一个函数。

```c
#include <stdio.h>

// 回调函数
int add(int a, int b) { return a + b; }
int subtract(int a, int b) { return a - b; }
int multiply(int a, int b) { return a * b; }

// 接受函数指针作为参数的高阶函数
int calculate(int x, int y, int (*operation)(int, int)) {
    return operation(x, y);
}

int main(void) {
    printf("3 + 4 = %d\n", calculate(3, 4, add));
    printf("10 - 7 = %d\n", calculate(10, 7, subtract));
    printf("5 * 6 = %d\n", calculate(5, 6, multiply));
    return 0;
}
```

### 10.4 函数指针数组

```c
// 菜单驱动的命令分发器
void cmd_help(void)  { printf("帮助...\n"); }
void cmd_quit(void)  { printf("退出...\n"); }
void cmd_save(void)  { printf("保存...\n"); }

int main(void) {
    void (*commands[3])(void) = {cmd_help, cmd_quit, cmd_save};
    int choice;
    scanf("%d", &choice);
    if (choice >= 0 && choice < 3) {
        commands[choice]();  // 通过函数指针数组调用
    }
    return 0;
}
```

## 十一、可变参数

### 11.1 stdarg.h 机制

C语言允许定义参数个数可变的函数，如 `printf`：

```c
#include <stdio.h>
#include <stdarg.h>

// 计算 n 个整数的和
int sum(int count, ...) {
    va_list args;
    va_start(args, count);  // 初始化 args，count 是最后一个命名参数

    int total = 0;
    for (int i = 0; i < count; i++) {
        total += va_arg(args, int);  // 获取下一个 int 参数
    }

    va_end(args);  // 清理
    return total;
}

int main(void) {
    printf("%d\n", sum(3, 10, 20, 30));   // 60
    printf("%d\n", sum(5, 1, 2, 3, 4, 5)); // 15
    return 0;
}
```

**关键宏**：

| 宏 | 功能 |
|----|------|
| `va_list` | 声明一个变量，用于遍历可变参数 |
| `va_start(args, last_named)` | 初始化，指向第一个可变参数 |
| `va_arg(args, type)` | 获取当前参数，并移动到下一个 |
| `va_end(args)` | 清理 |

### 11.2 printf 原理简述

`printf` 的实现大致流程：

1. 解析格式字符串 `fmt`，扫描 `%` 标记
2. 遇到 `%d` 就调用 `va_arg(args, int)` 获取一个整数
3. 遇到 `%f` 就调用 `va_arg(args, double)` 获取一个浮点数
4. 格式化和输出

**陷阱**：可变参数没有类型检查！传入的类型必须与 `va_arg` 期望的类型完全匹配。这也是为什么 `printf("%s", 42)` 会在运行时崩溃。

## 十二、嵌入式开发中的函数

### 12.1 中断服务函数（ISR）

中断服务函数（Interrupt Service Routine）是由硬件事件触发的特殊函数，不是由普通代码调用的。

```c
// 伪代码示例 —— 具体语法依赖于编译器
__interrupt void timer_isr(void) {
    // 硬件自动保存上下文
    // 处理中断事件
    timer_clear_flag();
    // 硬件自动恢复上下文
    // iret 指令返回
}
```

**ISR 编写规则**：
1. **尽可能短小**：中断应快速完成，避免丢失其他中断
2. **不能有阻塞调用**：如 `printf`（依赖中断的轮询输出会导致死锁）
3. **不能有浮点运算**（在大多数裸机环境中）：浮点操作会增大上下文保存开销
4. **所有被修改的全局变量必须加 `volatile`** 防止编译器优化掉对中断变量的访问

### 12.2 interrupt 属性

GCC 和 IAR 等编译器使用属性（attribute）或关键字标记 ISR：

```c
// GCC 风格（x86）
__attribute__((interrupt)) void isr_handler(void) {
    // ...
}

// ARM Cortex-M：标准函数就是中断函数
// 中断向量表中直接填写函数地址即可
```

**平台声明**：`interrupt` 属性的具体语法因编译器和架构而异。上述示例基于 GCC x86 实现。

### 12.3 函数重入（Reentrancy）

**可重入函数**是指可以同时被多个执行流（主程序和中断、或多个任务）调用而不会出错的函数。

```c
// 不可重入 —— 使用了全局静态变量
static int counter = 0;
int increment(void) {
    counter++;  // 中断发生在此处，另一执行流也调用 increment → 数据竞争
    return counter;
}

// 可重入 —— 所有数据由调用者提供
int increment_reentrant(int *counter) {
    (*counter)++;
    return *counter;
}
```

**可重入函数的特征**：
- 不使用静态或全局变量（或使用时通过互斥保护）
- 不调用不可重入函数
- 不使用硬件资源（除非通过互斥访问）

### 12.4 闪存中的函数

有些嵌入式系统将函数放在只读存储器（Flash/ROM）中执行，或为了性能将其复制到 RAM 中执行：

```c
// 函数默认位于 Flash（代码区）
void normal_function(void) {
    // 在 Flash 中就地执行
}

// 将函数放在 RAM 中以获得更快执行速度（特定编译器语法）
__attribute__((section(".ram_code"))) void fast_function(void) {
    // 在 RAM 中执行，速度更快
}
```

**平台声明**：上述 `__attribute__((section(...)))` 是 GCC 扩展，非标准 C 语法。

## 十三、面试直连

### Q1: C语言中传值和传指针有什么区别？

**A**: 传值将实参的拷贝传给形参，函数内修改形参不影响实参；传指针也是传值，但传的是地址值，可以通过指针间接修改原变量。面试时可以补充：C语言只有传值调用，没有传引用调用；实现"传引用"效果需要传指针。

### Q2: 函数指针的用途有哪些？

**A**: （1）回调函数（如 `qsort` 的比较器）；（2）实现多态和策略模式；（3）驱动开发中注册中断处理函数；（4）实现状态机跳转表；（5）动态加载的插件系统。

### Q3: 内联函数和宏有什么区别？

**A**: 内联函数有类型检查，宏是文本替换；内联函数的参数只求值一次，宏的参数可能被多次求值导致副作用；内联函数可调试，宏不能；内联函数遵循作用域规则，宏在预处理器层面替换。面试加分：现代编译器优化能力很强，手动加 inline 未必必要。

### Q4: 栈溢出是什么？什么情况下会发生？

**A**: 栈溢出是指程序使用的栈空间超过了操作系统分配的栈容量。常见原因：递归深度过大（如无限递归）、在栈上分配过大的局部变量（如 `int a[1000000]`）、深层嵌套的函数调用。

### Q5: 什么是回调函数？实际项目中如何使用？

**A**: 回调函数是通过函数指针参数传递的函数，在特定事件发生时被调用者执行。实际应用：`qsort` 的比较函数、定时器超时处理函数、网络库的事件处理函数。

### Q6: 可变参数是怎么实现的？为什么 printf 需要指定格式而不直接传类型信息？

**A**: 可变参数通过 `va_list`、`va_start`、`va_arg`、`va_end` 宏实现，本质上是通过指针遍历栈上的参数。C语言在运行时没有类型信息，所以 printf 必须通过格式字符串来知道每个参数的类型和数量。

### Q7: 函数声明和定义的区别？

**A**: 声明告诉编译器函数的名字、参数类型和返回类型（函数原型）；定义提供函数体（完整实现）。声明可多次出现，定义只能有一次。C99之前允许隐式声明（返回int），C99及以后禁止。

### Q8: 为什么在嵌入式中断服务函数中不能使用 printf？

**A**: `printf` 通常依赖底层 I/O 系统，可能会触发相同或更低优先级的中断，导致死锁或系统崩溃；`printf` 执行时间不可控，不适合要求快速响应的中断上下文；`printf` 使用内部缓冲区，可能不可重入。

## 十四、代码阅读题

### 题1

```c
#include <stdio.h>

void func(int *p) {
    static int x = 0;
    x++;
    *p = x;
}

int main(void) {
    int a = 10, b = 20;
    func(&a);
    func(&b);
    printf("%d, %d\n", a, b);
    return 0;
}
```

**问题**：输出结果是什么？为什么？

<details>
<summary>答案</summary>
输出：`1, 2`。`func` 中的 `x` 是静态局部变量，只初始化一次，每次调用自增。先传 `&a`，`*p = 1`；后传 `&b`，`*p = 2`。
</details>

### 题2

```c
#include <stdio.h>

int mystery(int arr[], int n) {
    if (n <= 0) return 0;
    return arr[0] + mystery(arr + 1, n - 1);
}

int main(void) {
    int nums[] = {2, 4, 6, 8};
    int result = mystery(nums, 4);
    printf("%d\n", result);
    return 0;
}
```

**问题**：输出结果是什么？`mystery` 函数的作用是什么？用循环重写它。

<details>
<summary>答案</summary>
输出：`20`。`mystery` 是一个递归函数，计算数组元素的和。等效的循环实现：`int sum = 0; for (int i = 0; i < n; i++) sum += arr[i];`
</details>

### 题3

```c
#include <stdio.h>

int main(void) {
    int (*fp)(int, int);
    int add(int, int);
    int sub(int, int);

    fp = add;
    int r1 = fp(10, 5);

    fp = sub;
    int r2 = fp(10, 5);

    printf("%d, %d\n", r1, r2);
    return 0;
}

int add(int a, int b) { return a + b; }
int sub(int a, int b) { return a - b; }
```

**问题**：输出结果是什么？如果交换 `add` 和 `sub` 的定义和函数指针赋值顺序，结果如何？

<details>
<summary>答案</summary>
输出：`15, 5`。`fp` 是一个函数指针，先指向 `add`，后指向 `sub`。交换顺序不影响结果，因为每次赋值只改变指针指向。
</details>

## 本章总结

1. **函数是C程序的基本组织单元**，声明告知签名，定义提供实现，旧式声明已被C99禁止
2. **C语言只有传值调用**，数组参数退化为指针，结构体可传值或传指针
3. **返回局部变量地址是危险的**，因为栈帧在函数返回后被回收
4. **栈帧管理函数调用的上下文**，递归过深会导致栈溢出
5. **main函数有标准形式**，支持命令行参数和环境变量
6. **标准库函数**（stdio、stdlib、string、ctype）提供了丰富的预置能力
7. **模块化设计**应遵循单一职责原则，接口与实现分离
8. **内联函数**比宏更安全，有类型检查且避免了多次求值问题
9. **函数指针**是实现回调、策略模式、状态机的关键机制
10. **可变参数**通过 `stdarg.h` 实现，`printf` 原理依赖格式字符串解析
11. **嵌入式函数设计**要考虑中断上下文、可重入性和存储位置
