## 一、递归的概念

### 1.1 直觉理解

**递归（Recursion）** 是函数调用自身的编程方式。

**生活中的递归**：

- **俄罗斯套娃**：打开一个娃娃，里面是更小的同款娃娃，直到最小的那个不能再打开（基线条件）。
- **字典查词**：查一个词的解释时，解释里出现了另一个不认识的词，于是再查那个词……直到所有词都认识。
- **两面镜子对照**：你在两面镜子中间，看到镜中有镜中有镜中有……无限循环。

**核心直觉**：**解决一个大问题的方法，就是把问题缩小一点，然后用同样的方法去解决它。**

### 1.2 递归的定义

```c
// 递归函数的标准结构
返回类型 function(参数) {
    if (满足基线条件) {
        return 直接结果;       // 不再调用自身
    } else {
        // 将问题缩小，调用自身
        return function(缩小后的参数);
    }
}
```

### 1.3 基线条件与递归条件

一个正确的递归函数需要两个要素：

| 要素 | 作用 | 类比 |
|------|------|------|
| **基线条件（Base Case）** | 递归终止的条件，问题足够简单时直接求解 | 套娃中最小的实心娃娃 |
| **递归条件（Recursive Case）** | 将问题缩小并调用自身 | 打开一个娃娃，处理里面的娃 |

```c
#include <stdio.h>

// 正确的递归：有基线条件 + 递归条件
void countdown(int n) {
    if (n <= 0) {           // 基线条件
        printf("发射！\n");
        return;
    }
    printf("%d...\n", n);
    countdown(n - 1);       // 递归条件：问题规模缩小
}

// 错误的递归：缺少基线条件
void infinite_countdown(int n) {
    // 没有基线条件！
    printf("%d...\n", n);
    infinite_countdown(n - 1);  // 永远不会停止
}
```

### 1.4 数学归纳法思维

设计和验证递归函数的最佳思维工具是**数学归纳法**：

1. **基础步骤**（对应基线条件）：当 `n = 0` 或 `n = 1` 时，函数正确吗？
2. **归纳假设**：假设函数对 `n-1`（规模更小的输入）是正确的。
3. **归纳步骤**：基于这个假设，证明函数对 `n` 也是正确的。

```c
// 用数学归纳法设计阶乘函数
int factorial(int n) {
    // 基础步骤：0! = 1
    if (n <= 1) return 1;

    // 归纳假设：factorial(n-1) 是对的
    // 归纳步骤：n! = n * (n-1)!
    return n * factorial(n - 1);
}
```

## 二、递归的执行过程

### 2.1 栈帧变化

每次递归调用都会在调用栈上创建新的栈帧，每个栈帧包含该调用的参数和局部变量。

**以 `countdown(3)` 为例的栈帧变化**：

```
调用链（递推阶段）：
    调用 countdown(3)
    调用 countdown(2)
    调用 countdown(1)
    调用 countdown(0)   ← 到达基线条件

回溯阶段：
    countdown(0) 返回
    countdown(1) 返回
    countdown(2) 返回
    countdown(3) 返回
```

### 2.2 ASCII 栈图 —— 以 factorial(4) 为例

```
递推（深入）阶段：
                                                      ┌─────────────────────┐
                                                      │ factorial(1): n=1   │
                                                      │ return 1            │
                                                      └─────────────────────┘
                     ┌─────────────────────┐           ┌─────────────────────┐
                     │ factorial(2): n=2   │           │ factorial(2): n=2   │
                     │ 等待 factorial(1)    │           │ return 2*1=2        │
                     └─────────────────────┘           └─────────────────────┘
┌─────────────────────┐ ┌─────────────────────┐       ┌─────────────────────┐
│ factorial(3): n=3   │ │ factorial(3): n=3   │       │ factorial(3): n=3   │
│ 等待 factorial(2)    │ │ 等待 factorial(2)    │       │ return 3*2=6        │
└─────────────────────┘ └─────────────────────┘       └─────────────────────┘
┌─────────────────────┐ ┌─────────────────────┐       ┌─────────────────────┐
│ factorial(4): n=4   │ │ factorial(4): n=4   │       │ factorial(4): n=4   │
│ 等待 factorial(3)    │ │ 等待 factorial(3)    │       │ return 4*6=24       │
└─────────────────────┘ └─────────────────────┘       └─────────────────────┘
     Step 1                 Step 2-3                     Step 4-7 (回溯)
     调用 factorial(4)     递归深入                      逐层返回
```

### 2.3 调用链与回溯

```c
#include <stdio.h>

int factorial(int n) {
    printf("=> factorial(%d) 入栈\n", n);

    if (n <= 1) {
        printf("<= factorial(%d) 返回 1 (基线条件)\n", n);
        return 1;
    }

    int result = n * factorial(n - 1);
    printf("<= factorial(%d) 返回 %d\n", n, result);
    return result;
}

int main(void) {
    factorial(4);
    return 0;
}
```

**输出**：
```
=> factorial(4) 入栈
=> factorial(3) 入栈
=> factorial(2) 入栈
=> factorial(1) 入栈
<= factorial(1) 返回 1 (基线条件)
<= factorial(2) 返回 2
<= factorial(3) 返回 6
<= factorial(4) 返回 24
```

递推阶段（入栈）：将问题逐步分解，直到触及基线条件。
回溯阶段（出栈）：返回计算结果，逐层组合，直到得到最终答案。

## 三、经典递归问题

### 3.1 阶乘（Factorial）

**数学定义**：
```
n! = n × (n-1) × (n-2) × ... × 1
0! = 1
```

**递归定义**：
```
factorial(n) = 1            (n <= 1)
factorial(n) = n × factorial(n-1)  (n > 1)
```

```c
#include <stdio.h>

int factorial(int n) {
    if (n <= 1) return 1;
    return n * factorial(n - 1);
}

int main(void) {
    for (int i = 0; i <= 10; i++) {
        printf("%2d! = %d\n", i, factorial(i));
    }
    return 0;
}
```

**输出**：
```
 0! = 1
 1! = 1
 2! = 2
 3! = 6
 4! = 24
 5! = 120
 6! = 720
 7! = 5040
 8! = 40320
 9! = 362880
10! = 3628800
```

### 3.2 斐波那契数列（Fibonacci Sequence）

**数学定义**：
```
F(0) = 0
F(1) = 1
F(n) = F(n-1) + F(n-2)   (n >= 2)
```

**朴素递归实现（不推荐，效率极低）**：

```c
#include <stdio.h>

int fib_naive(int n) {
    if (n <= 1) return n;
    return fib_naive(n - 1) + fib_naive(n - 2);
}

int main(void) {
    printf("F(10) = %d\n", fib_naive(10));
    return 0;
}
```

**计算 F(5) 的调用树**：

```
                     F(5)
                   /     \
               F(4)       F(3)
              /    \      /    \
          F(3)     F(2) F(2)   F(1)
         /    \    /  \  /  \
      F(2)   F(1) F(1)F(0)F(1)F(0)
      /  \
    F(1) F(0)
```

**重复计算统计**：
- F(3) 被重复计算 2 次
- F(2) 被重复计算 3 次
- F(1) 被重复计算 5 次

时间复杂度 **O(2^n)**，n=40 时调用次数超过 3 亿次。

**优化：记忆化递归**：

```c
#include <stdio.h>

#define MAX 100

int memo[MAX] = {0};

int fib_memo(int n) {
    if (n <= 1) return n;
    if (memo[n] != 0) return memo[n];   // 已经算过了，直接返回

    memo[n] = fib_memo(n - 1) + fib_memo(n - 2);
    return memo[n];
}

int main(void) {
    printf("F(40) = %d\n", fib_memo(40));  // 眨眼间算完
    return 0;
}
```

时间复杂度降为 **O(n)**。

### 3.3 汉诺塔（Tower of Hanoi）

**问题描述**：有三根柱子 A、B、C，A 上有 n 个大小不等的圆盘（大盘在下，小盘在上）。目标：将所有圆盘从 A 移到 C，规则：
1. 每次只能移动一个圆盘
2. 大盘不能放在小盘上
3. B 可作为辅助

**递归思路**（三步法）：
1. 将上面 n-1 个盘从 A 移到 B（借助 C）
2. 将最下面的盘从 A 移到 C
3. 将 B 上的 n-1 个盘移到 C（借助 A）

```c
#include <stdio.h>

void hanoi(int n, char from, char aux, char to) {
    if (n == 1) {  // 基线条件：只有一个盘，直接移动
        printf("移动盘 1: %c -> %c\n", from, to);
        return;
    }
    hanoi(n - 1, from, to, aux);        // 步骤1
    printf("移动盘 %d: %c -> %c\n", n, from, to);  // 步骤2
    hanoi(n - 1, aux, from, to);        // 步骤3
}

int main(void) {
    hanoi(3, 'A', 'B', 'C');
    return 0;
}
```

**输出**：
```
移动盘 1: A -> C
移动盘 2: A -> B
移动盘 1: C -> B
移动盘 3: A -> C
移动盘 1: B -> A
移动盘 2: B -> C
移动盘 1: A -> C
```

移动次数 = 2^n - 1，时间复杂度 O(2^n)。

### 3.4 全排列（Permutation）

生成一个字符串的所有排列组合：

```c
#include <stdio.h>
#include <string.h>

void swap(char *x, char *y) {
    char temp = *x;
    *x = *y;
    *y = temp;
}

void permute(char *str, int left, int right) {
    if (left == right) {              // 基线条件：到达末尾，输出
        printf("%s\n", str);
        return;
    }

    for (int i = left; i <= right; i++) {
        swap(&str[left], &str[i]);    // 将第 i 个字符放到 left 位置
        permute(str, left + 1, right); // 递归处理剩余字符
        swap(&str[left], &str[i]);    // 回溯：恢复原状
    }
}

int main(void) {
    char str[] = "ABC";
    int n = strlen(str);
    permute(str, 0, n - 1);
    return 0;
}
```

**输出**：
```
ABC
ACB
BAC
BCA
CBA
CAB
```

**关键点**：回溯时恢复原状（第二次 `swap`）—— 这是回溯算法（Backtracking）的典型特征。

### 3.5 二分查找（递归版）

```c
#include <stdio.h>

int binary_search(const int arr[], int left, int right, int target) {
    if (left > right) {
        return -1;              // 未找到
    }

    int mid = left + (right - left) / 2;  // 防溢出写法

    if (arr[mid] == target) {
        return mid;             // 找到
    } else if (arr[mid] < target) {
        return binary_search(arr, mid + 1, right, target);   // 在右半部分
    } else {
        return binary_search(arr, left, mid - 1, target);    // 在左半部分
    }
}

int main(void) {
    int sorted[] = {2, 5, 8, 12, 16, 23, 38, 45, 56, 72};
    int n = sizeof(sorted) / sizeof(sorted[0]);
    int targets[] = {23, 1, 72, 45};

    for (int i = 0; i < 4; i++) {
        int idx = binary_search(sorted, 0, n - 1, targets[i]);
        if (idx >= 0) {
            printf("%d 在索引 %d\n", targets[i], idx);
        } else {
            printf("%d 未找到\n", targets[i]);
        }
    }
    return 0;
}
```

**输出**：
```
23 在索引 5
1 未找到
72 在索引 9
45 在索引 7
```

## 四、递归与迭代的比较

### 4.1 可读性 vs 性能

**递归版 vs 迭代版：阶乘**

```c
// 递归 - 贴近数学定义，清晰
int fact_rec(int n) {
    return (n <= 1) ? 1 : n * fact_rec(n - 1);
}

// 迭代 - 高效，无栈开销
int fact_iter(int n) {
    int result = 1;
    for (int i = 2; i <= n; i++) {
        result *= i;
    }
    return result;
}
```

**递归版 vs 迭代版：斐波那契**

```c
// 记忆化递归 - O(n)，清晰
int fib_memo(int n, int *memo);

// 迭代 - O(n)，常数空间，最高效
int fib_iter(int n) {
    if (n <= 1) return n;
    int a = 0, b = 1;
    for (int i = 2; i <= n; i++) {
        int c = a + b;
        a = b;
        b = c;
    }
    return b;
}
```

### 4.2 对比表

| 维度 | 递归 | 迭代 |
|------|------|------|
| 代码简洁性 | 简洁，贴近数学/问题定义 | 较冗长，需手动维护状态 |
| 可读性 | 对递归思维熟悉者清晰 | 对大多数程序员更直观 |
| 性能 | 有函数调用开销，可能重复计算 | 通常更快，无额外开销 |
| 内存 | 每层调用消耗栈空间 O(n) | 固定 O(1) 或 O(k) 额外空间 |
| 适用场景 | 树遍历、分治、回溯、图搜索 | 线性重复操作、简单循环 |
| 编译器优化潜力 | 尾递归可优化为跳转 | 无需优化 |

### 4.3 尾调用与尾递归优化

**尾调用（Tail Call）**：函数最后一步是调用另一个函数（不需要保存当前栈帧）。

```c
// 尾递归：递归调用是函数的最后一步
int factorial_tail(int n, int acc) {
    if (n <= 1) return acc;
    return factorial_tail(n - 1, n * acc);  // 最后一步是调用自身，且不需要保存状态
}
```

**无尾调用优化版**（常规递归）：
```c
int fact(int n) {
    return n * fact(n - 1);  // 最后一步是乘法，不是调用自身
}
// 需要先得到 fact(n-1) 的结果，再做乘法，所以必须保留当前栈帧
```

**编译器优化原理**：对于尾递归，编译器可以将其优化为循环（将 `call` 指令替换为 `jmp`），栈空间不再增长。

**平台声明**：
- GCC 在 `-O2` 或以上级别启用尾调用优化
- 但 C 标准并不强制要求编译器进行尾调用优化，有些编译器完全不支持
- 对于嵌入式开发，即使编译器支持，也不应依赖尾递归来避免栈溢出——优化不是标准行为

### 4.4 何时选择递归

| 使用递归 | 使用迭代 |
|---------|---------|
| 问题天然具有递归结构（树、分治） | 线性重复操作 |
| 代码可读性比性能更关键 | 性能是关键指标 |
| 递归深度已知且有限 | 深度可能很大 |
| 回溯算法（需要恢复状态） | 简单计数或遍历 |

## 五、递归的常见错误

### 5.1 忘记基线条件

```c
int forever(int n) {
    // 忘记写基线条件！
    return n * forever(n - 1);  // 永远无法终止
}
```

**症状**：运行时栈溢出，程序崩溃。

**修复**：确保每条递归路径最终都能到达基线条件。

### 5.2 基线条件永远达不到

```c
int bad_power(int x, int n) {
    if (n == 0) return 1;            // 基线条件
    return x * bad_power(x, n--);    // 错误：使用了后置递减 n--！
    // n-- 先传 n 再减 1，每次调用传入的都是相同的 n，无限递归
}
```

**修复**：改用 `n - 1` 或 `--n`。

### 5.3 栈溢出

```c
// n = 100000 时必定栈溢出（大多数系统栈容量 ~8MB）
int recursive_sum(int n) {
    if (n <= 0) return 0;
    return n + recursive_sum(n - 1);
}
```

**预防**：
- 确定递归的最大深度是否在安全范围内
- 每个栈帧约占用 16-32 字节（参数 + 返回地址 + 局部变量 + 对齐）
- 安全深度 ≈ 栈总容量 / 每帧大小
- 保守估计：8MB 栈 / 32 字节 ≈ 262,000 层

**在嵌入式系统中，栈通常只有 1KB-16KB，安全递归深度非常有限。**

### 5.4 重复计算

朴素递归斐波那契的问题——同一子问题被计算多次。

**解决**：
1. **记忆化（Memoization）**：缓存已计算的结果
2. **动态规划**：自底向上迭代

### 5.5 全局变量的副作用

```c
int count = 0;

void traverse(int n) {
    if (n <= 0) return;
    count++;              // 依赖和修改全局状态
    traverse(n - 1);
}

int main(void) {
    traverse(5);
    printf("%d\n", count);   // 5，但如果 traverse 在别处也被调用，结果不可预测
    return 0;
}
```

**问题**：全局变量使递归函数不可重入，也无法在多线程或中断嵌套中使用。

**修复**：通过参数传递状态，或使用局部变量。

## 六、递归在实际项目中的使用

### 6.1 树的遍历

在文件系统、编译器的抽象语法树（AST）、UI组件树中，递归是遍历的自然方式：

```c
typedef struct TreeNode {
    int value;
    struct TreeNode *left;
    struct TreeNode *right;
} TreeNode;

// 前序遍历（递归版本清晰直观）
void preorder(TreeNode *root) {
    if (root == NULL) return;          // 基线条件
    printf("%d ", root->value);        // 处理当前节点
    preorder(root->left);              // 遍历左子树
    preorder(root->right);             // 遍历右子树
}
```

用迭代实现同样的功能需要手动维护栈，复杂得多。

### 6.2 分治算法

归并排序、快速排序都天然适合递归：

```c
// 归并排序的递归分解部分
void merge_sort(int arr[], int left, int right) {
    if (left >= right) return;             // 一个元素，已有序

    int mid = left + (right - left) / 2;
    merge_sort(arr, left, mid);            // 排序左半
    merge_sort(arr, mid + 1, right);       // 排序右半
    merge(arr, left, mid, right);          // 合并两个有序部分
}
```

### 6.3 嵌入式系统中的限制——栈大小有限

**嵌入式环境现实**：

| 系统类型 | 典型栈大小 | 安全递归深度估计 |
|---------|-----------|----------------|
| PC/服务器 | 8 MB | ~250,000 层 |
| Linux 嵌入式 | 128 KB - 1 MB | ~4,000 - 30,000 层 |
| RTOS 任务栈 | 1 KB - 16 KB | ~30 - 500 层 |
| 裸机单片机 | 512 B - 4 KB | ~15 - 125 层 |

**嵌入式开发中递归使用的黄金法则**：

1. **深度可控**：递归深度有严格上限（树的深度已知、分治层数对数增长）
2. **每帧小**：递归函数中不使用大数组或结构体作为局部变量
3. **不用不确定深度的递归**：避免像 `fib(n)` 这样深度随输入线性增长的递归
4. **进行栈空间计算**：估算最坏情况下的最大栈深度，留出 50% 以上的余量
5. **考虑手动展开**：对于小输入范围的递归，直接展开为迭代

**平台声明**：以上栈大小数据是常见嵌入式开发板的典型值，具体数值取决于 MCU 型号、RTOS 配置和链接脚本。开发前应阅读芯片手册和链接脚本文件。

## 七、面试直连

### Q1: 递归的优缺点是什么？

**A**: 优点——代码简洁、自然反映问题的数学/结构定义（如树的遍历、分治算法）。缺点——函数调用有开销、递归深时消耗大量栈空间（可能栈溢出）、朴素递归可能有大量重复计算（如斐波那契）。面试加分：能根据具体场景定量分析，说出 "n=40 的朴素斐波那契需要约 3 亿次调用，栈深度达到 40 层"。

### Q2: 什么是尾递归？尾递归一定比普通递归高效吗？

**A**: 尾递归是递归调用作为函数最后一步执行（返回值直接被返回，不需要额外计算）。编译器可以用跳转（jmp）代替调用（call），使栈不增长。但尾递归一定高效的前提是编译器进行了尾调用优化（TCO）。C 标准不要求 TCO，嵌入式交叉编译器可能不支持。实际开发中不要依赖编译器优化来避免栈溢出。

### Q3: 为什么嵌入式系统要慎用递归？

**A**: 因为嵌入式系统的栈空间非常有限（通常 1KB-16KB），而递归每层调用都需要栈帧。一个深度为 100 的递归可能消耗 3KB 栈空间，在小型 MCU 上直接溢出了。而且嵌入式交叉编译器可能不支持尾调用优化，使问题更严重。面试加分：提到裸机环境下没有 MMU，栈溢出不会触发段错误而是静默破坏内存，更难调试。

### Q4: 如何将递归转换为迭代？

**A**: 通用方法是用栈结构（STL `stack` 或数组实现的栈）手动模拟递归调用栈。对于简单的递归，直接改为循环即可（如阶乘用 `for` 循环）。对于分治递归（如快速排序），可以用栈保存待处理的区间。面试加分：能画出递归调用栈对应的迭代栈结构。

### Q5: 记忆化递归和动态规划（DP）的关系是什么？

**A**: 记忆化是自顶向下的递归 + 缓存（Memoization），DP 是自底向上的迭代填表。它们在本质上等价——都利用了子问题的重叠性来避免重复计算。区别在于实现方向：记忆化直接修改递归函数，对思考负担小；DP 需要找出递推公式和填表顺序，效率更高（无函数调用开销）。面试加分：能用斐波那契举例说明两者时间都是 O(n)，但 DP 空间可以优化到 O(1)。

### Q6: 什么是递归回溯？给出一个实际例子。

**A**: 递归回溯是一种通过尝试所有可能路径来求解问题的算法。在每步尝试一个选择后递归处理剩余部分，如果发现当前选择导致死路，就撤销（回溯）并尝试下一个选择。典型例子：N 皇后问题、迷宫寻路、全排列生成。面试时可以用八皇后问题举例说明回溯 + 剪枝。

## 八、代码阅读题

### 题1

```c
#include <stdio.h>

int func(int a, int b) {
    if (b == 0) return a;
    return func(b, a % b);
}

int main(void) {
    printf("%d\n", func(48, 18));
    return 0;
}
```

**问题**：输出结果是什么？`func` 实现了什么算法？它的时间复杂度是多少？

<details>
<summary>答案</summary>
输出：`6`。`func` 实现了辗转相除法（欧几里得算法）求最大公约数。时间复杂度 O(log min(a, b))。
执行过程：func(48,18) → func(18,12) → func(12,6) → func(6,0) → 返回 6。
</details>

### 题2

```c
#include <stdio.h>

int mystery(int n) {
    if (n == 0) return 0;
    if (n == 1) return 1;
    return mystery(n - 1) + mystery(n - 2);
}

int main(void) {
    for (int i = 0; i <= 5; i++) {
        printf("%d ", mystery(i));
    }
    printf("\n");
    return 0;
}
```

**问题**：输出结果是什么？计算 `mystery(6)` 需要调用 `mystery` 函数多少次（包括根节点）？如何优化？

<details>
<summary>答案</summary>
输出：`0 1 1 2 3 5`。计算 mystery(6) 共需要调用 25 次。优化方法：记忆化递归或迭代（动态规划）。
</details>

### 题3

```c
#include <stdio.h>

int f(int n) {
    static int count = 0;
    count++;
    if (n <= 2) return n;
    return f(n - 1) + f(n - 2);
}

int main(void) {
    int result = f(5);
    printf("result=%d, f 被调用了 %d 次\n", result, /* 如何得到调用次数？ */);
    return 0;
}
```

**问题**：这段代码有什么设计问题？如果不修改 `f` 的接口，如何统计 `f` 的调用次数？静态局部变量在递归中有什么风险？

<details>
<summary>答案</summary>
问题：静态变量 count 不是线程安全的，且如果 f 在别处被调用，count 会被累计。如果要统计某次调用树的次数，需要在调用前重置 count（通过额外函数或在调用者处重置）。静态变量在递归中的风险：它的值被所有递归调用共享，可能导致违反预期的行为（如用它作为返回值的一部分）。
</details>

## 本章总结

1. **递归**是函数直接或间接调用自身的编程方式，核心是"用同样方法解决更小的问题"
2. 递归函数必须包含**基线条件**（递归终止）和**递归条件**（向基线推进），缺一不可
3. **栈帧**管理递归的执行过程，递推阶段入栈，回溯阶段出栈，深度受栈空间限制
4. 经典递归问题包括**阶乘**、**斐波那契数列**、**汉诺塔**、**全排列**和**二分查找**
5. 递归与迭代各有优劣：递归简洁但开销大且可能重复计算，迭代高效但代码相对冗长
6. **尾递归**可在编译器优化下将栈空间降到 O(1)，但 C 标准不保证优化
7. 常见错误：缺少基线条件、栈溢出、重复计算、全局变量副作用
8. **嵌入式系统**因栈空间有限，必须谨慎使用递归——深度可控并估算栈占用
9. 记忆化可解决重复计算问题，动态规划（自底向上）是更高效的选择
