# 文件 I/O 项目：电子相册

> 本章目标：把文件 I/O、目录遍历、帧缓冲、图片解析和输入事件串成一个完整项目思路。

## 1. 项目目标

电子相册项目的目标是：从指定目录中读取图片文件，并在屏幕上显示。用户可以通过触摸或按键切换上一张、下一张。

核心能力：

- 扫描目录，找出图片文件。
- 保存图片文件列表。
- 根据文件类型选择不同解析流程。
- 通过帧缓冲显示像素。
- 读取输入事件，实现切换控制。

模块职责：

| `lcd.*` | 封装帧缓冲显示 |
| `input.*` | 读取触摸或按键事件 |

## 3. 主循环设计

伪代码：

```c
int main(void) {
    image_list_t list;

    scan_images("./images", &list);
    lcd_open();
    input_open();

    int index = 0;
    while (1) {
        image_t *img = list_get(&list, index);
        display_image(img);

        event_t ev = input_wait();
        if (ev == EVENT_NEXT) {
            index = (index + 1) % list.count;
        } else if (ev == EVENT_PREV) {
            index = (index + list.count - 1) % list.count;
        }
    }
}
```

## 4. 文件列表设计

图片列表可以用链表或动态数组保存。

```c
typedef enum {
    IMG_BMP,
    IMG_JPG,
    IMG_UNKNOWN
} image_type_t;

typedef struct image_node {
    char path[256];
    image_type_t type;
    struct image_node *next;
} image_node_t;
```

扫描目录时，根据扩展名判断类型：

```c
if (ends_with(name, ".bmp")) {
    type = IMG_BMP;
} else if (ends_with(name, ".jpg") || ends_with(name, ".jpeg")) {
    type = IMG_JPG;
}
```

## 5. 帧缓冲基础

Linux 帧缓冲设备通常通过 `/dev/fb0` 访问。它可以理解为屏幕像素内存的映射。

基本流程：

1. `open("/dev/fb0", O_RDWR)` 打开设备。
2. `ioctl` 获取屏幕参数。
3. `mmap` 把显存映射到用户空间。
4. 向映射区域写入像素。
5. 程序退出时 `munmap` 和 `close`。

示例框架：

```c
int fd = open("/dev/fb0", O_RDWR);
if (fd < 0) {
    perror("open fb");
    return 1;
}

// 实际项目中还需要 ioctl 获取分辨率和像素格式
```

## 6. mmap 的意义

如果用 `write` 每次写大量像素，接口开销较高。`mmap` 可以把设备内存映射到进程地址空间，应用直接写内存即可更新显示。

```c
void *fb = mmap(NULL, screen_size,
                PROT_READ | PROT_WRITE,
                MAP_SHARED, fd, 0);
```

注意：

- 映射大小必须正确。
- 像素格式必须和屏幕一致。
- 写越界会造成显示异常甚至程序崩溃。

## 7. BMP 图片解析思路

BMP 是常见位图格式，未压缩 BMP 比较适合入门练习。

需要读取的信息：

| 字段 | 作用 |
|---|---|
| 文件头 | 判断是否为 BMP |
| 像素数据偏移 | 找到图像数据起始位置 |
| 宽度和高度 | 确定显示尺寸 |
| 位深 | 判断每个像素占多少字节 |

解析流程：

```text
打开文件 -> 读取文件头 -> 读取宽高和位深 -> 定位像素数据 -> 按行读取 -> 转换到屏幕像素格式
```

BMP 行数据通常有 4 字节对齐，显示时还要注意图像可能是倒序存储。

## 8. JPEG 图片解析思路

JPEG 是压缩格式，通常需要解码库辅助。项目中可以把 JPEG 解码封装到 `jpg.c`，主流程只关心“把图片显示出来”。

建议封装接口：

```c
int jpg_display(const char *path, lcd_t *lcd);
```

这样主循环不需要关心 JPEG 内部解码细节。

## 9. 输入事件

触摸屏、按键等输入设备通常通过 `/dev/input/eventX` 暴露。

读取事件结构：

```c
#include <linux/input.h>

struct input_event ev;
read(fd, &ev, sizeof(ev));
```

常见字段：

| 字段 | 含义 |
|---|---|
| `type` | 事件类型 |
| `code` | 事件编码 |
| `value` | 事件值 |

项目中可以把“左滑/右滑/按键”转换成统一事件：

```c
typedef enum {
    EVENT_NONE,
    EVENT_NEXT,
    EVENT_PREV,
    EVENT_QUIT
} event_t;
```

## 10. 项目实现顺序

建议不要一上来写完整项目。按下面顺序推进：

1. 在终端打印目录下所有图片路径。
2. 用链表保存图片路径并遍历打印。
3. 打开帧缓冲，显示纯色。
4. 显示一张 BMP。
5. 接入 JPEG 显示。
6. 读取输入事件。
7. 把输入事件和图片切换连接起来。

## 11. 易错点

- 文件路径只保存文件名，切换目录后打不开。
- BMP 行对齐没有处理，显示错位。
- 屏幕像素格式和图片像素格式不一致。
- `mmap` 大小计算错误。
- 输入事件设备路径写死，换设备后失效。
