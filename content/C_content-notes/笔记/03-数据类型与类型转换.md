# 数据类型与类型转换

## 学习目标

完成本模块的学习后，应能够：

1. 系统描述 C 语言的类型系统全貌，区分基本类型、派生类型和 void 类型
2. 理解整型家族的存储大小（标准最小范围 vs 典型平台大小）、有符号/无符号的区别
3. 掌握 fixed-width 整型（`int8_t`、`uint32_t` 等）以及 PRI 格式化宏的用途
4. 理解浮点型的 IEEE 754 表示原理、精度损失原因以及安全比较方法
5. 掌握 `sizeof` 运算符的本质（编译期运算符，不是函数）以及数组与指针的 sizeof 陷阱
6. 理解隐式类型转换规则（整数提升、通常算术转换）和显式转换的正确用法
7. 理解有符号/无符号混合运算的危险性和有符号整数溢出的未定义行为
8. 掌握 `const` 和 `volatile` 限定符在 C 语言中的正确含义（`const` 是只读变量，非编译期常量）
9. 理解嵌入式开发中的类型选择策略（fixed-width、volatile MMIO、const 查表等）

## 本章与工作的关系

数据类型与类型转换是 C 语言面试中**出现频率最高**的考点之一。面试官喜欢从看似简单的问题（"int 有多大?"）出发，层层深入考察你对实现定义行为、未定义行为、隐式转换、整数提升等底层机制的掌握程度。

- **企业开发**：类型选择直接影响程序的内存占用和执行效率。错误使用类型（如将有符号数与无符号数混用）是线上 bug 的常见根源。
- **嵌入式开发**：需要精确控制内存布局（寄存器位宽、Flash 查表、位域对齐），必须使用 fixed-width 类型和 `volatile` 限定符。
- **笔试面试**：几乎每轮 C 语言面试都会涉及 sizeof 陷阱、类型转换结果分析、const 和 volatile 的含义与区别。

## C 语言类型系统全景

C 语言的类型系统分为三类：**基本类型（basic types）**、**派生类型（derived types）** 和 **void 类型**。

```
C 语言类型系统
 │
 ├── 基本类型 (basic types)
 │   ├── 整型 (integer types)
 │   │   ├── char               (字符型，本质上是小整数)
 │   │   ├── signed char        (有符号字符)
 │   │   ├── unsigned char      (无符号字符)
 │   │   ├── short / unsigned short
 │   │   ├── int / unsigned int
 │   │   ├── long / unsigned long
 │   │   └── long long / unsigned long long  (C99 起)
 │   ├── 浮点型 (floating types)
 │   │   ├── float              (单精度)
 │   │   ├── double             (双精度)
 │   │   └── long double        (扩展精度)
 │   └── 布尔类型 (_Bool, C99 起)
 │
 ├── 派生类型 (derived types)
 │   ├── 指针类型 (pointer)
 │   ├── 数组类型 (array)
 │   ├── 函数类型 (function)
 │   └── 结构/联合/枚举 (struct / union / enum)
 │
 └── void 类型
     ├── void                  (空类型，不能定义变量)
     └── void*                 (指向 void 的指针，通用指针)
```

> **说明**：`char` 在类型分类中同时属于字符类型和整型家族——它本质上是一个 1 字节的整数。`_Bool` 在 C99 标准中被归为无符号整型的一种。

## 整型详解

### 整型家族成员

| 类型 | C 标准最小范围 | 大多数 64 位平台典型大小 | 典型范围 |
|------|--------------|:----------------------:|---------|
| `char` | -127 ~ 127 或 0 ~ 255 | 1 字节 | -128 ~ 127 或 0 ~ 255 |
| `short` | -32767 ~ 32767 | 2 字节 | -32768 ~ 32767 |
| `unsigned short` | 0 ~ 65535 | 2 字节 | 0 ~ 65535 |
| `int` | -32767 ~ 32767 | **4 字节** | -2,147,483,648 ~ 2,147,483,647 |
| `unsigned int` | 0 ~ 65535 | **4 字节** | 0 ~ 4,294,967,295 |
| `long` | -2147483647 ~ 2147483647 | **8 字节**（64 位系统） | ≈ ±9.22×10¹⁷ |
| `unsigned long` | 0 ~ 4294967295 | **8 字节** | 0 ~ 1.84×10¹⁹ |
| `long long` | -9223372036854775807 ~ 9223372036854775807 | 8 字节 | ≈ ±9.22×10¹⁸ |
| `unsigned long long` | 0 ~ 18446744073709551615 | 8 字节 | 0 ~ 1.84×10¹⁹ |

**对"int 大小"的关键说明**（面试高频考点）：

`int` 的大小是**实现定义（implementation-defined）的**，C 标准仅要求它至少能表示 -32767 ~ 32767（即至少 16 位）。最常见的 64 位 PC 和服务器上 `int` 为 4 字节（32 位），但在一些 16 位微控制器（如 MSP430）上 `int` 为 2 字节，在一些早期大型机或 DSP 上可能为 4 字节。因此，"int 就是 4 字节" 的说法仅在特定平台上成立，不是一个 C 语言的通用保证。

C 标准保证的层级关系为：
```
sizeof(char) == 1
1 ≤ sizeof(short) ≤ sizeof(int) ≤ sizeof(long) ≤ sizeof(long long)
```

### 有符号与无符号

- **有符号（signed）**：用于表示负数、零和正数。现代平台通常采用**补码（two's complement）**；C23 才统一要求补码表示，更早的 C 标准还允许原码和反码实现。
- **无符号（unsigned）**：所有位均用于表示数值，范围从 0 到 `2^n - 1`（n 为位数）。

### 定宽整型（Fixed-width Integer Types）—— C99 `<stdint.h>`

为了编写**跨平台**代码，C99 引入了精确宽度的整型：

```c
#include <stdint.h>

int8_t   val1;   // 有符号 8 位整数
uint8_t  val2;   // 无符号 8 位整数
int16_t  val3;   // 有符号 16 位整数
uint32_t val4;   // 无符号 32 位整数
int64_t  val5;   // 有符号 64 位整数
```

> **注意**：`int8_t` 等类型是可选（optional）的——只有当平台能够以精确宽度表示时才会定义。不过绝大多数主流平台上（包括所有常见的 PC、服务器、ARM 和 RISC-V 微控制器）它们都存在。

### 格式化宏——`<inttypes.h>`

定宽整型的底层基础类型因平台数据模型而异，`uint32_t` 可能是 `unsigned int`，也可能是其他满足条件的无符号类型，因此不能凭系统是32位还是64位猜测格式符。`inttypes.h` 提供了 PRI 宏来消除这种平台差异：

```c
#include <stdio.h>
#include <stdint.h>
#include <inttypes.h>

int main(void)
{
    uint64_t big_num = 123456789012345ULL;
    printf("Value = %" PRIu64 "\n", big_num);  // 输出: Value = 123456789012345
    // PRIu64 在 64 位系统展开为 "lu"，在 32 位系统展开为 "llu"

    int32_t val = -100;
    printf("Value = %" PRId32 "\n", val);      // PRId32 展开为 "d"
    return 0;
}
```

> **工程实践**：嵌入式开发、网络协议栈、文件格式解析等要求精确定义数据宽度的场景，应始终使用 `<stdint.h>` 中的定宽类型，而不是直接使用 `int` 或 `long`。

## 字符型深入

### char 本质上是一个小整数

C 语言中的 `char` 类型占用 1 字节，用于存储字符编码（最常用的是 ASCII）。每个字符对应一个整数值：

```c
#include <stdio.h>

int main(void)
{
    char ch = 'A';
    printf("字符: %c\n", ch);        // A
    printf("ASCII 码: %d\n", ch);    // 65

    // char 可以直接参与算术运算
    char next = ch + 1;
    printf("下一个字符: %c\n", next); // B (ASCII 66)

    // 小写转大写
    char lower = 'b';
    char upper = lower - 32;         // 'b' - 'a' + 'A' = 98 - 97 + 65 = 66 = 'B'
    printf("大写: %c\n", upper);     // B

    return 0;
}
```

### signed char 与 unsigned char

`char`、`signed char`、`unsigned char` 在 C 标准中是**三种不同的类型**。

- `char` 默认是 signed 还是 unsigned 由**编译器决定**（实现定义行为，implementation-defined behavior）。在大多数 x86/x86-64 编译器上 `char` 等价于 `signed char`，在 ARM 某些编译器上默认是 `unsigned char`。
- 如果代码依赖字符变量的取值范围，应显式使用 `signed char` 或 `unsigned char`。

```c
#include <stdio.h>

int main(void)
{
    // 检查当前编译器 char 的默认符号
    char c = -1;
    if (c == -1) {
        printf("char 默认是 signed\n");
    } else if ((unsigned char)c == 255) {
        printf("char 默认是 unsigned\n");
    }

    signed char   sc = -128;     // 明确有符号，范围 -128 ~ 127
    unsigned char uc = 255;      // 明确无符号，范围 0 ~ 255
    // unsigned char uc = 256;   // 警告：256 无法放入 unsigned char，截断为 0
    return 0;
}
```

### ASCII 表核心记忆

| 范围 | 含义 | 例子 |
|------|------|------|
| 0x00–0x1F | 控制字符（不可打印） | '\0' (0)、'\n' (10)、'\t' (9) |
| 0x20 | 空格（Space） | ' ' = 32 |
| 0x30–0x39 | 数字 '0'–'9' | '0' = 48, '9' = 57 |
| 0x41–0x5A | 大写字母 'A'–'Z' | 'A' = 65, 'Z' = 90 |
| 0x61–0x7A | 小写字母 'a'–'z' | 'a' = 97, 'z' = 122 |

> **记忆技巧**：`'A'` = 65，`'a'` = 97，小写字母比对应大写字母大 32。`'0'` = 48，数字字符减去 `'0'` 即可得到数值：`'5' - '0'` = 5。

### 转义序列（Escape Sequences）

| 序列 | 含义 | ASCII 值 |
|------|------|:--------:|
| `\0` | 空字符（null terminator） | 0 |
| `\n` | 换行（newline） | 10 |
| `\t` | 水平制表（tab） | 9 |
| `\\` | 反斜杠 | 92 |
| `\'` | 单引号 | 39 |
| `\"` | 双引号 | 34 |
| `\xNN` | 十六进制转义（如 `\x41` = 'A'） | 由 NN 指定 |
| `\NNN` | 八进制转义（如 `\101` = 'A'） | 由 NNN 指定 |

### 宽字符（Wide Characters）简介

C 语言通过 `<wchar.h>` 和 `wchar_t` 类型支持宽字符（通常为 2 或 4 字节），用于表示 Unicode 等大字符集：

```c
#include <wchar.h>
#include <stdio.h>

wchar_t wc = L'中';   // L 前缀表示宽字符字面量
wprintf(L"%lc\n", wc); // wprintf 用于宽字符输出
```

在嵌入式系统等内存受限环境中，宽字符使用较少；更常见的做法是使用 UTF-8 编码（存储在 `char` 数组中）。

## 浮点型

### 浮点类型家族

| 类型 | 典型大小 | 有效十进制位数 | 典型范围 | 说明 |
|------|:-------:|:-------------:|:--------:|------|
| `float` | 4 字节 | 约 6–7 位 | ±1.2×10⁻³⁸ ~ ±3.4×10³⁸ | 单精度（IEEE 754 binary32） |
| `double` | 8 字节 | 约 15–16 位 | ±2.2×10⁻³⁰⁸ ~ ±1.8×10³⁰⁸ | 双精度（IEEE 754 binary64），C 中**浮点字面量的默认类型** |
| `long double` | 平台相关 | 不低于 double | 不低于 double | x86 上通常为 80 位扩展精度（10 字节），ARM 上通常与 double 相同 |

> **注意**：C 标准规定 `float` ≤ `double` ≤ `long double`，未强制要求 IEEE 754，但绝大多数现代平台实现了 IEEE 754 标准。

### IEEE 754 基本原理

以单精度 `float`（32 位）为例：

```
 31 30      23 22                        0
┌──┬──────────┬───────────────────────────┐
│ S│ Exponent │         Mantissa          │
└──┴──────────┴───────────────────────────┘
 1位   8位           23位
```

- **S（符号位）**：0 为正，1 为负
- **Exponent（指数）**：偏移表示（单精度偏移 127），决定量级
- **Mantissa（尾数/有效数字）**：表示精度

> **直觉理解**：浮点数在数轴上不是均匀分布的——靠近 0 的地方密度大，远离 0 的地方密度小。这就是为什么大数加小数可能导致精度损失。

### 精度损失与浮点数比较

```c
#include <stdio.h>

int main(void)
{
    float a = 0.1f;
    float b = 0.2f;
    float c = a + b;

    printf("0.1f + 0.2f = %.10f\n", c);  // 0.3000000119，不是 0.3

    // 错误：直接使用 == 比较
    if (c == 0.3f) {
        printf("相等\n");
    } else {
        printf("不相等！\n");
    }

    // 浮点数累加误差示例
    float sum = 0.0f;
    for (int i = 0; i < 100; i++) {
        sum += 0.01f;
    }
    printf("0.01 * 100 = %.10f\n", sum);  // 不是精确的 1.0
    return 0;
}
```

### 安全的浮点数比较方法

使用**误差范围（epsilon）** 进行比较：

```c
#include <math.h>
#include <stdio.h>

#define EPSILON 1e-6f   // 根据应用精度要求选择 epsilon

int main(void)
{
    float a = 0.1f + 0.2f;

    // 判断是否近似相等
    if (fabsf(a - 0.3f) < EPSILON) {
        printf("a 近似等于 0.3\n");
    }

    double x = 1.0 / 3.0;
    // 比较两个 double 时使用 fabs()
    if (fabs(x - 0.333333) < 1e-9) {
        printf("x 近似等于 0.333333\n");
    }
    return 0;
}
```

> **工程实践**：在比较浮点数时，通常不直接使用 `==`。但在以下有限情况下可以接受：比较同一个变量赋值的结果、与 0 比较（需要特别小心负零）、与 NaN/INF 的判断。

### NaN 与 INF

```c
#include <stdio.h>
#include <math.h>

int main(void)
{
    // IEEE 754 下产生 INF；C 标准不强制要求 IEEE 754
    double inf = 1.0 / 0.0;       // 仅在采用 IEC 60559 语义时可预期为正无穷
    double nan = 0.0 / 0.0;       // 仅在采用 IEC 60559 语义时可预期为 NaN

    printf("inf = %f\n", inf);     // inf
    printf("nan = %f\n", nan);     // nan

    // 判断方法
    printf("isinf(inf): %d\n", isinf(inf));         // 1
    printf("isnan(nan): %d\n", isnan(nan));         // 1

    // 注意事项
    if (nan == nan) {             // 永远为假！NaN 不等于任何值，包括自身
        printf("这条不会执行\n");
    }
    return 0;
}
```

> **关键说明**：`1.0 / 0.0` 在采用 IEC 60559 / IEEE 754 浮点语义的实现上产生 INF（正无穷），而非未定义行为。但 C 标准不强制要求 IEEE 754，且 `整数 / 0` 在任何情况下都是未定义行为。

## 布尔类型

C 语言在 C99 标准之前没有专用的布尔类型，通常用 `int` 表示真假（0 为假，非 0 为真）。

### C99 引入 `_Bool`

```c
#include <stdio.h>

int main(void)
{
    _Bool flag = 1;     // _Bool 是 C99 内建的关键词
    _Bool false_val = 0;

    // 任何非 0 值赋给 _Bool 都会被转换为 1
    _Bool true_val = 100;   // true_val 实际存储为 1
    _Bool also_true = -5;   // 也被转换为 1

    printf("flag = %d\n", flag);
    printf("true_val = %d\n", true_val);
    printf("also_true = %d\n", also_true);
    return 0;
}
```

### `<stdbool.h>`——更友好的写法

C99 同时提供了 `<stdbool.h>`，定义了三个宏：

```c
#include <stdbool.h>   // 定义 bool, true, false 三个宏

int main(void)
{
    bool is_valid = true;
    bool is_done = false;

    // bool 变量本质上是 _Bool，大小为 1 字节
    printf("size of bool: %zu\n", sizeof(bool));   // 1

    if (is_valid) {
        printf("有效\n");
    }
    return 0;
}
```

> **说明**：C23 标准已正式将 `bool` 作为内建关键词，不再需要包含 `<stdbool.h>`。

## sizeof 运算符深度解析

### sizeof 不是函数

`sizeof` 是**编译期运算符**（compile-time operator），不是函数。它返回操作数所占内存的字节数，结果类型为 `size_t`（无符号整型，格式化输出用 `%zu`）。不需要也不应该加括号（加括号只是为了改变运算顺序或使代码更清晰）。

```c
sizeof int       // 合法：sizeof 是运算符
sizeof(int)      // 也合法：括号只是类型名时的语法要求
sizeof x + y     // 等价于 (sizeof x) + y，不是 sizeof(x + y)！
```

### sizeof 对数组 vs 指针

这是面试中最常见的 sizeof 陷阱之一。

```c
#include <stdio.h>

void func(int arr[])    // 数组参数退化为指针！等价于 void func(int *arr)
{
    printf("函数内 sizeof(arr) = %zu\n", sizeof(arr));   // 8（指针大小，64 位系统）
}

int main(void)
{
    int arr[10] = {0};
    int *p = arr;

    printf("sizeof(arr) = %zu\n", sizeof(arr));   // 40（10 × 4 字节）
    printf("sizeof(p)   = %zu\n", sizeof(p));     //  8（指针本身的大小，64 位系统）

    // 计算数组元素个数的经典写法（仅在数组作用域内有效）
    size_t count = sizeof(arr) / sizeof(arr[0]);
    printf("元素个数 = %zu\n", count);             // 10

    func(arr);  // 传入的是指针，不是数组本身
    return 0;
}
```

> **陷阱总结**：当数组作为函数参数传递时，它"退化（decay）"为指向第一个元素的指针。此时 `sizeof` 只能得到指针的大小，而不是数组的大小。因此不能在函数内部用 `sizeof(arr)/sizeof(arr[0])` 计算数组长度——必须额外传入长度参数。

### sizeof 与变长数组（VLA，Variable-Length Array）

C99 引入的 VLA 是 sizeof 的一个例外：sizeof 对 VLA 求值是**运行时**的（因为 VLA 的大小在编译时未知）：

```c
#include <stdio.h>

int main(void)
{
    int n = 10;
    int vla[n];          // VLA：长度在运行时确定

    printf("sizeof(vla) = %zu\n", sizeof(vla));   // 输出 40（运行时计算：10 × 4）
    // 对 VLA 使用 sizeof 是在运行时求值，不是编译期

    n = 5;
    // 注意：VLA 的大小在声明时就固定了，后续修改 n 不影响已声明的 vla
    return 0;
}
```

### 常见面试陷阱

```c
// 陷阱 1：sizeof 对空结构体（C 标准规定结构体大小不能为 0，不同编译器有不同处理）
struct Empty { };
printf("%zu\n", sizeof(struct Empty));  // 某些编译器输出 0，某些输出 1（GCC 输出 0）

// 陷阱 2：sizeof 对字符串字面量
printf("%zu\n", sizeof("hello"));       // 6（包含末尾的 '\0'！注意不是 5）
printf("%zu\n", strlen("hello"));       // 5（strlen 不计 '\0'）

// 陷阱 3：sizeof 对联合体
union Data {
    int i;
    double d;
};
printf("%zu\n", sizeof(union Data));    // 8（取最大成员的大小，double 为 8 字节）
```

## 类型转换详解

### 隐式类型转换（Implicit Type Conversion）

C 编译器在以下情况会自动进行隐式类型转换：

#### 1. 整数提升（Integer Promotion）

在表达式中，任何比 `int` 短的整数类型（`char`、`short`、它们的 `unsigned` 版本、`_Bool`）都会被提升为 `int`（或 `unsigned int`，如果 `int` 无法表示原类型的所有值）。详见"整数提升与符号扩展"一节。

#### 2. 通常算术转换（Usual Arithmetic Conversions）

当双目运算符的两个操作数类型不同时，编译器按"等级（rank）"将较低等级的操作数提升到较高等级。转换层次如下（从低到高）：

```
long double  ←  double  ←  float
                                   ↑
unsigned long long  ←  long long
       ↑
unsigned long  ←  long
       ↑
unsigned int  ←  int    ←  整数提升 (char, short → int)
```

```c
#include <stdio.h>

int main(void)
{
    int a = 10;
    double b = 3.5;

    double result = a + b;   // a 被隐式转换为 double，结果是 double 类型
    printf("%d + %.1f = %.1f\n", a, b, result);  // 10 + 3.5 = 13.5
    return 0;
}
```

#### 3. 赋值转换

将值赋给不同类型的变量时，编译器自动进行转换：

```c
double pi = 3.14159;
int n = pi;           // n = 3，小数部分被截断（截断向零，不是四舍五入）

int a = 5, b = 2;
double r = a / b;     // 2.0 而不是 2.5！因为 a / b 先做整数除法得 2，再转 double
```

### 显式类型转换（强制类型转换，Explicit Cast）

语法：`(目标类型) 表达式`

```c
#include <stdio.h>

int main(void)
{
    int a = 5, b = 2;

    double r1 = a / b;                  // 2.0（整数除法后转换）
    double r2 = (double)a / b;          // 2.5（a 先转 double）
    double r3 = (double)(a / b);        // 2.0（先整数除法再转 double）

    printf("r1 = %f, r2 = %f, r3 = %f\n", r1, r2, r3);

    // 指针类型转换（风险极高）
    int x = 12345;
    double *p = (double *)&x;           // 将 int 指针强转为 double 指针
    printf("%f\n", *p);                  // 未定义行为！类型双关（type punning）
    return 0;
}
```

> **工程建议**：强制类型转换会关闭编译器的类型检查，滥用可能导致难以调试的 bug。在嵌入式开发中，MMIO（内存映射 I/O）地址转换、协议栈数据解析等场景不得已需要使用，但应尽量减少。

### 有符号与无符号混合——危险区

这是 C 语言中最容易出 bug 的隐式转换场景之一：

```c
#include <stdio.h>

int main(void)
{
    // 场景 1：有符号与无符号比较
    int a = -1;
    unsigned int b = 1;

    if (a < b) {
        printf("a < b\n");      // 你以为会执行这条
    } else {
        printf("a >= b\n");     // 实际执行这条！
    }
    // 原因：a 被隐式转换为 unsigned int，-1 变成 0xFFFFFFFF（即 4294967295），所以 a >= b

    // 场景 2：无符号循环陷阱
    for (unsigned int i = 5; i >= 0; i--) {    // 无限循环！
        // i 从 0 减 1 后变为 UINT_MAX（42 亿多），永远 >= 0
        if (i == 0) break;      // 唯一的退出方式
    }

    // 场景 3：有符号数转无符号数
    signed int si = -3;
    unsigned int ui = si;       // 位模式不变，但解释为无符号大数
    printf("si = %d, ui = %u\n", si, ui);  // si = -3, ui = 4294967293

    return 0;
}
```

> **工程规则**：避免将 `int` 和 `unsigned int` 混合运算或比较。对无符号类型不要使用 `i >= 0` 作为循环条件。使用 `-Wsign-compare` 编译选项帮助检测此类问题。

### 有符号整数溢出——未定义行为（UB，Undefined Behavior）

有符号整数溢出是**未定义行为**。编译器可以生成任何代码——不做任何假设。

```c
#include <stdio.h>
#include <limits.h>

int main(void)
{
    int max = INT_MAX;    // 2147483647（在 32-bit int 平台上）
    int overflow = max + 1;   // 未定义行为！

    printf("max = %d\n", max);
    printf("overflow = %d\n", overflow);   // 输出的值不可预测，依赖于编译器行为
    // 某些编译器可能会"绕回"到 -2147483648，但这绝不是保证

    return 0;
}
```

> **关键说明**：无符号整数溢出有明确定义的行为——绕回（wraparound）模 `UINT_MAX + 1`。例如 `UINT_MAX + 1` = 0。这属于**已定义行为（well-defined behavior）**，与有符号整数溢出的未定义行为严格不同。千万不要混淆。

## 整数提升与符号扩展

### 为什么 char 和 short 会被提升为 int？

C 语言中一个历史原因的设计：早期 CPU 上的算术运算至少需要 `int` 的精度（寄存器宽度至少 16 位），因此在表达式中遇到 `char` 或 `short` 时，编译器会**自动将它们提升为 `int`**。

```
表达式:  c1 + c2     (c1, c2 均为 char)
            │
            ▼
      整数提升 (integer promotion)
            │
            ▼
      (int)c1 + (int)c2   →   结果类型为 int
```

```c
#include <stdio.h>

int main(void)
{
    char c1 = 100, c2 = 100;
    char result = c1 + c2;      // c1 + c2 先提升为 int，结果为 int（200），再截断为 char

    // 关键证明：sizeof 表达式的结果
    char c = 'A';
    printf("sizeof(c)         = %zu\n", sizeof(c));      // 1
    printf("sizeof(c + c)     = %zu\n", sizeof(c + c));  // 4（int！因为 c 被提升为 int）
    printf("sizeof(c + 0)     = %zu\n", sizeof(c + 0));  // 4（同上）

    short s = 10;
    printf("sizeof(s + s)     = %zu\n", sizeof(s + s));  // 4（short 也提升为 int）
    return 0;
}
```

### 符号扩展（Sign Extension）vs 零扩展（Zero Extension）

当将一个较窄的有符号类型赋值给较宽的类型时，高位根据符号位填充（符号扩展）；无符号类型则高位填 0（零扩展）。

```
signed char c = -5;   // 二进制: 1111 1011
int i = c;            // 符号扩展: 1111 1111 1111 1111 1111 1111 1111 1011
                      // i 的值: -5（正确保持负数）

unsigned char uc = 200;  // 二进制: 1100 1000
int j = uc;              // 零扩展: 0000 0000 0000 0000 0000 0000 1100 1000
                         // j 的值: 200（正数保持）

signed char sc = -1;
unsigned int ui = sc;    // 先符号扩展为 int（-1），再隐式转 unsigned int
                         // ui = 0xFFFFFFFF = 4294967295（不是 255！）
```

> **面试陷阱**：`(unsigned int)(signed char)-1` 的值是多少？答案是 `4294967295`（即 `UINT_MAX`），而不是 `255`。因为先符号扩展为 `int(-1)`，再作为 `unsigned int` 解释。

## const、volatile 限定符

### const——只读变量，而非编译期常量

C 语言中的 `const` 表示变量是**只读（read-only）** 的，不可以被直接修改。但它**不是编译期常量**（compile-time constant）。

这是 C 与 C++ 的一个关键区别：C++ 中满足常量表达式要求的 `const int` 可以用于编译期数组长度；C 中的 `const int` 不是整数常量表达式。不过，在支持 VLA 的 C99/C11 实现中，它可以在块作用域作为变长数组长度。

```c
// ---- C 语言中 ----
const int n = 10;
// int arr[n];   // C 中 const int 不是整数常量表达式，但在块作用域中这是一个合法的 VLA（C99起）
// 文件作用域数组必须使用整数常量表达式；块作用域还可以使用实现支持的 VLA

// 正确做法：使用宏或 enum
#define SIZE 10
int arr1[SIZE];

enum { SIZE2 = 10 };
int arr2[SIZE2];

// ---- const 是只读变量 ----
const int x = 100;
// x = 200;           // 编译错误：不能直接修改 const 变量

// 但可以通过指针绕过类型系统修改（不要这样做！）
int *p = (int *)&x;
*p = 200;             // 未定义行为！x 可能是只读内存区域（如放在 .rodata 段）
```

> **面试重点**：面试官常问"C 的 const 和 C++ 的 const 有何区别？"核心答案——C 的 const 只保证"不可通过该左值修改"，不是整数常量表达式；C++ 中满足条件的整数 const 可以作为常量表达式。两种语言的链接规则差异应限定在文件作用域讨论，不能笼统地说所有 const 都具有某种链接属性。

### volatile——保留抽象机可观察的易变访问

`volatile` 限定符告知编译器：对象的值可能在普通程序流程之外发生变化（如硬件寄存器更新、信号处理函数修改）。对 volatile 对象的访问属于抽象机中的可观察行为，编译器必须按语言规则保留这些访问；但这不等于“禁止所有优化”。

> **关键澄清**：`volatile` **不保证**原子性、线程同步、缓存一致性或内存屏障。多线程共享变量应使用 `_Atomic` / `stdatomic.h` 或同步机制（互斥锁）。信号处理函数中共享的标志应使用 `volatile sig_atomic_t`。

```c
#include <stdio.h>
#include <signal.h>

volatile sig_atomic_t flag = 0;  // 信号处理函数与主流程共享的最小安全标志类型

void handler(int sig)
{
    (void)sig;
    flag = 1;             // 修改 volatile 变量
}

int main(void)
{
    signal(SIGINT, handler);
    printf("按 Ctrl+C 触发信号...\n");

    while (!flag) {
        // 若 flag 不加 volatile，编译器可能将 flag 的值优化到寄存器中，
        // 导致循环永远感知不到 flag 的变化
    }

    printf("收到信号！\n");
    return 0;
}
```

嵌入式开发中 `volatile` 的典型应用——访问硬件寄存器：

```c
// 假设硬件寄存器映射到地址 0x40020000
volatile unsigned int *status_reg = (volatile unsigned int *)0x40020000;

// 每次读取都真正从硬件寄存器读取，而不是从缓存的值
while (*status_reg & 0x01) {
    // 等待硬件置位第 0 位
}
```

### const volatile 组合

`const` 和 `volatile` 不是互斥的，可以同时修饰一个变量。这种组合表示：**程序代码不能修改这个变量，但它的值可能被外部因素改变**。最常见的场景是**只读硬件寄存器**（如状态寄存器）：

```c
// 只读状态寄存器：程序不能写，但硬件会更新其值
const volatile uint32_t *status = (const volatile uint32_t *)0x40021000;

// uint32_t status_val = *status;   // 允许读，每次真正读取硬件
// *status = 0;                     // 编译错误！因为 const 禁止写入
```

> **面试题**："一个既是 const 又是 volatile 的变量有什么用？"——只读硬件寄存器。const 表示程序不应修改它，volatile 表示它的值可能因外部硬件事件而改变。

## 嵌入式开发中的类型选择

### 1. 优先使用定宽类型

在嵌入式开发中，寄存器宽度是固定的（8/16/32/64 位），必须使用精确宽度的类型：

```c
#include <stdint.h>

typedef volatile uint32_t reg32_t;   // 32 位寄存器类型

// 将某个地址映射为寄存器指针
#define GPIOA_BASE      0x40020000UL
#define GPIOA_MODER     ((reg32_t *)(GPIOA_BASE + 0x00))
#define GPIOA_ODR       ((reg32_t *)(GPIOA_BASE + 0x14))

// 设置 GPIO 模式
*GPIOA_MODER |= (1 << 0);   // 将 PA0 设为输出模式
```

### 2. volatile 用于 MMIO

内存映射 I/O 的寄存器访问**必须**使用 `volatile`。否则编译器可能优化掉看似"多余"的多次读取。

### 3. const 用于 Flash 查表

```c
// 将常量数据放在 Flash/ROM 中（而不是 RAM）
const uint8_t sine_table[256] = {
    128, 131, 134, 137, /* ... 预计算的正弦表 ... */
};

// uint8_t val = sine_table[100];  // 从 Flash 读取
```

### 4. 位域（Bit-field）的注意事项

```c
struct {
    unsigned int enable : 1;   // 位域：占 1 位
    unsigned int mode   : 2;   // 占 2 位
    unsigned int        : 3;   // 无名位域：填充 3 位（对齐用）
    unsigned int flag   : 1;
} reg;

// 位域的排列顺序（大端 vs 小端）是编译器相关的
// 位域不能跨字节边界的行为也是实现定义的
// 在需要精确位布局的场景（如硬件寄存器映射），优先使用手动位操作而非位域
```

### 5. 结构体对齐与填充

```c
#include <stddef.h>  // offsetof 宏

struct __attribute__((packed)) SensorData {   // packed 消除填充
    uint8_t  id;          // 偏移 0
    uint32_t timestamp;   // 偏移 1（无 packed 时装在偏移 4，有 packed 时在偏移 1）
    uint16_t value;       // 偏移 5（无 packed 时在偏移 8）
    // 无 packed 时 sizeof = 12（含填充）；有 packed 时 sizeof = 7
};

// 注意：packed 可节省空间但降低访问速度（未对齐访问需要分多次读取）
```

## 面试直连

### Q1: C 语言中 int 类型有多大？（How big is int in C?）

**答案**：`int` 的大小是**实现定义（implementation-defined）** 的。C 标准只要求它至少能表示 -32767 ~ 32767（即至少 16 位）。在大多数 64 位 PC 和服务器上 `int` 为 4 字节（32 位），在 16 位微控制器上为 2 字节，在 32 位系统上为 4 字节。绝对不能假设 `int` 永远是 4 字节。

### Q2: 什么是整数提升？（What is integer promotion?）

**答案**：整数提升是 C 语言隐式类型转换的一种规则：在表达式中，任何等级低于 `int` 的整数类型（`char`、`short`、`_Bool` 以及它们的 `unsigned` 版本）都会被提升为 `int`（或 `unsigned int`，如果 `int` 无法表示原类型所有可能值）。例如 `char + char` 的表达式结果是 `int` 类型，不是 `char`。

### Q3: C 语言中的 const 和 C++ 中的 const 有什么区别？（Explain the difference between const in C and C++）

**答案**：C 语言中 `const` 修饰的变量本质上是**只读变量（read-only variable）**，不是整数常量表达式（integer constant expression）。`const int n = 10; int arr[n];` 在块作用域中是合法的变长数组（VLA，C99起且实现支持）——虽然 n 不是编译期常量，但数组长度可在运行时确定。文件作用域不允许 VLA，数组大小必须是整数常量表达式。C++ 中满足条件的整数 const 可以作为常量表达式。链接规则也有差异，但必须限定在文件作用域讨论：C++ 的非 extern、非 volatile const 对象默认具有内部链接，不能把这条规则扩展到所有作用域和所有 const 声明。

### Q4: 有符号整数溢出是什么？（What is undefined behavior in signed integer overflow?）

**答案**：有符号整数溢出是**未定义行为（Undefined Behavior，UB）**。这意味着 C 标准不给任何保证——编译器可以生成任意代码，程序可能崩溃、产生错误结果、甚至完全不可预测。例如 `INT_MAX + 1` 是 UB，千万不要依赖"绕回"行为。与之不同，无符号整数溢出是有明确定义的，它使用模运算绕回。

### Q5: 如何安全比较浮点数？（How to safely compare floating-point numbers?）

**答案**：由于 IEEE 754 浮点数的表示方式，大多数浮点数无法精确存储（如 0.1），因此不应直接使用 `==` 比较。安全做法是比较两个浮点数的差的绝对值是否小于一个很小的误差范围（epsilon），如 `fabs(a - b) < EPSILON`。C 标准库提供了 `isnan()` 和 `isinf()` 来判断 NaN 和 INF 情况。

### Q6: volatile 的含义和用途是什么？（What does volatile mean and when do you need it?）

**答案**：`volatile` 告诉编译器，变量的值可能在程序流程之外被改变，因此编译器不能优化对其的读写访问。需要 `volatile` 的场景：1）访问内存映射硬件寄存器（MMIO）；2）在信号处理函数中修改的全局变量；3）`setjmp` 所在函数中可能被 longjmp 修改的自动变量。`const` 和 `volatile` 可以同时使用（如只读硬件状态寄存器）。

### Q7: 如何检测当前平台 char 的默认符号？（Write code to detect if char is signed or unsigned）

```c
#include <stdio.h>

int main(void)
{
    char c = -1;
    if (c == -1) {
        printf("char 默认是 signed\n");
    } else if ((unsigned char)c == 255) {
        printf("char 默认是 unsigned\n");
    } else {
        printf("未知\n");
    }
    return 0;
}
```

### Q8: 为什么 sizeof 对数组和指针给出不同的结果？

**答案**：`sizeof` 对数组返回整个数组占用的字节数（编译期已知），对指针只返回指针本身的大小（在 64 位系统上为 8 字节）。这背后的机制是：当数组名用在表达式中（除 `&` 和 `sizeof` 的操作数外）时，它"退化（decay）"为指向第一个元素的指针。数组作为函数参数传递时也发生这种退化，因此在函数内 sizeof 数组参数只会得到指针的大小。

### Q9: 什么是未定义行为（UB）和实现定义行为？有何区别？

**答案**：**未定义行为（UB）** 指 C 标准完全不作任何规定，程序可能崩溃、产生错误结果甚至看起来"正常工作"——编译器可以生成任意代码。常见 UB 包括：有符号整数溢出、数组越界、空指针解引用。**实现定义行为**指 C 标准给出了选项，每个编译器必须选择一种行为并记录下来（如 `int` 的大小、`char` 的默认符号、右移对有符号数的处理方式）。两者的核心区别是：UB 的程序是**错误的**，标准不要求任何可预测行为；实现定义行为下程序是正确的，但不可移植。

### Q10: 什么是类型双关（type punning）？为什么危险？

**答案**：类型双关指通过不同类型的指针访问同一个内存位置，如将 `int*` 强转为 `float*` 再解引用。这违反 C 语言的严格别名规则（strict aliasing rule），导致未定义行为。正确做法是使用 `memcpy()` 或联合体（union，C99/C11 下的特定形式）进行类型转换。

## 代码阅读题

### 题 1：sizeof 陷阱

```c
#include <stdio.h>
#include <string.h>

void test(int arr[5])
{
    printf("%zu\n", sizeof(arr));
}

int main(void)
{
    int arr[5] = {1, 2, 3, 4, 5};
    int *p = arr;

    printf("%zu\n", sizeof(arr));
    printf("%zu\n", sizeof(p));
    test(arr);
    printf("%zu\n", sizeof("Hello"));
    return 0;
}
```

**问题**：在 64 位平台上（`int` 为 4 字节），输出的四行结果各是什么？

<details>
<summary>答案</summary>

- `sizeof(arr)` = 20（5 个 int × 4 字节）
- `sizeof(p)` = 8（指针大小，64 位）
- `sizeof(arr)` 在 test 函数中 = 8（数组参数退化为指针）
- `sizeof("Hello")` = 6（字符串字面量包含末尾的 '\0'，共 6 个字符）

### 题 2：整数提升与无符号陷阱

```c
#include <stdio.h>

int main(void)
{
    unsigned int a = 10;
    int b = -20;

    if (a + b > 0) {
        printf("结果 > 0: %u\n", a + b);
    } else {
        printf("结果 <= 0: %d\n", a + b);
    }

    char c = 0x80;     // 假设 char 默认 signed
    unsigned long ul = c;
    printf("ul = %lu\n", ul);

    unsigned char uc = 0x80;
    unsigned long ul2 = uc;
    printf("ul2 = %lu\n", ul2);

    return 0;
}
```

**问题**：这段程序的输出是什么？解释每一行结果的原因。

<details>
<summary>答案</summary>

- `a + b > 0` 打印 "结果 > 0"：因为 `b` 被转换为 `unsigned int`（-20 → 4294967276），`10 + 4294967276 = 4294967286`，为正数。
- `ul = 18446744073709551488`（如果在 64 位系统上）：`char(0x80)` 是 -128，符号扩展为 `unsigned long` 得到一个大数。
- `ul2 = 128`：`unsigned char(0x80)` = 128，零扩展为 `unsigned long` 保持 128。
</details>

### 题 3：浮点数比较

```c
#include <stdio.h>
#include <math.h>

int main(void)
{
    double a = 0.1;
    double b = 0.2;
    double c = a + b;

    printf("c = %.20f\n", c);
    printf("c == 0.3: %d\n", c == 0.3);

    double d = 1.0 / 0.0;
    double e = 0.0 / 0.0;

    printf("d = %f, e = %f\n", d, e);
    printf("d == d: %d, e == e: %d\n", d == d, e == e);

    return 0;
}
```

**问题**：前三行 printf 的输出分别是什么？为什么？

<details>
<summary>答案</summary>

- `c = 0.30000000000000004441`：0.1 和 0.2 都无法精确表示为 IEEE 754 双精度浮点数，相加后产生了微小的误差。
- `c == 0.3: 0`：由于上述精度误差，c 并不精确等于 0.3。
- `d = inf, e = nan`：`1.0/0.0` 产生 INF（无穷大），`0.0/0.0` 产生 NaN（不是数字）。
- `d == d: 1, e == e: 0`：INF 等于自身，但 **NaN 不等于任何值，包括其自身**。
</details>

## 本章总结

1. **类型系统**：C 语言的类型分基本类型（整型、浮点型、字符型、布尔型）、派生类型（指针、数组、结构体等）和 void 类型。
2. **整型大小是平台相关的**：`int` 的大小是实现定义的，典型大小为 4 字节，但不可一概而论。跨平台代码应使用 `<stdint.h>` 中的定宽类型（`int32_t`、`uint64_t` 等）。
3. **char 本质是小整数**：`char` 占用 1 字节，`signed char` 和 `unsigned char` 在类型系统中与 `char` 是不同的类型。char 的默认符号是编译器决定的。
4. **浮点精度**：浮点数无法精确表示所有十进制小数，不能直接用 `==` 比较。应使用 epsilon 方法或 `isnan()/isinf()` 判断特殊值。
5. **sizeof 是编译期运算符**：sizeof(数组) 返回整个数组大小，sizeof(指针) 只返回指针大小。数组作为函数参数退化为指针。
6. **类型转换有陷阱**：隐式转换（整数提升、通常算术转换）和显式转换都可能产生意外结果。有符号/无符号混合是最常见的陷阱，有符号整数溢出是未定义行为。
7. **const 是只读而非常量**：C 中 `const int` 不是编译期常量。`volatile` 禁止编译器优化读写，用于 MMIO 和信号处理。
8. **嵌入式开发的特殊需求**：使用定宽类型保证跨平台一致性，使用 `volatile` 访问硬件寄存器，使用 `const` 将查表数据放在 Flash 中。
