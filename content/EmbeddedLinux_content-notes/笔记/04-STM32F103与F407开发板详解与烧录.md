# STM32F103 与 STM32F407 开发板详解与烧录

## 1. STM32F103 开发板详解

### 1.1 芯片规格概览

STM32F103 是 某微控制器厂商基于 ARM Cortex-M3 内核推出的主流微控制器，属于 STM32 的 **主流系列（Mainstream）**，在工业控制、消费电子、物联网终端等领域应用极为广泛。

| 参数 | 规格 |
|------|------|
| 内核 | ARM Cortex-M3 (ARMv7-M 架构) |
| 主频 | 72MHz（最高） |
| Flash 容量 | 64KB / 128KB（根据型号，如 STM32F103C8T6 为 64KB，STM32F103ZET6 为 512KB） |
| SRAM 容量 | 20KB（C8T6）/ 64KB（ZET6） |
| 工作电压 | 2.0V ~ 3.6V |
| 工作温度 | -40°C ~ +85°C |
| 指令集 | Thumb-2（16/32 位混合指令） |
| 调试接口 | SWD / JTAG |
| 封装 | LQFP48 / LQFP64 / LQFP144 等 |

**Cortex-M3 核心特性：**
- 哈佛架构（指令总线与数据总线分离）
- 单周期乘法、硬件除法
- 嵌套向量中断控制器（NVIC），支持最多 240 个中断
- 3 级流水线 + 分支预测
- 不可屏蔽中断（NMI）
- 位带操作（Bit-Band）：将 1MB 的别名区映射到 1MB 的位带区，实现 GPIO 等寄存器的原子位操作

### 1.2 最小系统板 vs 开发板

**最小系统板（如 STM32F103C8T6 蓝色pill板）：**
- 仅包含芯片、晶振、复位电路、稳压电源、USB-TTL 转换
- 引出所有 GPIO 引脚，尺寸小巧（约 5.3cm x 2.1cm）
- 适合嵌入到最终产品中或作为核心模块
- 价格低廉（约 10-20 元人民币）
- **缺点：** 板载调试器（部分版本需外接 ST-Link），无额外外设

**开发板（如虚拟开发板 Mini、虚拟开发板 Guide）：**
- 在最小系统基础上集成了大量外设：LED、按键、LCD 屏幕接口、传感器模块等
- 板载 USB 转串口、有时板载 ST-Link/V2-1 调试器
- 适合初学者快速上手，无需额外购买烧录器
- 价格相对较高（50-200 元人民币）

### 1.3 板载资源详解

**GPIO（通用输入输出）：**
- F103C8T6 有 37 个 I/O 引脚（PA0-PA15, PB0-PB15, PC13-PC15）
- 每个引脚可配置为：浮空输入、上拉输入、下拉输入、推挽输出、开漏输出、复用推挽输出、复用开漏输出、模拟输入
- 输出速度可配置：2MHz / 10MHz / 50MHz
- 大部分引脚具有 5V 容忍能力（注意查看数据手册标注 FT 引脚）

**USART（通用同步异步收发器）：**
- F103C8T6 有 3 路 USART（USART1 挂载在 APB2，USART2/3 挂载在 APB1）
- USART1 最高波特率 4.5Mbps（APB2 = 72MHz）
- USART2/3 最高波特率 2.25Mbps（APB1 = 36MHz）
- 支持同步模式、智能卡协议、IrDA、LIN、调制解调器流控

**SPI（串行外设接口）：**
- 2 路 SPI，最高速率 18Mbps（主模式）
- 支持 SPI Mode 0/1/2/3
- 支持全双工/半双工/单工通信
- 可用于驱动 LCD、Flash 存储、SD 卡（SPI 模式）等

**I2C（Inter-Integrated Circuit）：**
- 2 路 I2C，支持标准 (100kHz) 和快速 (400kHz) 模式
- 可配置为 7 位或 10 位地址模式
- 支持多主机仲裁
- **注意：** F103 的 I2C 硬件模块存在一些已知 Bug（如总线忙标志异常），社区更推荐 GPIO 模拟 I2C

**ADC（模数转换器）：**
- 2 个 12 位 ADC，最多 10 个外部通道（F103C8T6）
- 转换时间：1us（12 位分辨率时）
- 支持单次、连续、扫描、间断转换模式
- 内置温度传感器（连接到 ADC1 的通道 16）

**TIM（定时器）：**
- 1 个高级定时器 TIM1（16 位，支持 6 步 PWM 输出、刹车功能、互补输出）
- 3 个通用定时器 TIM2/3/4（16 位，支持输入捕获、输出比较、PWM 生成）
- 2 个基本定时器 TIM6/7（16 位，仅用作时基）
- 独立看门狗（IWDG）和窗口看门狗（WWDG）
- 系统滴答定时器 SysTick（24 位递减，用于 OS 心跳）

### 1.4 原理图关键部分解读

对于一个标准的 STM32F103 最小系统板原理图，应重点关注以下几部分：

**电源电路：**
- 输入 VIN（通常 5V）经 AMS1117-3.3 稳压至 3.3V 供芯片使用
- VDD/VSS：芯片工作电源，每个电源对需并联 100nF 去耦电容
- VDDA/VSSA：模拟电源，独立供电以提高 ADC 精度
- VREF+/VREF-：ADC 参考电压（F103C8T6 无独立引脚，内部连接至 VDDA/VSSA）

**时钟电路：**
- HSE（高速外部时钟）：8MHz 晶振 + 两个 20pF 负载电容
- LSE（低速外部时钟）：32.768kHz 晶振（用于 RTC）
- HSI（高速内部时钟）：8MHz RC 振荡器（精度约 ±1%）
- LSI（低速内部时钟）：40kHz RC 振荡器（用于 IWDG）

**复位电路：**
- NRST 引脚经 10kΩ 上拉至 3.3V
- 按键接地，按下时产生低电平复位信号
- 并联 100nF 电容抗干扰

**启动配置：**
- BOOT0 引脚通过 10kΩ 电阻下拉（默认从 Flash 启动）
- BOOT1 引脚通过 10kΩ 电阻下拉
- 当需要 ISP 烧录时，将 BOOT0 拉高（3.3V）

**SWD 调试接口：**
- SWDIO（PA13）：数据线，需 4.7kΩ 上拉
- SWCLK（PA14）：时钟线，需 4.7kΩ 下拉
- 另外接 VCC、GND 和目标板复位信号（可选）

## 2. STM32F407 开发板详解

### 2.1 芯片规格概览

STM32F407 属于 STM32 的 **高性能系列（High Performance）**，基于 ARM Cortex-M4F 内核，相比 F103 在性能和外设上均有大幅提升。

| 参数 | 规格 |
|------|------|
| 内核 | ARM Cortex-M4 + FPU（单精度浮点运算单元） |
| DSP 指令 | 支持 SIMD、饱和运算等 DSP 扩展指令 |
| 主频 | 168MHz（最高） |
| Flash 容量 | 512KB / 1MB（STM32F407VGT6 为 1MB） |
| SRAM 容量 | 192KB（128KB + 64KB） |
| 工作电压 | 1.8V ~ 3.6V |
| 工作温度 | -40°C ~ +105°C |
| 调试接口 | SWD / JTAG |
| 封装 | LQFP100 / LQFP144 / LQFP176 / BGA176 |

### 2.2 相比 F103 的核心升级点

| 维度 | F103 | F407 | 提升说明 |
|------|------|------|----------|
| 内核 | Cortex-M3 | Cortex-M4F | 增加 DSP 指令集和 FPU，运算性能约提升 30-40% |
| 主频 | 72MHz | 168MHz | 频率翻倍以上 |
| Flash | 最大 512KB | 最大 1MB | 容量翻倍 |
| SRAM | 最大 64KB | 192KB (128+64) | 3 倍以上，且包含 64KB CCM（紧耦合内存） |
| ADC | 12位 x 2 | 12位 x 3 | 新增 1 个 ADC；支持差分输入 |
| DAC | 无 | 2 路 12 位 DAC | 新增数模转换功能 |
| TIM | 7 个定时器 | 14 个定时器 | 数量翻倍，新增 2 个 32 位定时器 |
| FSMC | 无 | 有 | 支持扩展外部 SRAM/NOR Flash/NAND Flash/LCD |
| DMA | 2 个控制器 | 2 个控制器 | DMA 请求更多，支持 FIFO 和突发传输 |
| RNG | 无 | 有 | 硬件真随机数发生器 |
| CRC | 无 | 有 | 硬件 CRC 计算单元 |

### 2.3 新增重要外设详解

**USB OTG（On-The-Go）：**
- 支持 USB Host 和 USB Device 双重角色
- F407 有 2 个 USB 接口：USB_OTG_FS（全速）和 USB_OTG_HS（高速，需外接 PHY）
- 支持 HID、MSC、CDC、AUDIO 等 USB 类协议
- 内嵌 DMA 控制器，减少 CPU 开销
- 典型应用：USB 读卡器、USB 声卡、USB 串口（CDC）、连接 U 盘

**DCMI（Digital Camera Interface，数字摄像头接口）：**
- 支持 8/10/12/14 位并行数据输入
- 兼容 CMOS 摄像头传感器（如 OV2640、OV5640）
- 最大像素时钟 48MHz
- 内嵌 FIFO（32 字深度）和 DMA 接口
- 支持黑白/YCbCr/RGB/Bayer 格式
- 在**机器视觉**课程中，F407 + OV2640 摄像头是经典入门组合

**以太网 MAC：**
- 符合 IEEE 802.3-2002 标准
- 支持 10/100Mbps，全双工或半双工
- MII / RMII 接口与外部 PHY 芯片连接（如 LAN8720、DP83848）
- 支持 TCP/IP 硬件校验和计算
- 以太网 DMA 控制器减轻 CPU 负担
- **注意：** 芯片内部仅包含 MAC，需要外接 PHY 芯片才能接入网线
- 在**嵌入式 Linux** 课程中，F407 可用于移植 LwIP 协议栈

**FSMC（Flexible Static Memory Controller）：**
- 支持 NOR Flash、PSRAM、SRAM、NAND Flash、PC Card
- 地址/数据总线宽度可配置（8/16 位）
- LCD 接口模式（8080/6800 时序）
- 常用于连接 TFT-LCD 屏幕（ILI9341/ILI9488 等驱动芯片）

### 2.4 常见开发板资源清单

以 **虚拟实验板 Explorer STM32F407** 开发板为例：

| 资源 | 说明 |
|------|------|
| CPU | STM32F407ZGT6 (Cortex-M4F, 168MHz, 1MB Flash, 192KB SRAM) |
| 外扩 SRAM | 1MB IS62WV51216 |
| 外扩 NAND Flash | 256MB K9F4G08U0A |
| 板载 ST-Link | 通过跳线可选择使用板载或外部调试器 |
| 板载传感器 | MPU6050（六轴姿态传感器）、DHT11（温湿度） |
| 显示接口 | 3.5 寸 TFT-LCD（FSMC 接口，最高 320x480） |
| 摄像头 | FIFO 摄像头接口（DCMI + AL422B FIFO） |
| 音频 | VS1053（MP3 解码）或 WM8978（音频编解码） |
| 网络 | LAN8720A（RMII 接口，10/100M） |
| USB | USB_OTG_FS（Micro-USB 接口） |
| 无线 | ATK-ESP8266 WiFi 模块接口 |

## 3. 两种烧录方式详解

### 3.1 ST-Link 烧录

ST-Link 是 某微控制器厂商推出的调试/烧录工具，是学习和开发 STM32 时**最推荐**的方式。

#### 3.1.1 连接方法（SWD 4线）

SWD（Serial Wire Debug）是 ARM 定义的两线调试接口，相比传统的 JTAG 更节省引脚：

| ST-Link 端 | 目标板 STM32 | 线色（参考） | 功能说明 |
|------------|-------------|-------------|----------|
| SWDIO | PA13 / SWDIO | 黄 | 双向数据线 |
| SWCLK | PA14 / SWCLK | 绿 | 时钟线 |
| VCC (3.3V) | VDD | 红 | 电源输出/输入 |
| GND | GND | 黑 | 共地 |

**连接示意图：**

```
ST-Link V2          STM32 Target
 ┌─────────┐        ┌──────────┐
 │  1. VCC ├────────┤ VDD      │
 │  2. SWDIO├───────┤ PA13     │
 │  3. GND ├────────┤ GND      │
 │  4. SWCLK├───────┤ PA14     │
 │  5. RESET├───────┤ NRST(可选)│
 └─────────┘        └──────────┘
```

**注意事项：**
- ST-Link V2 可通过 VCC 线为目标板供电（最大 300mA），但建议目标板独立供电
- SWDIO 需在目标板上拉 4.7kΩ 至 3.3V，SWCLK 需下拉 4.7kΩ 至 GND
- 连接线长度不宜超过 20cm，否则高速调试时可能出现信号完整性问题
- 部分 ST-Link 克隆版本需要在 SWCLK 上增加串联电阻（约 100Ω）以改善信号质量

#### 3.1.2 驱动安装

**Windows 环境：**

1. **官方驱动（推荐）：** 安装 ST-Link 驱动
   - 访问 ST 官网下载 `ST-Link/V2-1 driver`
   - 或直接安装 Keil MDK，安装过程会自动包含 ST-Link 驱动
   - 手动安装路径：`Keil_v5/ARM/STM32_Programmer/Driver`

2. **Zadig 工具（备选）：**
   - 当 Windows 无法自动识别时，使用 Zadig 工具
   - 选择 ST-Link 设备，安装 WinUSB 驱动
   - 适用于 STM32CubeProgrammer 的场景

3. **验证驱动：**
   - 插入 ST-Link，打开设备管理器
   - 应能看到 `STMicroelectronics STLink dongle` 或类似设备
   - 若显示未知设备或黄色感叹号，需重新安装驱动

**Linux 环境：**

Linux 下 ST-Link 通常无需手动安装驱动，系统自动识别为 USB 设备。

**macOS 环境：**

同样无需额外驱动，插入即可被 OpenOCD 和 STM32CubeProgrammer 识别。

#### 3.1.3 Keil MDK 中配置与烧录步骤

**配置步骤：**

1. 在 Keil 中打开项目
2. 点击工具栏 `Options for Target`（魔术棒图标）或快捷键 `Alt+F7`
3. 切换到 `Debug` 选项卡
4. 选择调试器为 `ST-Link Debugger`
5. 点击 `Settings`，进入 ST-Link 配置界面
6. 在 `Debug` 选项卡中：
   - Port: `SW`（选择 SWD 模式）
   - Max Clock: 建议 4MHz（若连接不稳定可降至 1MHz）
7. 切换到 `Flash Download` 选项卡：
   - 点击 `Add`，选择对应芯片的 Flash 算法（如 `STM32F10x Med Density Flash`）
   - 勾选 `Reset and Run`（烧录完成后自动复位运行）
   - Programming Algorithm：确认 Flash 大小

**烧录步骤：**

1. 编译项目，确认 0 Error, 0 Warning
2. 点击 `Flash` 菜单 → `Download`（或快捷键 F8）
3. 观察输出窗口的烧录进度
4. 成功标志：`Flash Download complete - 0 Errors, 0 Warnings`
5. 若勾选 `Reset and Run`，程序会立即自动运行

**调试模式（配合 Keil）：**

1. 在 `Debug` 选项卡中配置好后，点击 `Start/Stop Debug Session`（Ctrl+F5）
2. 可使用单步执行（F11）、断点（F9）、查看寄存器/变量值
3. 注意：在调试模式下，**TIM 定时器在断点暂停时会继续运行**，这一点与某些其他 MCU 不同

#### 3.1.4 其他 IDE 中的 ST-Link 配置

**IAR EWARM：**
- 配置路径：Project → Options → Debugger → Setup → Driver: ST-Link
- 在 Debugger → Images 中添加 Flash 算法

**STM32CubeIDE（免费）：**
- 基于 Eclipse + GCC，集成了 ST-Link 支持
- 配置自动完成，通常无需手动设置
- 点击绿色向右箭头（Debug/Run）即可烧录

### 3.2 串口 ISP 烧录

ISP（In-System Programming）通过 STM32 内部 ROM 自举程序（Bootloader），利用 USART1 接口完成程序烧录，**无需专用调试器**，只需 USB-TTL 模块。

#### 3.2.1 工作原理

STM32 芯片出厂时在系统存储器（System Memory，位于 0x1FFFxxxx 地址）中预置了一段 Bootloader 代码。当芯片的上电启动模式被配置为从系统存储器启动时，Bootloader 会通过 USART1（F103）/ USART3 或 USB（F407）等待主机发送程序数据，并将数据写入用户 Flash（0x08000000）。

#### 3.2.2 BOOT0 / BOOT1 引脚配置

| BOOT0 | BOOT1 | 启动模式 | 说明 |
|-------|-------|----------|------|
| 0 | X | 主 Flash (0x08000000) | **正常模式**，运行用户程序 |
| 1 | 0 | 系统存储器 (Bootloader) | **ISP 模式**，通过串口/USB 烧录 |
| 1 | 1 | 内置 SRAM (0x20000000) | 调试模式，在 RAM 中运行代码 |

**ISP 烧录操作步骤：**

1. **设置 BOOT 引脚：** BOOT0 接 3.3V (高电平), BOOT1 接 GND (低电平)
2. **连接串口：** USB-TTL 模块的 TXD 接 STM32 的 PA10 (USART1_RX)，RXD 接 PA9 (USART1_TX)，GND 接 GND
3. **给目标板上电**（或按复位键）
4. **打开上位机软件**（FlyMcu、STM32FlashLoader 等），选择正确的串口号
5. **烧录程序：** 选择 .hex 或 .bin 文件，点击开始编程
6. **烧录完成后：** 断开电源，将 BOOT0 跳回 GND（连接到低电平）
7. **重新上电**，程序从 Flash 启动运行

**重要提醒：**
- BOOT 引脚的切换需要**断电**操作（部分板子支持不彻底）
- PA9/PA10 在连接 USB-TTL 时上位机软件需要**交叉连接**：TX→RX, RX→TX
- ISP 烧录只能烧录程序到 Flash，**不能用于在线调试和单步执行**

#### 3.2.3 FlyMcu 软件使用详解

FlyMcu 是国内最常用的 STM32 ISP 烧录工具，由武汉飞梦科技开发。

**基本设置：**
- **串口选择：** 选择 USB-TTL 对应的 COM 口（如 COM3）
- **波特率：** 通常选择 115200 或 460800（高速烧录）
- **校验方式：** 建议勾选校验
- **编程后执行：** 烧录完成后自动运行程序
- **选项字节区：** 一般不勾选，除非需要配置读保护

**烧录流程：**

1. 选择要烧录的 .hex 文件（Keil 生成的 .hex 位于 `Objects/` 或 `Listings/` 目录）
2. 点击 `开始编程`
3. 观察进度：检测芯片 → 擦除 → 编程 → 校验
4. 完成提示后，切换 BOOT0 到低电平并按复位

**高级功能：**
- **读写芯片唯一 ID：** 通过 FlyMcu 可读取 STM32 的 96 位唯一 ID
- **选项字节配置：** 设置读保护级别 RDP（Level 0/1/2）、看门狗硬件/软件模式等
- **Flash 读出：** 可回读 Flash 内容（若未设置读保护），保存为 .bin 文件

#### 3.2.4 ISP 烧录的适用场景

| 场景 | 适用性 | 说明 |
|------|--------|------|
| 没有调试器 | 最佳选择 | 只需 10 元的 USB-TTL 模块即可 |
| 量产烧录 | 推荐 | 可配合自动化治具批量烧录 |
| 第一次学习 | 推荐 | 成本最低的入门方式 |
| 在线调试 | 不支持 | ISP 无法进行断点调试 |
| 快速迭代开发 | 不推荐 | 每次需手动切换 BOOT 引脚 |
| 芯片锁死恢复 | 推荐 | 通过 ISP 擦除 Flash 可解除误锁 |

### 3.3 J-Link 烧录

J-Link 是 Segger 公司推出的 ARM 调试工具，功能比 ST-Link 更强大。

#### 3.3.1 相比 ST-Link 的优势

| 对比维度 | ST-Link V2 | J-Link EDU (教育版) | J-Link Pro (专业版) |
|----------|-----------|-------------------|-------------------|
| 调试速度 | 最高 4MHz SWCLK | 最高 12MHz SWCLK | 最高 50MHz SWCLK |
| 软件支持 | Keil, IAR, STM32CubeIDE | Keil, IAR, Ozone, VS Code 全系列 | 同上 |
| 虚拟串口 (VCOM) | ST-Link V2-1 支持 | 部分型号支持 | 支持 |
| RTT 调试 | 不支持 | 支持（高速日志输出） | 支持 |
| 性能分析 | 不支持 | 支持（函数性能分析） | 支持 |
| 价格 | 约 30-80 元 | 约 300-600 元 | 约 2000-6000 元 |
| 开源/第三方支持 | 广泛（OpenOCD, st-flash） | 广泛 | 广泛 |

**RTT（Real-Time Transfer）技术：**
- Segger 的独有技术，通过 SWD 接口实现高速双向数据传输
- 用于 printf 调试日志输出，速度比 UART 串口快数十倍
- 不占用额外引脚，不影响实时性
- 需要 J-Link + Segger RTT Viewer 软件配合使用

#### 3.3.2 连接方式

J-Link 使用 20-pin 标准 JTAG/SWD 接口（Cortex Debug Connector）：

| J-Link 引脚 | 信号 | STM32 引脚 | 说明 |
|-------------|------|-----------|------|
| 1 | VREF | VDD | 参考电压，连接目标板 VDD |
| 4 | GND | GND | 共地 |
| 7 | SWDIO | PA13 | SWD 数据线 |
| 9 | SWCLK | PA14 | SWD 时钟线 |
| 15 | RESET | NRST | 复位信号（可选） |
| 19 | VCC(5V) | VIN | 供电（可选） |

**注：** J-Link 使用 SWD 模式时，仅需连接引脚 1(VREF)、4(GND)、7(SWDIO)、9(SWCLK) 即可，与 ST-Link 兼容。

#### 3.3.3 在 Keil 中配置 J-Link

1. 打开 `Options for Target` → `Debug` 选项卡
2. 选择 `J-LINK / J-Trace Cortex`
3. 点击 `Settings`
4. Port：选择 SW（SWD 模式）
5. Max Clock：可选择更高速度（如 10MHz），前提是连接稳定
6. 切换到 `Flash Download`，选择对应 Flash 算法

#### 3.3.4 J-Link Commander 命令行工具

J-Link 提供强大的命令行工具 J-Link Commander，可用于自动化烧录：

```bash
# 连接 J-Link 并连接目标芯片
JLinkExe -device STM32F103C8 -if SWD -speed 4000 -autoconnect 1

# 在 JLink 命令行中执行操作
# 加载程序到 Flash
loadfile ./build/firmware.hex

# 加载并运行
loadfile ./build/firmware.hex
g

# 退出
exit
```

## 4. Ubuntu 下的烧录方案

在 Ubuntu（或其他 Linux 发行版）下无法使用 Keil 和 ST-Link Utility 等 Windows 专用工具，但 Linux 提供了更灵活的开源替代方案，适合嵌入式开发流水线集成。

### 4.1 OpenOCD + ST-Link（推荐方案）

OpenOCD（Open On-Chip Debugger）是嵌入式领域最常用的开源调试烧录软件，支持 ST-Link、J-Link 等多种调试器。

#### 4.1.1 OpenOCD 安装

```bash
# Ubuntu 20.04/22.04 apt 直接安装
sudo apt update
sudo apt install openocd

# 或从源码编译最新版本
git clone https://example.com/debug-tools/openocd.git
cd openocd
./bootstrap
./configure --enable-stlink
make -j$(nproc)
sudo make install
```

#### 4.1.2 烧录命令

```bash
# STM32F103C8T6 烧录示例（板载 ST-Link）
openocd -f interface/stlink.cfg \
        -f target/stm32f1x.cfg \
        -c "program firmware.elf verify reset exit"

# STM32F407VGT6 烧录示例
openocd -f interface/stlink.cfg \
        -f target/stm32f4x.cfg \
        -c "program firmware.elf verify reset exit"

# 烧录 .hex 文件
openocd -f interface/stlink.cfg \
        -f target/stm32f1x.cfg \
        -c "program firmware.hex verify reset exit"

# 烧录 .bin 文件（需要指定起始地址）
openocd -f interface/stlink.cfg \
        -f target/stm32f1x.cfg \
        -c "program firmware.bin 0x08000000 verify reset exit"
```

#### 4.1.3 交互式调试

```bash
# 启动 OpenOCD 后台服务
openocd -f interface/stlink.cfg -f target/stm32f1x.cfg &

# 使用 telnet 或 GDB 连接
telnet localhost 4444

# 在 telnet 会话中执行命令
> halt           # 停止目标 CPU
> flash banks    # 查看 Flash bank 信息
> stm32f1x mass_erase 0  # 整片擦除（F1）
> reset          # 复位目标
> exit           # 退出

# 使用 GDB 调试
arm-none-eabi-gdb firmware.elf
(gdb) target remote localhost:3333
(gdb) load
(gdb) continue
```

**配置文件说明：**
- `/usr/local/share/openocd/scripts/interface/`：存放调试接口配置
- `/usr/local/share/openocd/scripts/target/`：存放目标芯片配置
- 自定义配置时，可创建 `.cfg` 文件并引用标准配置

### 4.2 st-flash（ST-Link 命令行工具）

st-flash 是开源项目 **stlink** 提供的命令行烧录工具，操作比 OpenOCD 更简单直接。

#### 4.2.1 安装

```bash
# 从源码编译安装
sudo apt install build-essential cmake libusb-1.0-0-dev
git clone https://example.com/debug-tools/stlink.git
cd stlink
cmake -S . -B build
cmake --build build
cd build && make install

# 设置 udev 规则（使非 root 用户可访问 ST-Link）
sudo cp /usr/local/share/stlink/49-stlinkv*.rules /etc/udev/rules.d/
sudo udevadm control --reload
sudo udevadm trigger
```

#### 4.2.2 使用命令

```bash
# 查看是否检测到 ST-Link 设备
st-info --probe

# 擦除整个 Flash
st-flash erase

# 烧录 .bin 文件（从 0x08000000 开始）
st-flash write firmware.bin 0x08000000

# 烧录 .hex 文件（st-flash 不直接支持 hex，需先转换）
arm-none-eabi-objcopy -O binary firmware.elf firmware.bin
st-flash write firmware.bin 0x08000000

# 读取 Flash 内容并保存
st-flash read dump.bin 0x08000000 0x10000

# 复位运行
st-flash reset
```

**st-flash 与 OpenOCD 的对比：**

| 维度 | st-flash | OpenOCD |
|------|----------|---------|
| 使用复杂度 | 低，单一命令 | 中，需要配置文件和参数 |
| 灵活性 | 较低（仅烧录功能） | 高（调试 + 烧录 + GDB server） |
| 支持的调试器 | 仅 ST-Link | ST-Link, J-Link, FT2232 等 |
| 烧录速度 | 相当 | 相当 |
| 调试功能 | 不支持 | 完整支持 |
| 错误提示 | 较简单 | 详细丰富 |
| 适用场景 | 学生快速烧录、CI 集成 | 专业开发、调试场景 |

### 4.3 STM32CubeProgrammer（ST 官方跨平台工具）

ST 官方提供的跨平台烧录/编程工具，同时支持 Windows/Linux/macOS，GUI 和 CLI 两种模式。

#### 4.3.3 GUI 模式使用

GUI 界面操作流程：
1. 连接方式选择：ST-Link 或 UART

**STM32CubeProgrammer 的独特优势：**

## 6. 常见问题排查

### 6.1 无法连接调试器

**现象：** Keil/OpenOCD 报错 "Cannot connect to target" 或 "No target connected"

**排查步骤：**

| 步骤 | 检查项 | 解决方法 |
|------|--------|---------|
| 1 | 供电 | 测量 STM32 VDD 引脚电压是否为 3.3V ± 0.1V |
| 2 | 共地 | 确认调试器 GND 与目标板 GND 已连接 |
| 3 | 接线是否正确 | SWDIO → PA13, SWCLK → PA14；检查是否有虚焊 |
| 4 | 复位引脚 | NRST 是否被异常拉低？是否有 10kΩ 上拉到 3.3V |
| 5 | Boot 引脚 | BOOT0 是否接 GND？（若接 3.3V 则从系统存储器启动，Flash 不可访问） |
| 6 | 驱动程序 | 设备管理器是否识别？重新安装驱动或更换 USB 端口 |
| 7 | SWD 引脚被复用 | 是否代码中将 PA13/PA14 配置为 GPIO？按住复位键的同时点击下载，松开复位 |
| 8 | 芯片损坏 | 检查芯片是否发烫，有无短路 |

**OpenOCD 特定检查：**

```bash
# 检查 USB 设备是否被识别
lsusb | grep -i stlink
# 输出示例：Bus 001 Device 003: ID 0483:3748 STMicroelectronics ST-LINK/V2

# 检查 udev 规则是否正确设置
dmesg | grep -i stlink
# 若无法识别，需添加 udev 规则
```

### 6.2 烧录失败

**现象 1：烧录过程中断，提示 Flash 擦除/写入失败**

可能原因：
- **Flash 读保护已启用（RDP Level 1/2）：** 需要使用 ISP 或 STM32CubeProgrammer 解除保护
- **Flash 算法不对：** Keil 中选择了错误的 Flash 算法（例如 C8T6 选成了 ZET6 的算法）
- **供电不稳定：** 烧录时电流需求较大，USB 供电不足可用外部 5V 适配器
- **时钟配置错误：** 芯片 HSE 晶振故障导致 PLL 锁定失败，芯片无法以正确频率工作

```bash
# 通过 OpenOCD 强制执行完全擦除
openocd -f interface/stlink.cfg -f target/stm32f1x.cfg \
        -c "init" -c "reset halt" \
        -c "stm32f1x mass_erase 0" \
        -c "exit"
```

**现象 2：烧录成功但程序不运行**

- 未勾选 `Reset and Run`：烧录后目标芯片仍处于调试停止状态，需手动按复位键
- 程序跑飞：检查中断向量表是否链接正确（起始地址 0x08000000）
- BOOT0 引脚未拉低：芯片仍从系统存储器启动
- HSE 晶振不起振：检查晶振及负载电容是否焊接正确，或改用 HSI 内部时钟调试

### 6.3 芯片锁死（Read Protection Lock）

**现象：** 烧录时提示 "Flash Timeout" 或 "Device is secured"，无法连接调试器

**原因：**
- 误操作设置了 Flash 读保护 RDP Level 1（调用 `FLASH_OB_RDPConfig(OB_RDP_Level_1)`)
- 更严重：设置了 Level 2（不可逆，芯片永久锁死，只能更换）

**解决方法（Level 1 可逆）：**

```bash
# 方法一：STM32CubeProgrammer（推荐）
STM32_Programmer_CLI -c port=SWD -ob RDP=0xAA -v
# 选项字节 RDP=0xAA 表示 Level 0（无保护）
# 注意：解除保护将自动擦除整个 Flash

# 方法二：OpenOCD
openocd -f interface/stlink.cfg -f target/stm32f1x.cfg \
        -c "init" -c "reset halt" \
        -c "stm32f1x unlock 0" \
        -c "exit"

# 方法三：FlyMcu（串口 ISP）
# 1. 切换到 ISP 启动模式（BOOT0=1, BOOT1=0）
# 2. 打开 FlyMcu，勾选"选项字节"中的"解除读保护"
# 3. 点击开始编程
```

**预防措施：**
- 在调试阶段，不要调用 `FLASH_OB_RDPConfig()` 函数
- 量产时如果需要读保护，先在测试板上验证
- 设置读保护前，确保已备份程序

### 6.4 串口 ISP 无法连接

**现象：** FlyMcu 显示 "连接失败" 或 "芯片无应答"

| 故障原因 | 解决方法 |
|---------|---------|
| BOOT0 未接高 | 将 BOOT0 接 3.3V，然后按复位键 |
| TX/RX 交叉错误 | USB-TTL 的 TX 接 STM32 的 RX (PA10)，RX 接 TX (PA9) |
| 波特率过高 | 降低波特率至 9600 或 14400 尝试 |
| 串口号错误 | 打开设备管理器确认 USB-TTL 的 COM 端口号 |
| USB-TTL 驱动未装 | CH340/CP2102 芯片需安装对应驱动 |
| 上电时序 | 先设好 BOOT，**再上电**（或按复位键） |
| 时钟故障 | HSI 损坏？尝试改用 STM32FlashLoader Demo（低波特率） |

### 6.5 OpenOCD 常见错误

```bash
# 错误：unable to find a matching CMSIS-DAP device
# 解决：检查 USB 连接，确认 ST-Link 被识别

# 错误：Error: timed out while waiting for target halted
# 解决：目标芯片已死锁或 SWD 连接不良，检查接线，尝试降低 SWD 速度

# 错误：Error: init mode failed (unable to connect to the target)
# 解决：检查供电，按住复位在 init 过程中尝试，必要时使用硬件复位

# 添加 --debug 参数查看详细信息
openocd -d3 -f interface/stlink.cfg -f target/stm32f1x.cfg
```

### 6.6 其他常见问题

**Q：SWD 接线很短但还是连接不稳定？**
- 尝试降低 SWD 时钟频率（在 OpenOCD 配置中添加 `adapter speed 1000` 即 1MHz）
- 在 SWCLK 和 SWDIO 上分别加 4.7kΩ 上拉/下拉电阻
- 检查目标板电源纹波，加大去耦电容

**Q：Keil 编译通过但烧录提示 "No Algorithm found"？**
- 在 Flash Download 选项卡中未添加编程算法
- 或者选择了错误的芯片型号（F103C8 选了 F103RC）

**Q：芯片发烫？**
- 立即断电！可能是 3.3V 和 GND 短路，或电源极性接反
- 检查 GPIO 引脚是否直接连接 5V 电平（非 5V 容忍引脚）
- 测量 VDD 对地电阻，排除短路

**Q：代码在调试模式下正常运行，但独立运行不工作？**
- 可能原因：调试器在后台初始化了某些外设
- 检查代码中是否有未初始化的变量被使用
- 确认 SystemInit() 函数正确配置了系统时钟

**Q：芯片 Flash 烧录到一半卡死，之后再也无法烧录？**
- 可能 Flash 处于未完全擦除状态或保护状态
- 使用串口 ISP 全片擦除后再试
- 作为最后手段，使用 `stm32f1x mass_erase` 命令通过 OpenOCD 强制擦除
