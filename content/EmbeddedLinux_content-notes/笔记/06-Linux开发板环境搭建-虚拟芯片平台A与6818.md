# Linux 开发板环境搭建——虚拟芯片平台A与 6818

---

## 1. 嵌入式 Linux 开发板概述

### 1.1 什么是 Linux 开发板

**嵌入式 Linux 开发板**是一块集成了处理器（SoC）、内存、存储和外设接口的电路板，能够运行完整的 Linux 操作系统。它与我们熟悉的 STM32 单片机开发板有本质区别：

| 对比维度 | STM32 单片机 | Linux 开发板 |
|---------|-------------|-------------|
| 操作系统 | 裸机或 RTOS（FreeRTOS、RT-Thread） | 完整的 Linux 内核 + 用户空间 |
| CPU 架构 | Cortex-M 系列（M0 / M3 / M4 / M7） | Cortex-A 系列（A7 / A53 / A72 / A76） |
| 主频 | 几十 MHz ~ 几百 MHz | 1.0 GHz ~ 2.4 GHz |
| 内存 | 几十 KB ~ 几 MB（片上 SRAM / SDRAM） | 1 GB ~ 32 GB（DDR4 / LPDDR4） |
| 存储 | 内部 Flash（几百 KB ~ 几 MB） | 外部 eMMC / SD 卡 / NVMe（几 GB ~ 几百 GB） |
| MMU | 无（Cortex-M 无 MMU） | 有（必需，用于 Linux 虚拟内存管理） |
| 外设驱动 | 裸机寄存器编程 / HAL 库 | Linux 内核驱动框架（platform bus、设备树） |
| 开发方式 | Keil / IAR / STM32CubeIDE | 交叉编译工具链 + SDK + 命令行 |
| 调试手段 | J-Link / ST-Link + IDE 单步调试 | 串口打印 + 内核日志（dmesg）+ GDB 远程调试 |
| 多任务 | 中断 + 调度器（协作式/抢占式） | 内核完整进程调度 + 线程管理 |
| 网络协议栈 | LwIP（轻量级 TCP/IP） | 完整 Linux 网络栈（TCP/IP + Netfilter + Socket） |

简单来说：**单片机适合对实时性要求高、任务简单的场景；Linux 开发板适合需要复杂软件栈、多进程、图形界面、网络通信的场景。**

### 1.2 典型应用场景

- **智能家居网关**：连接多种通信协议（Wi-Fi / Zigbee / BLE），运行 Web 服务器提供控制面板
- **边缘计算节点**：AI 推理（NPU 加速）、视频流分析、工业数据采集与预处理
- **人机交互界面**：QT / LVGL 图形界面，触摸屏交互，多语言支持
- **网络设备**：路由器、NAS 存储服务器、VPN 网关
- **工业控制**：PLC 控制器、数据采集器、协议转换器（Modbus / CAN / Ethernet/IP）
- **教育与教学**：嵌入式 Linux 驱动开发、系统移植、BSP 开发的教学平台

## 2. 虚拟芯片平台 A（ChipLab-A）开发板

### 2.1 平台背景

虚拟芯片公司甲（ChipLab-A）成立于 2001 年，是国内领先的 Fabless 芯片设计公司。其 SoC 广泛应用于平板电脑、电视盒子、AI 边缘计算、门禁安防、商业显示等领域。ChipLab-A 在开源社区（Linux Kernel 主线、U-Boot）的支持度一直较高，官方提供完善的 BSP 和 SDK。

### 2.2 常见型号及规格

| 芯片型号 | 架构 | CPU | GPU | NPU | 典型频率 | 应用领域 |
|---------|------|-----|-----|-----|---------|---------|
| **PA3588** | Cortex-A76 x4 + A55 x4 | 八核（4大+4小） | Mali-G610 MC4 | 6 TOPS | 2.4 GHz / 1.8 GHz | AI 边缘计算、高端平板、NVR、智能座舱 |
| **PA3568** | Cortex-A55 x4 | 四核 | Mali-G52 EE | 0.8 TOPS | 2.0 GHz | 工业平板、多媒体终端、边缘网关 |
| **PA3399** | Cortex-A72 x2 + A53 x4 | 六核（2大+4小） | Mali-T860 MP4 | 无 | 2.0 GHz / 1.5 GHz | 开发板标杆、Chromebook、商业显示 |
| **PA3328** | Cortex-A53 x4 | 四核 | Mali-450 MP2 | 无 | 1.5 GHz | 电视盒子、低成本方案 |
| **PA3288** | Cortex-A17 x4 | 四核 | Mali-T760 MP4 | 无 | 1.8 GHz | 经典方案、互动广告机 |

### 2.3 PA3588 深度解读

PA3588 是虚拟芯片平台A 2022 年推出的旗舰级 SoC，采用 **8nm 制程**，主要特性包括：

- **CPU**：4 x Cortex-A76（2.4 GHz）+ 4 x Cortex-A55（1.8 GHz），大小核架构（DSU），性能可达 100K+ DMIPS
- **GPU**：Mali-G610 MP4，支持 OpenGL ES 3.2、Vulkan 1.2、OpenCL 2.2
- **NPU**：6 TOPS 算力（INT8），支持 TensorFlow / Caffe / ONNX / PyTorch 模型转换
- **VPU**：8K@60fps 解码（H.265/H.264/VP9），8K@30fps 编码
- **内存**：LPDDR4/LPDDR4x/LPDDR5，最高 32 GB
- **显示**：支持三屏异显（HDMI 2.1 + DP 1.4 + eDP 1.3 + MIPI DSI）
- **接口**：PCIe 3.0 x4、SATA 3.0 x3、USB 3.1 Gen2、Gigabit Ethernet x2、CAN-FD

### 2.5 适用项目类型

- **AI 视觉终端**：人脸识别门禁、车牌识别、客流统计（PA3588 NPU）
- **视频处理**：8K 播放器、视频采集编码器、直播推流设备
- **工业 HMI**：人机交互触摸屏、数控机床控制面板（PA3568）
- **边缘服务器**：多路 RTSP 流分析、协议转换、数据清洗上云
- **教育机器人**：SLAM 导航、视觉抓取、语音交互

## 3. 6818 开发板（SocPlatform-B VP6818）

### 3.1 SocPlatform-B VP6818 芯片简介

**VP6818** 是SocPlatform-B（芯片平台 B）推出的一款八核 Cortex-A53 应用处理器，最早应用于 Chromebook 等消费产品，后因其良好的性能和较低的成本，被国内大量培训机构（如虚拟培训机构甲、虚拟开发板厂商甲、虚拟开发板厂商乙、虚拟硬件机构丙）选为嵌入式 Linux 教学平台。

### 3.2 核心规格

| 参数 | 规格 |
|-----|------|
| CPU | ARM Cortex-A53 x8（八核，ARMv8-A 架构） |
| 主频 | 1.4 GHz（最高可配置至 2.0 GHz） |
| GPU | Mali-400 MP4（支持 OpenGL ES 2.0） |
| 制程 | 28nm HKMG |
| 内存控制器 | DDR3 / DDR3L / LPDDR3，双通道 32-bit，最高 800 MHz |
| 视频解码 | 1080p@60fps H.264 / MPEG-4 |
| 视频编码 | 1080p@30fps H.264 |
| 典型功耗 | ~2 W（full load） |
| 工作温度 | -25℃ ~ 85℃（工业级） |

### 3.3 6818 开发板板载资源

以虚拟培训机构甲 FS6818 和虚拟硬件机构丙 CompactPi M3 为例，典型板载资源包括：

- **处理器**：芯片平台 B VP6818，八核 Cortex-A53 @ 1.4 GHz
- **内存**：1 GB / 2 GB DDR3（视版本而定）
- **存储**：8 GB / 16 GB eMMC + Micro SD 卡槽
- **显示接口**：HDMI 输出、MIPI DSI（4-lane）、RGB LCD 接口（40-pin FPC）
- **触摸接口**：I2C 电容触摸 / 电阻触摸
- **网络**：10/100/1000M Ethernet（RTL8211E 千兆 PHY）
- **无线通信**：AP6212（Wi-Fi 802.11 b/g/n + Bluetooth 4.0，部分型号可选）
- **USB**：USB 2.0 Host x4 + USB OTG (Micro USB)
- **串口**：2路 UART（其中一路通过 3.3V 电平 4-pin 引出用作调试串口）
- **音频**：3.5mm 耳机接口 + 板载麦克风（WM8960 音频 Codec）
- **摄像头**：DVP 摄像头接口（OV5640 等）
- **GPIO 扩展**：40-pin 2.54mm 排针（兼容 通用 40-pin 引脚顺序），包含 SPI、I2C、UART、PWM、ADC
- **常见板型**：FS6818（虚拟培训机构甲）、CompactPi M3 / M3B（虚拟硬件机构丙）、iTop-6818（虚拟开发板厂商丁）

### 3.4 教育领域应用

6818 在国内嵌入式培训中占据重要地位，主要原因：

1. **成本低**：整套开发板 + 屏幕 + 配件约 400~800 元
2. **资料全**：培训机构提供完整的教学视频、课件、实验代码、SDK
3. **难度适中**：Cortex-A53 架构文档丰富，Linux 内核移植难度低于最新芯片
4. **实验丰富**：LED 驱动、按键中断、LCD 显示、摄像头采集、网络通信等实验一应俱全
5. **就业导向**：掌握 6818 开发板移植流程后，可快速迁移到 PA3568、PA3588 等更先进的平台

> **注意**：6818 的官方主线内核（Mainline Linux）支持度不如 ChipLab-A，因此更多依赖于芯片平台 B 原厂 BSP 或培训机构提供的自定义内核（通常基于 Linux 4.4 / 5.10）。

## 4. 开发板启动流程

**启动流程**是嵌入式 Linux 开发的核心知识点。从按下电源到系统登录，完整启动链如下：

```
电源上电
    │
    ▼
BootROM（片内 ROM）
    │ 加载第一级引导程序
    ▼
U-Boot SPL / BL1（二级引导）
    │ 初始化 DDR、时钟、存储控制器
    ▼
U-Boot（完整引导程序）
    │ 加载内核和设备树到内存
    ▼
Linux Kernel
    │ 解压、初始化各子系统、挂载根文件系统
    ▼
Rootfs（根文件系统）
    │ 执行 init 程序（/sbin/init）
    ▼
用户空间（shell / GUI / application）
```

### 4.1 BootROM（片内 ROM）

- 固化在 SoC 芯片内部的只读存储器
- 由芯片设计厂（ChipLab-A / 芯片平台 B）写入，用户无法修改
- 上电后 CPU 首先执行 BootROM 中的代码
- 主要任务：
  - 初始化最基本的硬件（时钟、看门狗）
  - 检测启动媒体优先级（eMMC → SD 卡 → USB OTG → 串口）
  - 从选定的启动媒体加载 **SPL（Secondary Program Loader）** 到 SRAM 中

### 4.2 U-Boot（Universal Bootloader）

**U-Boot** 是嵌入式 Linux 中最常用的开源引导程序。分为两个阶段运行：

**第一阶段 —— SPL（Secondary Program Loader）：**
- 由 BootROM 加载到内部 SRAM（通常只有 32 KB ~ 192 KB）
- 初始化 DDR 控制器、时钟 PLL、存储控制器
- 从存储设备加载完整的 U-Boot（u-boot-dtb.img）到 DDR

**第二阶段 —— 完整的 U-Boot：**
- 运行在 DDR 中，功能丰富，提供命令行交互
- 主要任务：
  - 初始化网络、USB、MMC、显示等外设
  - 读取环境变量（保存在 eMMC / SD 卡特定分区）
  - 通过 `bootcmd` 命令加载 Linux 内核（zImage / Image）和设备树（.dtb）
  - 传递启动参数给内核（通过 bootargs 环境变量）
  - 跳转到内核入口地址

常见 U-Boot 命令：

```bash
# 查看环境变量
printenv

# 设置 bootargs（传递给内核的参数）
setenv bootargs 'console=ttySAC2,115200 root=/dev/mmcblk0p2 rootwait rw'

# 通过网络加载内核
tftp 0x40008000 zImage
tftp 0x43000000 exynos6818.dtb

# 启动内核
bootz 0x40008000 - 0x43000000
```

### 4.3 Linux Kernel

- 内核从 U-Boot 加载到 DDR 指定地址（通常为 0x40008000 / 0x80080000）
- 如果内核是压缩格式（zImage），先解压，后执行
- 内核初始化流程：
  1. **架构相关初始化**（`start_kernel`）：setup_arch、trap_init、mm_init
  2. **设备模型初始化**：platform bus、驱动注册 probe
  3. **调度器初始化**：sched_init
  4. **内存管理初始化**：page_alloc、slab
  5. **中断控制器初始化**：GIC（Generic Interrupt Controller）
  6. **时钟与定时器初始化**：clk、timer
  7. **控制台初始化**：printk 开始输出日志
  8. **根文件系统挂载**：根据 bootargs 中的 `root=` 参数挂载根fs
  9. **启动 init 进程**：执行 `/sbin/init`

通过内核日志命令查看启动过程：

```bash
# 在开发板上查看内核启动日志
dmesg | less

# 或者通过串口直接观察启动时内核打印
```

### 4.4 Rootfs（根文件系统）

- 内核完成初始化后，根据 `bootargs` 挂载根文件系统
- 根文件系统中必须包含：`/sbin/init`（或内核指定的 init）、`/dev`、`/proc`、`/sys`、基本 shell 工具
- 早期使用 BusyBox + 手工构建的根文件系统
- 现代嵌入式系统多使用 Ubuntu Base、Buildroot、Yocto 构建

### 4.5 启动流程图

```
[电源上电]
    │
    ▼
[时钟 & 复位控制]
    │
    ▼
[BootROM] ──→ 检测启动引脚电平 ──→ USB OTG 下载模式（烧录模式）
    │
    ▼
[从存储读取 SPL] ←── SD/eMMC/NAND 的起始扇区（MBR/GPT）
    │
    ▼
[SPL] ──→ 初始化 DDR & 时钟
    │
    ▼
[从存储读取 U-Boot] ←── bootloader 分区
    │
    ▼
[U-Boot] ──→ 初始化外设、读环境变量、启动倒计时
    │                   │               │
    │         按任意键进入命令行     自动执行 bootcmd
    │                                      │
    ▼                                      ▼
[tftp / SD / eMMC 加载]           [加载 kernel + dtb 到 DDR]
                                                │
                                                ▼
                                        [跳转到内核入口]
                                                │
                                                ▼
                                        [Linux 内核启动]
                                                │
                                                ▼
                                        [挂载 Rootfs]
                                                │
                                                ▼
                                        [/sbin/init 启动用户空间]
```

## 5. SDK 获取与编译环境搭建

### 5.1 什么是 SDK

嵌入式 Linux SDK（Software Development Kit）通常包括：

- **交叉编译工具链**（Cross Toolchain）：aarch64-linux-gnu-gcc / arm-linux-gnueabihf-gcc
- **U-Boot 源码**
- **Linux 内核源码**
- **根文件系统构建脚本**（Buildroot / Yocto）
- **设备树源文件（.dts）**
- **分区表配置与烧录工具**
- **示例代码和文档**

### 5.2 ChipLab-A SDK 获取

ChipLab-A 提供官方 SDK 并通过多个渠道分发：

#### 虚拟平台 SDK（代码仓库）

ChipLab-A 在示例代码仓库维护了 Linux 内核和 U-Boot 的仓库：

```bash
# 平台 Linux 内核（含 ChipLab-A 平台代码）
git clone https://example.com/chiplab-a/kernel.git -b develop-5.10

# 平台 U-Boot
git clone https://example.com/chiplab-a/u-boot.git -b develop-4.19
```

#### DevKit-A 开源社区

DevKit-A 提供完整的 AIOC（Android Isolated OS Companion）SDK：

```bash
# 下载 DevKit-A SDK（含全部源码包）
wget https://example.com/devkit-a/linux-sdk/pa3588_linux_sdk_v1.0.0.tar.gz
tar xzf pa3588_linux_sdk_v1.0.0.tar.gz
cd pa3588_linux_sdk_v1.0.0
ls -la
```

#### DevKit-B / BoardVendor-B / 虚拟硬件机构丙

各厂商同样提供针对自家开发板的 SDK：

| 厂商 | 资源地址 | 说明 |
|------|---------|------|
| **DevKit-B** | https://example.com/devkit-b/download/ | PA3588S / PA3566 |
| **BoardVendor-B** | https://example.com/boardvendor-b/download/ | DevBoard-5B / Zero 2 |
| **虚拟硬件机构丙** | https://example.com/virtual-board/wiki/ | CompactPC T6 / CompactPi |
| **BoardVendor-C** | https://example.com/boardvendor-c/ | PA3588 板卡 |

### 7.3 设备树（Device Tree）概念

**设备树**是一种描述硬件资源的数据结构，解决早期 Linux 内核中大量硬件信息硬编码（board file）的问题。

#### 为什么需要设备树？

在 Linux 2.6 ~ 3.x 时代，每个板子都需要在 `arch/arm/mach-xxx/` 下写一个 board 文件，其中包含所有硬件信息。这导致：

- 同一 SoC 的不同板子需要重复编写代码
- 内核主线难以维护
- 更换外设需要重新编译内核

设备树将硬件描述与内核驱动分离，**一个内核映像可以适配多种硬件配置**。

#### 设备树基本语法

设备树源文件（.dts）会被编译为设备树二进制（.dtb），由 U-Boot 传递给内核。

```dts
// vp6818.dts（简化示例）
/dts-v1/;

#include "vp6818.dtsi"   // SoC 级共用定义

/ {
    model = "FS6818 Board";
    compatible = "vendorb,vp6818", "vendorb,vp6818";

    chosen {
        stdout-path = &uart2;
    };

    memory@40000000 {
        device_type = "memory";
        reg = <0x40000000 0x80000000>;  // 2GB DDR：起始地址 0x40000000，大小 2GB
    };

    leds {
        compatible = "gpio-leds";
        led1 {
            label = "heartbeat";
            gpios = <&gpioc 7 GPIO_ACTIVE_LOW>;
            linux,default-trigger = "heartbeat";
        };
        led2 {
            label = "user-led";
            gpios = <&gpioc 8 GPIO_ACTIVE_LOW>;
            default-state = "off";
        };
    };

    &uart2 {
        status = "okay";
        clock-frequency = <100000000>;
    };

    &mmc0 {
        status = "okay";
        bus-width = <4>;
        cap-sd-highspeed;
        sd-uhs-sdr50;
    };

    &i2c0 {
        status = "okay";
        clock-frequency = <100000>;

        eeprom@50 {
            compatible = "atmel,24c02";
            reg = <0x50>;
            pagesize = <8>;
        };
    };
};
```

#### 设备树关键语法

| 语法元素 | 说明 | 示例 |
|---------|------|------|
| `/dts-v1/;` | DTS 文件版本标识 | |
| `/ { }` | 根节点 | `/ { model = "xxx"; };` |
| `node-name@address` | 节点名称 + 寄存器地址 | `uart2@c00a0000` |
| `compatible` | 驱动匹配字符串（最重要） | `"vendorb,vp6818-uart"` |
| `reg` | 寄存器地址范围 | `<0xc00a0000 0x100>` |
| `interrupts` | 中断号 | `<GIC_SPI 30 IRQ_TYPE_LEVEL_HIGH>` |
| `clocks` | 时钟引用 | `<&clk CLK_UART2>` |
| `status` | 设备启用状态 | `"okay"` / `"disabled"` |
| `&label` | 引用其他节点进行覆盖 | `&uart2 { status = "okay"; };` |
| `#include` | 包含其他 dts/dtsi 文件 | `#include "vp6818.dtsi"` |
| `GPIO_ACTIVE_LOW` | GPIO 极性宏 | 需 `#include <dt-bindings/gpio/gpio.h>` |

#### 设备树编译

```bash
# 编译 .dts 为 .dtb
# 方法1：在内核编译时自动编译
make dtbs

# 方法2：使用 dtc 单独编译
# dtc（Device Tree Compiler）由 device-tree-compiler 包提供
dtc -I dts -O dtb -o vp6818.dtb vp6818.dts

# 反编译 .dtb 为 .dts（调试用）
dtc -I dtb -O dts -o decompiled.dts vp6818.dtb

# 查看设备树中是否包含某个设备
fdtdump vp6818.dtb | grep -i uart
```

## 8. 根文件系统制作

### 8.1 根文件系统概述

根文件系统（Rootfs）是 Linux 启动后第一个挂载的文件系统，它提供了系统运行所需的基本目录结构、工具库和配置文件。

一个最小的根文件系统至少包含：

```
rootfs/
├── bin/         # 基本用户命令（BusyBox）
├── sbin/        # 系统管理命令
├── usr/         # 用户程序和数据
├── lib/         # 动态链接库 (.so)
├── etc/         # 配置文件
│   ├── inittab  # init 进程配置
│   ├── fstab    # 文件系统挂载表
│   ├── init.d/  # 启动脚本
│   └── profile  # 用户登录配置
├── dev/         # 设备节点
├── proc/        # proc 文件系统挂载点
├── sys/         # sysfs 挂载点
├── tmp/         # 临时文件
├── var/         # 可变数据
├── mnt/         # 挂载点
└── root/        # root 用户家目录
```

### 8.2 使用 BusyBox 构建最小根文件系统

**BusyBox** 是一个"瑞士军刀"般的可执行文件，它将数百个常用 Linux 命令（ls、cp、mv、vi、sh 等）集成到一个二进制文件中，极大减小了根文件系统体积。

#### 编译 BusyBox

```bash
# 1. 下载 BusyBox
wget https://busybox.net/downloads/busybox-1.36.0.tar.bz2
tar xf busybox-1.36.0.tar.bz2
cd busybox-1.36.0

# 2. 配置（设置交叉编译）
export ARCH=arm64
export CROSS_COMPILE=aarch64-linux-gnu-
make defconfig

# 3. 修改配置以确保静态编译（可选，方便调试）
# 进入 menuconfig 勾选 Settings --> Build static binary (no shared libs)
make menuconfig

# 4. 编译
make -j$(nproc)

# 5. 安装到指定目录
make install CONFIG_PREFIX=../rootfs

# 安装后，rootfs 目录下将出现 bin/ sbin/ usr/ 等目录
```

#### 手工构建根文件系统目录

```bash
# 在工作目录下创建 rootfs
mkdir -p ~/rootfs
cd ~/rootfs

# 创建基本目录结构
mkdir -p bin sbin usr/bin usr/sbin lib etc/init.d dev proc sys tmp var mnt root

# 复制 BusyBox 安装产物
cp -a ~/busybox-1.36.0/_install/* ./

# 复制交叉编译器的动态链接库
# 找到 aarch64-linux-gnu 的 lib 目录
TOOLCHAIN_LIB=$(aarch64-linux-gnu-gcc -print-sysroot)/lib
cp -a $TOOLCHAIN_LIB/*.so* lib/

# 或手动复制常用库

cp /usr/aarch64-linux-gnu/lib/libpthread.so.0 lib/
```

#### 创建配置文件

```bash
# 1. init 进程配置文件 /etc/inittab
cat > etc/inittab << 'EOF'
::sysinit:/etc/init.d/rcS
::respawn:-/bin/sh
::ctrlaltdel:/sbin/reboot
::shutdown:/bin/umount -a -r
EOF

# 2. 系统初始化脚本 /etc/init.d/rcS
cat > etc/init.d/rcS << 'EOF'
#!/bin/sh
# 挂载文件系统
mount -t proc none /proc
mount -t sysfs none /sys
mount -t tmpfs none /tmp

# 创建设备节点（如果使用 devtmpfs 则自动创建）
mdev -s

# 配置网络（可选）
ifconfig lo 127.0.0.1
# ifconfig eth0 192.168.1.200 netmask 255.255.255.0 up
# route add default gw 192.168.1.1

# 打印启动信息
echo "Welcome to Embedded Linux (BusyBox Build)"
EOF
chmod +x etc/init.d/rcS

# 3. fstab 文件系统挂载表
cat > etc/fstab << 'EOF'
proc     /proc   proc    defaults  0  0
sysfs    /sys    sysfs   defaults  0  0
tmpfs    /tmp    tmpfs   defaults  0  0
devpts   /dev/pts devpts  defaults  0  0
EOF

# 4. profile 用户登录配置
cat > etc/profile << 'EOF'
export PATH=/bin:/sbin:/usr/bin:/usr/sbin
export PS1='[\u@\h:\w]# '
alias ll='ls -alF'
alias ls='ls --color=auto'
EOF
```

#### 制作根文件系统镜像

```bash
# 方式1：制作 ext4 镜像（用于 eMMC/SD 卡)
cd ~/rootfs
dd if=/dev/zero of=rootfs.ext4 bs=1M count=512
```

对于需要更完整开发环境的情况，可以使用 **Ubuntu Base** 构建根文件系统，它提供 apt 包管理器、完整的软件生态系统。

```bash
# 1. 下载 Ubuntu Base for ARM64

sudo mount -t proc /proc proc/

sudo mount -t tmpfs tmpfs tmp/

# 5. 拷贝 DNS 配置以访问网络
sudo cp /etc/resolv.conf etc/resolv.conf

# 6. 使用 chroot 进入 ARM64 环境
sudo chroot .

# 以下命令在开发板 ARM64 环境中执行
# 更新软件源

# 安装常用软件
apt install -y \
    openssh-server \

# 8. 打包成镜像
```

### 8.4 烧录根文件系统

```bash
# 烧录到 SD 卡第二分区
sudo dd if=rootfs.ext4 of=/dev/sdb2 bs=1M status=progress conv=fsync

# 烧录到 eMMC（通过 U-Boot 或 fastboot）
# 方式1：U-Boot 下使用 fastboot 烧录
sudo fastboot flash rootfs rootfs.ext4

# 方式2：从 U-Boot 使用 mmc write
# 先将 image 写入 SD 卡或通过 TFTP 传到内存
tftp 0x50000000 rootfs.ext4
mmc dev 0              # 选择 eMMC
mmc write 0x50000000 0x8000 0x8000  # 写入 rootfs 分区（扇区地址需参考分区表）
```

## 9. 开发板与宿主机通信

### 9.1 串口连接（minicom）

**串口**是嵌入式开发中最基本的调试手段，用于查看 U-Boot 和内核启动日志、登录系统。

#### 硬件连接

```
宿主机 USB ---(USB转串口线)---> 开发板调试串口引脚

开发板端（通常为 4-pin 排针）：
  Pin 1: GND  ---------- USB转串口 GND
  Pin 2: TXD  ---------- USB转串口 RXD
  Pin 3: RXD  ---------- USB转串口 TXD
  Pin 4: VCC  ---------- (通常不连接，防止供电冲突)
```

> **注意**：TX 连接 RX，RX 连接 TX（交叉连接）。

#### minicom 配置与使用

```bash
# 安装 minicom
sudo apt install -y minicom

# 查看 USB 转串口设备节点
ls -la /dev/ttyUSB* /dev/ttyACM*

# 第一次运行需配置
sudo minicom -s

# 在 minicom 配置菜单中：
# 选择 "Serial port setup"
# +------------------------------------------+
# | A - Serial Device: /dev/ttyUSB0           |
# | B - Lockfile Location: /var/lock          |
# | C - Callin Program:                       |
# | D - Callout Program:                      |
# | E - Bps/Par/Bits: 115200 8N1              |
# | F - Hardware Flow Control: No             |
# | G - Software Flow Control: No             |
# +------------------------------------------+
# 选择 "Save setup as dfl" 保存为默认配置
# 选择 "Exit" 退出配置

# 启动串口连接
sudo minicom

# 带参数直接启动
sudo minicom -D /dev/ttyUSB0 -b 115200

# 退出 minicom：Ctrl+A，然后 X，确认退出
```

#### 串口常见问题排查

```bash
# 1. 权限问题（用户不在 dialout 组）
sudo usermod -a -G dialout $USER
# 重新登录使组权限生效

# 2. 串口被占用
lsof /dev/ttyUSB0
# 使用 lsof 查找占用进程（如 picocom 等）

# 3. 波特率不匹配
# 常见嵌入式开发板波特率：115200，但也有 1500000（1.5Mbps）
stty -F /dev/ttyUSB0 115200

# 4. 使用 picocom（minicom 的轻量级替代）
sudo apt install -y picocom
picocom -b 115200 /dev/ttyUSB0
# 退出：Ctrl+A，Ctrl+Q
```

### 9.2 SSH 登录

当开发板网络配置好后，SSH 比串口更方便高效。

```bash
# 开发板端（确保网络配置正确，sshd 已启动）
# 查看 IP 地址
ifconfig eth0
# 或者
ip addr show eth0

# 确认 SSH 服务已启动
systemctl status sshd
# 或
ps aux | grep sshd

# 宿主机端连接
ssh root@192.168.1.200

# 传递文件到开发板（SCP）
scp my_program.c root@192.168.1.200:/root/

# 从开发板拉取文件
scp root@192.168.1.200:/var/log/syslog ./
```

### 9.3 NFS 挂载根文件系统

**NFS（Network File System）** 允许开发板通过网络挂载宿主机上的目录作为根文件系统，极大加速开发迭代——修改代码后无需重新烧录。

#### 宿主机配置 NFS 服务器

```bash
# 1. 安装 NFS 服务器
sudo apt install -y nfs-kernel-server

# 2. 编辑 /etc/exports，添加导出目录
# 将 rootfs 目录导出（允许开发板读写）
sudo bash -c 'echo "/home/zhouxuan/rootfs 192.168.1.0/24(rw,sync,no_subtree_check,no_root_squash)" >> /etc/exports'

# 3. 重启 NFS 服务器
sudo systemctl restart nfs-kernel-server

# 4. 检查导出是否生效
showmount -e

# 5. 如果在同一台宿主机上测试
sudo mount -t nfs localhost:/home/zhouxuan/rootfs /mnt
ls /mnt
sudo umount /mnt
```

#### 开发板 U-Boot 设置 NFS 启动

```bash
# 在 U-Boot 命令行中设置 NFS 启动参数
setenv serverip 192.168.1.100     # 宿主机 IP
setenv ipaddr 192.168.1.200      # 开发板 IP
setenv netmask 255.255.255.0
setenv gatewayip 192.168.1.1

# NFS 根文件系统 bootargs
# root=/dev/nfs 表示使用 NFS 根文件系统
# nfsroot=<服务器IP>:<路径> 指定 NFS 挂载源
# rw 表示读写挂载
# nfsvers=3 使用 NFSv3 协议（兼容性更好）

setenv bootargs 'console=ttySAC2,115200 root=/dev/nfs nfsroot=192.168.1.100:/home/zhouxuan/rootfs,rw,nfsvers=3 ip=192.168.1.200:192.168.1.100:192.168.1.1:255.255.255.0::eth0:off'

# 通过网络加载内核和设备树
tftp 0x40008000 zImage
tftp 0x43000000 vp6818.dtb

# 启动内核
bootz 0x40008000 - 0x43000000
```

#### NFS 启动内核参数详解

```
root=/dev/nfs                                         # 根文件系统类型为 NFS
nfsroot=192.168.1.100:/home/zhouxuan/rootfs,rw       # NFS 服务器 IP 与路径
nfsvers=3                                             # NFS 协议版本（3 比 4 更简单）
ip=<dev板IP>:<服务器IP>:<网关>:<掩码>::eth0:off      # 网络配置（内核自动配置网卡）
```

`ip=` 参数的完整格式：

```
ip=<client-ip>:<server-ip>:<gw-ip>:<netmask>:<hostname>:<device>:<autoconf>

# 更简单的用法（使用 DHCP 自动获取）：ip=dhcp
setenv bootargs 'console=ttySAC2,115200 root=/dev/nfs nfsroot=192.168.1.100:/home/zhouxuan/rootfs rw ip=dhcp'
```

### 9.4 TFTP 传输文件

**TFTP（Trivial File Transfer Protocol）** 用于在 U-Boot 中通过网络加载内核和 dtb，比从 SD 卡读取更快，适合频繁修改内核调试的场景。

#### 宿主机配置 TFTP 服务器

```bash
# 1. 安装 TFTP 服务器
sudo apt install -y tftpd-hpa tftp-hpa

# 2. 配置 TFTP 服务器
sudo vim /etc/default/tftpd-hpa

# 内容：
# TFTP_USERNAME="tftp"
# TFTP_DIRECTORY="/tftpboot"           # TFTP 根目录
# TFTP_ADDRESS="0.0.0.0:69"
# TFTP_OPTIONS="-l -c -s -s --secure"

# 3. 创建 TFTP 目录并设置权限
sudo mkdir -p /tftpboot
sudo chmod 777 /tftpboot

# 4. 将内核和设备树复制到 TFTP 目录
sudo cp arch/arm64/boot/Image /tftpboot/
sudo cp arch/arm64/boot/dts/nexell/vp6818.dtb /tftpboot/

# 5. 重启 TFTP 服务器
sudo systemctl restart tftpd-hpa

# 6. 验证 TFTP 服务器是否运行
sudo systemctl status tftpd-hpa
netstat -an | grep :69
# 使用 tftp 客户端测试
echo "get test.txt" | tftp 192.168.1.100
```

#### U-Boot 端使用 TFTP

```bash
# 先确保网络配置正确
setenv serverip 192.168.1.100
setenv ipaddr 192.168.1.200
setenv netmask 255.255.255.0

# 测试网络连通
ping 192.168.1.100

# TFTP 下载内核到内存
tftp 0x40008000 Image

# TFTP 下载设备树
tftp 0x43000000 vp6818.dtb

# 启动
booti 0x40008000 - 0x43000000

# 如果内核是 zImage（ARM 32位），使用 bootz
bootz 0x40008000 - 0x43000000
```

#### 常用 TFTP 调试场景

```bash
# 场景1：频繁修改内核，从 TFTP 启动
setenv bootcmd 'tftp 0x40008000 Image; tftp 0x43000000 vp6818.dtb; booti 0x40008000 - 0x43000000'
saveenv
# 下次自动启动时，将从 TFTP 加载内核

# 场景2：从 SD 卡启动根文件系统，但从 TFTP 加载内核
setenv bootcmd 'mmc dev 0; ext4load mmc 0:1 0x40008000 /Image; ext4load mmc 0:1 0x43000000 /vp6818.dtb; booti 0x40008000 - 0x43000000'
setenv bootargs 'console=ttySAC2,115200 root=/dev/mmcblk0p2 rootwait rw'
saveenv

# 场景3：双备份启动（先尝试 SD 卡，失败则从 TFTP）
setenv bootcmd 'if mmc dev 0; then ext4load mmc 0:1 0x40008000 /Image && booti 0x40008000 - 0x43000000; fi; tftp 0x40008000 Image; tftp 0x43000000 vp6818.dtb; booti 0x40008000 - 0x43000000'
saveenv
```

### 9.5 完整工作流程示例

开发和调试过程中，各通信方式的典型配合：

```
宿主机（Ubuntu）                         开发板
    │                                      │
    │---[USB 串口 (minicom)]-------------->│ 观察启动日志、登录
    │                                      │
    │---[TFTP 加载内核/dtb]--------------->│ U-Boot 从 TFTP 获取内核
    │                                      │
    │---[NFS 根文件系统]------------------>│ 挂载宿主机目录作为 rootfs
    │                                      │
    │---[SSH 远程登录]-------------------->│ 进入开发板 shell
    │                                      │
    │---[SCP 传输编译产物]---------------->│ 将交叉编译程序传到板端
    │                                      │
    │<--[dmesg / syslog 日志]-------------│ 获取内核日志
    │                                      │
    │<--[网络调试 (gdb/gdbserver)]--------│ 远程调试应用程序
```

最有效率的开发流程：

1. 串口连接 minicom，观察所有启动信息
2. 使用 NFS 共享根文件系统，避免反复烧写
3. 在所有驱动调试完成后，将最后的 rootfs 固化到 eMMC
