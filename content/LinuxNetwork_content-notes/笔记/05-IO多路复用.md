# I/O 多路复用

> 本章目标：理解为什么需要同时监听多个文件描述符，并掌握 `select/poll/epoll` 的基本思路。

## 1. 阻塞 I/O 的问题

阻塞 I/O 很简单：

```text
没有数据 -> read 阻塞等待
有数据   -> read 返回数据
```

如果服务端只有一个客户端，这样没问题。但如果有很多客户端，一个线程阻塞在某个 fd 上，就无法及时处理其他 fd。

I/O 多路复用解决的问题是：

```text
同时关注多个 fd，哪个就绪就处理哪个。
```

## 2. select

`select` 使用 fd 集合表示要监听的读、写、异常事件。

```c
#include <sys/select.h>

int select(int nfds,
           fd_set *readfds,
           fd_set *writefds,
           fd_set *exceptfds,
           struct timeval *timeout);
```

常用宏：

| 宏 | 作用 |
|---|---|
| `FD_ZERO` | 清空集合 |
| `FD_SET` | 把 fd 加入集合 |
| `FD_CLR` | 从集合删除 fd |
| `FD_ISSET` | 判断 fd 是否就绪 |

## 3. select 示例

```c
fd_set readfds;
FD_ZERO(&readfds);
FD_SET(listen_fd, &readfds);
FD_SET(conn_fd, &readfds);

int maxfd = listen_fd > conn_fd ? listen_fd : conn_fd;
int n = select(maxfd + 1, &readfds, NULL, NULL, NULL);
if (n < 0) {
    perror("select");
}

if (FD_ISSET(listen_fd, &readfds)) {
    // 有新连接
}

if (FD_ISSET(conn_fd, &readfds)) {
    // 有客户端数据
}
```

注意：`select` 返回后，集合会被修改。下一轮循环前需要重新设置集合。

## 4. select 参数理解

| 参数 | 说明 |
|---|---|
| `nfds` | 最大 fd + 1 |
| `readfds` | 关注可读事件 |
| `writefds` | 关注可写事件 |
| `exceptfds` | 关注异常事件 |
| `timeout` | 超时时间，`NULL` 表示一直等 |

返回值：

| 返回值 | 含义 |
|---|---|
| `> 0` | 就绪 fd 数量 |
| `0` | 超时 |
| `< 0` | 出错 |

## 5. poll

`poll` 使用数组描述要监听的 fd。

```c
#include <poll.h>

struct pollfd fds[2];
fds[0].fd = listen_fd;
fds[0].events = POLLIN;
fds[1].fd = conn_fd;
fds[1].events = POLLIN;

int n = poll(fds, 2, -1);
```

对比 `select`：

- 不需要计算 `maxfd + 1`。
- 不受固定 fd 集合大小影响。
- 用数组管理大量 fd 更方便。

## 6. epoll

`epoll` 更适合大量连接场景。

基本流程：

```text
epoll_create1 -> epoll_ctl 添加/修改/删除 fd -> epoll_wait 等待事件
```

示例框架：

```c
#include <sys/epoll.h>

int epfd = epoll_create1(0);

struct epoll_event ev;
ev.events = EPOLLIN;
ev.data.fd = listen_fd;
epoll_ctl(epfd, EPOLL_CTL_ADD, listen_fd, &ev);

struct epoll_event events[64];
int n = epoll_wait(epfd, events, 64, -1);
for (int i = 0; i < n; ++i) {
    int fd = events[i].data.fd;
    // 处理 fd 事件
}
```

## 7. select、poll、epoll 对比

| 对比项 | select | poll | epoll |
|---|---|---|---|
| fd 管理 | fd_set | 数组 | 内核事件表 |
| 大量 fd | 不方便 | 比 select 方便 | 更适合 |
| 每轮是否重设 | 需要 | 事件字段可复用 | 通过 ctl 管理 |
| 常见用途 | 入门、小规模 | 中等规模 | 高并发服务 |

## 8. 多路复用服务端思路

典型循环：

```text
初始化监听 socket
加入多路复用监听集合
while (1):
    等待事件
    如果监听 socket 就绪：accept 新连接
    如果连接 socket 就绪：读取并处理数据
    如果连接关闭：移除 fd 并 close
```

## 9. 易错点

- `select` 的 `nfds` 忘记加 1。
- `select` 返回后没有重新初始化 fd 集合。
- 客户端关闭连接后没有移除 fd。
- 把“可读”误解为一定能读到业务完整包。
- `epoll` 中忘记处理错误和关闭事件。
