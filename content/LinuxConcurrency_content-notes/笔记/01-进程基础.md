# 进程基础

> 本章目标：理解 Linux 为什么需要进程，以及进程如何创建、退出、等待和替换程序。

## 1. 程序与进程

程序是磁盘上的可执行文件，是静态的；进程是程序运行起来后的活动，是动态的。

可以这样类比：

| 概念 | 类比 |
|---|---|
| 程序 | 菜谱 |
| 进程 | 按菜谱真正炒菜的过程 |

一个程序可以启动多次，因此一个程序可以对应多个进程。

## 2. 为什么需要进程

如果系统一次只能执行一个程序，CPU 会经常等待 I/O，利用率很低。操作系统引入进程后，可以让多个程序在同一时间段内交替运行。

这就是并发：

```text
进程 A：运行 -> 等待 I/O -> 就绪 -> 运行
进程 B：就绪 -> 运行 -> 就绪 -> 等待 I/O
```

在单核 CPU 上，并发通常表现为快速切换；在多核 CPU 上，多个进程还可能真正并行执行。

## 3. 进程状态

常见状态：

| 状态 | 含义 |
|---|---|
| 就绪 Ready | 等待 CPU 调度 |
| 运行 Running | 正在 CPU 上执行 |
| 阻塞 Blocking | 等待外部事件，例如 I/O |
| 退出 Zombie/Dead | 运行结束，等待父进程回收或已释放 |

简化状态转换：

```text
就绪 --调度--> 运行 --时间片到--> 就绪
运行 --等待事件--> 阻塞 --事件完成--> 就绪
运行 --exit/return--> 退出
```

## 4. 进程地址空间

每个进程都有自己的虚拟地址空间。典型布局包括：

| 区域 | 用途 |
|---|---|
| 代码段 text | 存放机器指令 |
| 只读数据段 rodata | 字符串常量等只读内容 |
| 数据段 data | 已初始化全局变量 |
| BSS 段 | 未初始化全局变量 |
| 堆 heap | `malloc` 动态分配 |
| 栈 stack | 局部变量、函数调用现场 |

进程之间地址空间相互隔离，这是稳定性和安全性的基础。

## 5. fork：创建子进程

`fork` 会复制当前进程，产生一个子进程。

```c
#include <stdio.h>
#include <sys/types.h>
#include <unistd.h>

int main(void) {
    pid_t pid = fork();

    if (pid < 0) {
        perror("fork");
        return 1;
    }

    if (pid == 0) {
        printf("child: pid=%d\n", getpid());
    } else {
        printf("parent: child pid=%d\n", pid);
    }

    return 0;
}
```

返回值规则：

| 返回值 | 所在进程 | 含义 |
|---|---|---|
| `< 0` | 父进程 | 创建失败 |
| `0` | 子进程 | 当前是子进程 |
| `> 0` | 父进程 | 返回子进程 PID |

## 6. wait：回收子进程

父进程应该等待子进程结束，避免产生僵尸进程。

```c
#include <sys/wait.h>
#include <unistd.h>
#include <stdio.h>

int main(void) {
    pid_t pid = fork();

    if (pid == 0) {
        return 7;
    }

    int status = 0;
    wait(&status);

    if (WIFEXITED(status)) {
        printf("child exit code = %d\n", WEXITSTATUS(status));
    }

    return 0;
}
```

## 7. exit 与 return

在 `main` 函数中：

```c
return 0;
```

基本等价于正常退出进程。也可以显式调用：

```c
#include <stdlib.h>

exit(0);
```

常见约定：

- `0` 表示成功。
- 非 `0` 表示失败或异常。

## 8. exec：替换进程映像

`exec` 系列函数不会创建新进程，而是把当前进程的程序替换成另一个程序。

```c
#include <unistd.h>
#include <stdio.h>

int main(void) {
    execlp("ls", "ls", "-l", NULL);
    perror("execlp");
    return 1;
}
```

如果 `exec` 成功，后面的代码不会继续执行；只有失败时才会返回。

## 9. fork + exec 的常见模式

Shell 执行命令时常用这个模型：

```text
shell 进程
  └─ fork 创建子进程
        └─ 子进程 exec 替换为目标程序
  └─ 父进程 wait 等待命令完成
```

简化示例：

```c
pid_t pid = fork();
if (pid == 0) {
    execlp("ls", "ls", "-l", NULL);
    _exit(127);
}
wait(NULL);
```

## 10. 易错点

- `fork` 后父子进程都会继续执行后面的代码。
- `fork` 的返回值在父子进程中不同。
- 子进程结束后，父进程不回收可能产生僵尸进程。
- `exec` 成功后不会返回。
- 多进程输出到终端时，顺序不一定稳定。
