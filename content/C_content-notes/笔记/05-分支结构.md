# 分支结构

## 学习目标

完成本模块的学习后，应能够：

1. 掌握 `if` / `else if` / `else` 分支语句的语法和语义，理解悬空 else（dangling else）问题的成因和规避方法。
2. 掌握 `switch` / `case` 语句的语法，理解穿透（fall-through）机制、`break` 的作用、`default` 位置的可选性和类型限制。
3. 理解条件表达式（`? :`）的求值规则，以及逻辑运算符（`&&`、`||`）的短路求值（short-circuit evaluation）特性。
4. 了解分支语句在汇编层面的基本实现——条件跳转指令的直觉概念。
5. 理解分支预测（branch prediction）对嵌入式实时系统性能的影响。
6. 养成防御式编程（defensive programming）习惯：用 `if` 保护数组下标和指针访问。
7. 认出并修正常见陷阱：`if (x = 5)` 赋值误当判断、`switch` 忘记 `break`、对浮点数使用 `switch` 等。

---

## 本章与工作的关系

分支结构是所有 C 程序中**体现逻辑决策**的基本手段。

- **嵌入式控制逻辑**：传感器的阈值判断、按键事件分发、状态机（state machine）的各级状态转移，全部依赖分支语句。
- **工业通信协议解析**：报文类型码需要 `switch` / `case` 分发到不同的处理函数；条件不满足时的容错走 `if` 过滤。
- **防御式编程**：在校招代码审查（code review）中，面试官会专门检查你有没有在数组下标或指针解引用之前加保护 `if`。没加的保护往往是 **CVE 安全漏洞**的根源。
- **性能敏感场景**：嵌入式 CPU 往往没有复杂的分支预测硬件，一次分支预测错误（misprediction）可能浪费十几个时钟周期。理解分支带来的性能代价是你写出实时可靠代码的前提。

因此，本章并非只是语法罗列，而是为后续的嵌入式开发、安全编码、性能优化铺路。

## 一、`if` / `else` 语句详解

### 1.1 直觉

写程序就是在告诉计算机："如果……就做 A；否则就做 B。"`if` 语句就是这句话最直接的翻译。

### 1.2 定义

`if` 语句根据条件表达式的值（非零为真，零为假）决定是否执行后续语句。

**三种基本形式：**

| 形式 | 语法 | 语义 |
|---|---|---|
| 单分支 | `if (表达式) 语句` | 条件为真则执行语句 |
| 双分支 | `if (表达式) 语句1 else 语句2` | 真 → 语句1；假 → 语句2 |
| 多分支阶梯 | `if (e1) s1 else if (e2) s2 ... else sn` | 依次测试，首个为真时执行对应分支 |

### 1.3 代码与输出

```c
#include <stdio.h>

int main(void)
{
    int score;
    printf("请输入成绩: ");
    scanf("%d", &score);

    if (score < 0 || score > 100)
    {
        printf("输入无效\n");
        return 1;
    }

    if (score >= 90)
    {
        printf("等级: A\n");
    }
    else if (score >= 75)
    {
        printf("等级: B\n");
    }
    else if (score >= 60)
    {
        printf("等级: C\n");
    }
    else
    {
        printf("等级: D\n");
    }

    return 0;
}
```

```
输入: 85  →  等级: B
输入: 120 →  输入无效
输入: 45  →  等级: D
```

### 1.4 悬空 else 问题（dangling else）

C 标准规定：**`else` 总是与它上面最近的、同级的、尚未配对的 `if` 结合。** 这是语言本身的设计，不是编译器的选择。

```c
#include <stdio.h>

int main(void)
{
    int x = 0, y = 1;

    /* 悬空 else：缩进暗示 else 与第一个 if 匹配，实际上与第二个 if 匹配 */
    if (x > 0)
        if (y > 0)
            printf("x>0, y>0\n");
    else
        printf("x<=0 (?) \n");       /* 这行永远不会执行 —— 它属于内层 if */

    return 0;
}
```

**输出：** 无任何输出。

**分析：** 因为 `x == 0`，外层 `if (x > 0)` 为假，整个嵌套结构（包含内层 `if` 和后面的 `else`）被跳过。`else` 虽然在缩进上与第一个 `if` 对齐，但语法上属于内层 `if`。

**规避方法：** 无论分支是否只有一条语句，始终使用花括号 `{}`。

```c
/* 正确的做法：花括号消除歧义 */
if (x > 0)
{
    if (y > 0)
        printf("x>0, y>0\n");
}
else
{
    printf("x<=0\n");
}
```

### 1.5 陷阱细节：花括号与声明

在 `if` 分支内声明变量的规则随 C 标准版本不同而不同。

- **C90：** 不允许在 `if` 的 `()` 内声明变量。变量必须在花括号 `{}` 内声明，且 `{}` 代表一个复合语句（block）。
- **C99 及以后：** 可以在 `if` 的 `()` 内声明变量（如 `if (int x = get())`），该变量的作用域覆盖整个 `if - else` 结构。这是 C99 引入的特性，GCC 和 Clang 都支持，但要注意你的编译标准是否允许。

```c
/* C99 起允许的写法 */
#include <stdio.h>

int main(void)
{
    /* if 的声明条件 —— 变量作用域包含 else 分支 (C99 特性) */
    if (int x = 5)
    {
        printf("x = %d, 条件为真\n", x);
    }
    else
    {
        /* x 在这里也可见 */
        printf("x = %d, 条件为假\n", x);
    }
    return 0;
}
```

**注意：** 编译时请确认 `-std` 版本。使用 `gcc -std=c11 -Wall -Wextra -Wpedantic` 时此写法合法。

## 二、`switch` / `case` 详解

### 2.1 直觉

当你需要对**单个整型表达式**的结果做出**多个固定选项**的选择时，`switch` 比一连串 `if - else if` 更清晰。例如：根据协议中的指令码选择执行动作。

### 2.2 定义与语法

```c
switch (整型表达式)
{
    case 常量表达式1:
        语句序列;
        break;   /* 可选 */
    case 常量表达式2:
        语句序列;
        break;
    /* ... 更多 case ... */
    default:     /* 可选 */
        语句序列;
}
```

### 2.3 执行规则（step by step）

1. 计算 `switch` 后的整型表达式，得到一个整数值。
2. 将该值与每个 `case` 标签的常量表达式**逐一比较**（注意：这是顺序比较，但编译器通常会优化为跳转表，所以不能依赖比较顺序）。
3. 找到匹配的 `case` 后，从该处**开始向下顺序执行**，直到遇到 `break` 或者到达 `switch` 结构的结尾。
4. 如果没有任何 `case` 匹配，执行 `default` 分支（如果有）。
5. `default` 的位置可以放在 `switch` 结构中的任意位置，不一定要在末尾。但按惯例通常放在最后。

### 2.4 代码与输出

```c
#include <stdio.h>

int main(void)
{
    int cmd;
    printf("请输入指令码 (1-4): ");
    scanf("%d", &cmd);

    switch (cmd)
    {
        case 1:
            printf("启动\n");
            break;
        case 2:
            printf("暂停\n");
            break;
        case 3:
            printf("继续\n");
            break;
        case 4:
            printf("停止\n");
            break;
        default:
            printf("未知指令\n");
            break;
    }

    return 0;
}
```

```
输入: 2  →  暂停
输入: 5  →  未知指令
```

### 2.5 穿透（fall-through）

当 `case` 末尾**没有** `break` 时，执行会"穿透"到下一个 `case`，继续执行其中的代码，直到遇到下一个 `break` 或 `switch` 结束。

**有意使用 fall-through 的场景（成绩分段）：**

```c
#include <stdio.h>

int main(void)
{
    int score;
    printf("请输入成绩: ");
    scanf("%d", &score);
    if (score < 0 || score > 100)
    {
        printf("无效\n");
        return 1;
    }

    switch (score / 10)
    {
        case 10:         /* 100 分 */
        case 9:          /* 90-99 */
            printf("A\n");     /* case 10 和 case 9 共用此输出 */
            break;
        case 8:
            printf("B\n");
            break;
        case 7:
            printf("C\n");
            break;
        case 6:
            printf("D\n");
            break;
        default:
            printf("E\n");
            break;
    }

    return 0;
}
```

**无意 fall-through（bug 示例）：**

```c
int n = 1;
switch (n)
{
    case 1:
        printf("一");   /* 没有 break，执行会穿透到 case 2 */
    case 2:
        printf("二");   /* n == 1 时也会执行到这里 */
        break;
    case 3:
        printf("三");
        break;
}
/* 输出: 一二  (而不是预期的 "一") */
```

**平台规范说明：** GCC 提供了 `-Wimplicit-fallthrough` 警告（在 `-Wextra` 中启用）。C23 引入了 `[[fallthrough]]` 属性来明确标注有意的 fall-through，但在 C11 之前的标准中没有标准化的标记方式。有些团队约定在注释中写 `/* fall through */` 来通过静态分析工具的检查。

### 2.6 `break` 的意义

`break` 跳出的是**当前所在的 `switch` 结构**，而不是外层循环（如果有的话）。它让执行流程跳过剩余的所有 `case` 和 `default`。

### 2.7 只能用整型

`switch` 的表达式的类型必须是**整数类型**（integral type）：

- `int`、`char`、`short`、`long`、`long long`、`_Bool`、枚举类型（`enum`）都是整数类型。
- `float` 和 `double` 等浮点类型**不允许**。
- 字符串、指针、结构体也**不允许**。

原因：`switch` 底层通过比较整型值或者使用跳转表（jump table）实现，浮点数存在不可避免的精度误差（rounding error），不适合做精确相等比较。

### 2.8 `if - else if` 和 `switch` 怎么选

| 比较维度 | `if - else if` | `switch` |
|---|---|---|
| 条件类型 | 任意布尔表达式（比较、范围、逻辑组合） | 仅能对单个整型表达式做相等比较 |
| 可读性 | 分支少时好；超过 4-5 个分支时结构变重 | 分支多且值离散时阅读性好 |
| 性能（编译器优化层面） | 难以优化为跳转表 | 编译器可生成跳转表（jump table），O(1) 分发 |
| 调试 | 每个条件都可单独设断点 | 整个 `switch` 一般是一个断点位置 |
| 浮点数/字符串 | 支持（通过比较函数） | 不支持 |
| 范围判断 | 支持（`if (x >= 0 && x < 10)`） | 不支持；需要用 `case` 枚举 |

**经验法则：** 如果选择依据是一个整型表达式，且候选值是少量的离散常量（如指令码、状态枚举、菜单选项），优先用 `switch`。如果条件涉及范围、浮点数、字符串、多个变量的组合逻辑，用 `if`。

## 三、条件表达式与逻辑运算符的短路求值

### 3.1 条件表达式（`? :`）

**直觉：** 根据条件在两个值/表达式中二选一。这是 `if - else` 在表达式层面的简洁形式。

**定义：**

```
条件 ? 表达式1 : 表达式2
```

条件为真（非零）时求值表达式1，否则求值表达式2。这个结构**整体是一个表达式**，有值，可以参与赋值、函数的参数传递等。

```c
#include <stdio.h>

int main(void)
{
    int a = 10, b = 20;
    int max = (a > b) ? a : b;      /* max = 20 */
    printf("max = %d\n", max);

    /* 可用于函数参数 */
    printf("绝对值: %d\n", (a > 0) ? a : -a);

    return 0;
}
```

```
输出:
max = 20
绝对值: 10
```

**工程建议：** 条件表达式适合简单的二选一赋值。如果逻辑复杂（嵌套 `?:`），会使代码难以阅读。不建议 `?:` 嵌套超过一层。

### 3.2 逻辑运算符的短路求值

C 语言的逻辑与 `&&` 和逻辑或 `||` 在执行时**从左向右求值**，且一旦结果确定，就不再计算右侧剩余的表达式。这称为**短路求值**（short-circuit evaluation）。

**`&&`（逻辑与）：** 左操作数为假（0）时，结果必定为假，右操作数不再求值。
**`||`（逻辑或）：** 左操作数为真（非 0）时，结果必定为真，右操作数不再求值。

```c
#include <stdio.h>

int main(void)
{
    int a = 0;
    int b = 0;

    /* && 短路：a == 0（假），右边 b = 100 不会执行 */
    int result1 = (a && (b = 100));
    printf("result1 = %d, b = %d\n", result1, b);   /* b 仍为 0 */

    a = 1;
    int c = 0;

    /* || 短路：a == 1（真），右边 c = 200 不会执行 */
    int result2 = (a || (c = 200));
    printf("result2 = %d, c = %d\n", result2, c);   /* c 仍为 0 */

    return 0;
}
```

```
输出:
result1 = 0, b = 0
result2 = 1, c = 0
```

**工程价值：**

```c
/* 安全解引用：先判非空再访问，利用短路避免空指针解引用 */
if (ptr != NULL && *ptr == 42)
{
    /* 指针非空时才解引用 —— 安全 */
}

/* 数组下标保护 */
int a[10];
int idx = get_index();
if (idx >= 0 && idx < 10 && a[idx] == 5)
{
    /* idx 在合法范围内时才访问 —— 安全 */
}
```

**顺序依赖的技巧：**

```c
/* 有意图地利用短路：确保 divisor 非零才做除法 */
if (divisor != 0 && dividend / divisor > threshold) { /* ... */ }
```

**注意：** 短路求值是 C 标准规定的行为，所有符合标准的编译器都必须遵守，不是特定平台的特性。

## 四、分支语句的汇编视角

> 本节的目的是建立概念层面的直觉，不需要记住指令名，但理解"分支对应什么级别的机器操作"有助于你评估性能。

### 4.1 条件跳转指令的概念

`if` 和 `switch` 在 CPU 层面最终被翻译为**比较指令** + **条件跳转指令**。

- `cmp`（compare）：比较两个值，设置 CPU 的标志寄存器（status flags），例如零标志位（ZF, Zero Flag）、符号标志位（SF, Sign Flag）等。
- `je`（jump if equal） / `jne`（jump if not equal）：根据标志寄存器的状态决定是否跳转到另一条指令。

**概念化示例**（并非真实汇编，仅供理解）：

```
// C 代码:  if (x > 0)  y = 1;
//
// 概念汇编:
//   cmp  x, 0       ; 比较 x 和 0
//   jle  .else      ; 如果 x <= 0，跳转到 else 分支
//   mov  y, 1       ; y = 1
//   jmp  .end
// .else:
//   mov  y, 0       ; y = 0
// .end:
```

### 4.2 `switch` 的常见实现方式

编译器可以根据 `case` 值的分布选择不同的实现策略：

1. **跳转表（jump table）：** 当 `case` 值紧凑（如 0-7 连续）时，生成一个地址表，`switch` 表达式直接索引到对应处理代码。时间复杂度 O(1)。
2. **二分查找/决策树：** 当 `case` 值稀疏且数量较多时，编译器可能生成类似二分查找的比较树。
3. **线性链：** `case` 数量很少时，退化为顺序比较链，和 `if - else if` 类似。

**关键点：** `switch` 的性能优势高度依赖于编译器的优化能力和 `case` 值的分布情况，这一点不是 C 标准规定的，而属于编译器实现的选择。面试时不要声称"`switch` 一定比 `if - else if` 快"，只能说"编译器有机会将其优化为跳转表"。

## 五、分支预测与性能（嵌入式场景）

### 5.1 什么是分支预测

现代 CPU 采用**流水线**（pipeline）技术：取指令、解码、执行、写回等步骤并行处理。遇到条件跳转指令时，CPU 不知道跳转是否发生，但必须提前预取指令才能保持流水线满载。**分支预测**（branch prediction）就是 CPU 用来猜测跳转方向的硬件机制。

### 5.2 预测错误的代价

如果分支预测错误（misprediction），CPU 需要丢弃已预取和执行了一半的指令，清空流水线，跳转到正确的目标地址重新开始。这会产生 **10-20 个时钟周期（clock cycles）的惩罚**。

在桌面 CPU（x86）上，现代分支预测器准确率通常在 95% 以上。但**嵌入式场景**差异很大：

- **ARM Cortex-M 系列（无分支预测）：** 每个条件跳转都可能导致流水线冲刷。分支的代价是固定的几个周期。
- **ARM Cortex-A 系列（有分支预测）：** 准确率取决于预测器的复杂度和模式规律性。

### 5.3 嵌入式上的工程实践

```c
/* 不好的模式：分支结果难以预测 */
for (int i = 0; i < n; i++)
{
    if (data[i] > threshold)      /* 如果 data 是随机信号，分支规律性差 */
    {
        process(data[i]);
    }
}

/* 好的模式：将条件转化为计算，消除分支 */
/* 如果 process 操作是可逆的，可以用掩码技巧 */
for (int i = 0; i < n; i++)
{
    unsigned char mask = (data[i] > threshold) - 1;  /* 真 → 0xFF, 假 → 0x00 */
    /* 按条件选择，无分支 —— 但注意可读性 */
}
```

**注意：** 无分支（branchless）编程并非总是有必要。**只有在深度嵌入式、实时约束极苛刻且经过 profile 证明分支代价构成瓶颈时**才需考虑这种优化。常规应用应优先保证代码清晰。

## 六、防御式编程与边界检查

### 6.1 直觉

防御式编程（defensive programming）的核心原则：**不要信任外部输入**。在 C 语言中，函数参数、用户输入、传感器读数、通信报文都可能携带超出预期的值。你的代码必须用 `if` 在这些值被使用之前先将非法值挡在门外。

### 6.2 用 `if` 保护数组访问

数组越界是 C 语言最臭名昭著的安全漏洞来源之一。保护手段很简单：在访问数组元素之前，检查下标是否在 `[0, n)` 范围内。

```c
#include <stddef.h>

/* 防御式数组访问函数 */
int get_element_safe(const int arr[], size_t len, size_t index)
{
    if (index >= len)                  /* 防御检查 */
    {
        return -1;                     /* 约定：用 -1 表示越界（如果 -1 不是有效值） */
    }
    return arr[index];
}
```

### 6.3 用 `if` 保护指针解引用

空指针（NULL pointer）解引用会导致未定义行为（undefined behavior, UB），通常表现为程序崩溃。

```c
void process_buffer(const char *buf, size_t len)
{
    if (buf == NULL)      /* 防御检查：指针非空才操作 */
    {
        return;            /* 提前返回，避免 UB */
    }

    for (size_t i = 0; i < len; i++)
    {
        putchar(buf[i]);
    }
}
```

### 6.4 嵌入式中的边界检查

```c
/* 模拟 ADC 采样值读取，带合法范围检查 */
#include <stdint.h>
#include <stdbool.h>

bool adc_read_safe(uint32_t adc_value)
{
    /* ADC 是 12 位，合法范围 0-4095 */
    if (adc_value > 4095)
    {
        return false;      /* 越界标志，不处理 */
    }

    /* 使用 adc_value 进行后续处理 */
    return true;
}
```

## 七、常见错误

### 7.1 `if (x = 5)` —— 赋值误当判断

`=` 是赋值运算符，`==` 是相等比较运算符。`if (x = 5)` 做了两件事：将 5 赋值给 x，然后将赋值表达式的值（即 5）作为条件判断。因为 5 非零，条件恒为真。

```c
#include <stdio.h>

int main(void)
{
    int x = 0;

    /* 编译能通过但逻辑错误：不是判断 x 是否等于 5，而是把 5 赋给 x */
    if (x = 5)
    {
        printf("这个分支永远会执行\n");
    }

    printf("x = %d\n", x);   /* x 被修改为 5 */

    return 0;
}
```

```
输出:
这个分支永远会执行
x = 5
```

**防御技巧：** 将常量写在比较运算符左侧（Yoda 条件），这样误写 `=` 时编译器会报错，因为不能给常量赋值。

```c
/* 如果手误写成 if (5 = x) ，编译器直接报错 */
if (5 == x) { /* ... */ }
```

**编译器辅助：** `gcc -Wall` 会给出警告 `warning: suggest parentheses around assignment used as truth value`。始终开启 `-Wall -Wextra -Wpedantic`。

### 7.2 `switch` 忘记 `break`

见上文 2.5 节的"无意 fall-through"示例。解决方案：除非故意利用 fall-through，否则每个 `case` 末尾都写 `break`。

### 7.3 浮点数做 `switch` 条件

`switch` 表达式必须是整数类型，浮点类型（`float`, `double`）会直接导致编译错误。

```c
double x = 1.5;
switch (x)     /* 编译错误: switch quantity not an integer */
{
    case 1.5:  /* 编译错误 */
        break;
}
```

**替代方案：** 使用 `if - else if` 链条，配合容差比较（因为浮点数相等比较不可靠）。

```c
double x = 1.5;
const double EPS = 1e-6;
if (x > 1.5 - EPS && x < 1.5 + EPS)
{
    /* 近似等于 1.5 */
}
```

### 7.4 带副作用的条件写在一起

短路求值带来的副效应（side effect）问题：

```c
/* 问题：x++ 在 && 右侧，如果 left 为假，x++ 不会执行 */
int left = 0;
int x = 10;
if (left && (x++ > 5))   /* left == 0，x++ 不执行 */
{
}
printf("x = %d\n", x);   /* 输出 x = 10，不是 11 —— 可能违反预期 */
```

**经验：** 不要在条件表达式中混合副作用操作（如 `++`、赋值、函数调用）。将副作用放在条件外面执行。

## 八、面试直连

**Q1：什么是悬空 else（dangling else）问题？如何避免？**

A：悬空 else 是指当 `if` 嵌套时，`else` 的归属不清晰（但 C 标准规定它属于最近的未配对 `if`）。避免方法是**始终使用花括号 `{}`**，即使分支只有一条语句。花括号将 `if` 和 `else` 的对应关系明确固定。

**Q2：什么时候应该用 `switch` 而不是 `if - else if`？**

A：当选择依据是一个**整型表达式**，且分支是少量离散常量值时，优先用 `switch`。例如：协议指令码、状态机状态、枚举值。`switch` 让代码更紧凑，并且编译器有机会优化为跳转表。如果条件涉及范围比较、浮点数、字符串、多变量逻辑组合，只能使用 `if - else if`。

**Q3：`switch` 的 `case` 后面能用变量吗？为什么？**

A：不能。`case` 标签必须是**整数常量表达式**（integer constant expression），即在编译期就能计算出确定值的表达式。因为 `switch` 需要在编译期生成跳转逻辑（跳转表或决策树），变量值在编译期未知。

**Q4：`switch` 要处理一段连续区间（如 0-100）时，应该如何实现？**

A：可以通过数学变换将范围映射到离散值。例如成绩分段：`score / 10` 将 0-100 映射到 0-10。如果区间跨度大且无法映射，应改用 `if - else if` 链，因为 `switch` 本质只做相等的点比较，不适合范围判断。

**Q5：`switch` 中 `default` 必须放在最后吗？**

A：不是，`default` 可以放在 `switch` 内的任何位置，执行行为与位置无关——任何 `case` 不匹配时都会跳转到 `default` 标签处。但是通常约定放在最后，以提高可读性。如果 `default` 放在前面并且没有 `break`，也会穿透到后面的 `case`。

**Q6：`if` 语句的条件中，`&&` 和 `||` 的短路求值可以依赖吗？**

A：可以，这是 C 标准规定的行为。所有符合标准的编译器都必须保证 `&&` 和 `||` 从左向右求值并短路。这是安全编程的基础技巧，如 `if (p != NULL && *p == 5)` 利用短路避免空指针解引用。

**Q7：嵌入式系统中，分支语句可能带来哪些性能问题？**

A：分支语句可能造成**分支预测错误**（branch misprediction），CPU 需要清空流水线，浪费 10-20 个时钟周期。在无分支预测的 MCU（如低端 ARM Cortex-M）上，每个条件跳转都导致流水线暂停。对硬实时任务，如果分支结果不可预测且频繁执行，可能需要考虑用无分支（branchless）写法或查表法替代分支。

## 九、代码阅读题

### 题 1

```c
#include <stdio.h>

int main(void)
{
    int a = 0, b = 1, c = 2;

    if (a)
        if (b)
            printf("A\n");
        else
            printf("B\n");

    if (c)
        printf("C\n");

    return 0;
}
```

**问题：** 程序输出是什么？请解释为什么。

<details>
<summary>答案</summary>
只输出 `C`。第一组嵌套 `if`：`a == 0` 为假，整个内层 `if - else` 被跳过，没有输出。第二组 `if (c)`：`c == 2` 为真，输出 `C`。缩进带来的视觉误导正是悬空 else 问题的体现。因为 `a == 0`，没有任何分支体被执行。
</details>

### 题 2

```c
#include <stdio.h>

int main(void)
{
    int x = 3;

    switch (x)
    {
        default:
            printf("default ");
        case 1:
            printf("1 ");
        case 2:
            printf("2 ");
            break;
        case 3:
            printf("3 ");
    }

    return 0;
}
```

**问题：** 程序输出是什么？为什么？

<details>
<summary>答案</summary>
输出 `3 `。`x == 3` 匹配 `case 3`，输出 `3 `，然后执行到 `switch` 结束（后面没有 `break`，但也没有更多 `case` 了）。要注意的是：`default` 放在哪里都可以，这里因为没有匹配到 `default` 所以不执行。
</details>

### 题 3

```c
#include <stdio.h>

int main(void)
{
    int arr[] = {1, 2, 3, 4, 5};
    int *p = arr;
    int i = 2;

    if (p != NULL && i >= 0 && i < 5 && p[i] > 2)
    {
        printf("p[%d] = %d\n", i, p[i]);
    }

    return 0;
}
```

**问题：** 程序输出什么？利用了哪个语言特性？

<details>
<summary>答案</summary>
输出 `p[2] = 3`。利用逻辑与 `&&` 的短路求值（short-circuit evaluation）：`p != NULL` 为真，`i >= 0` 为真，`i < 5` 为真，才继续计算 `p[2] > 2`。任何一个条件为假就不会执行后续的解引用和比较，确保安全访问。
</details>

## 本章总结

1. **`if / else`** 是 C 语言中最通用的分支结构，支持任意布尔表达式和嵌套。注意悬空 else 问题，始终使用花括号。
2. **`switch / case`** 适用于整型表达式的离散常量匹配。理解 fall-through 和 `break` 的作用。`default` 位置任意，约定在末尾。
3. **条件表达式 `?:`** 适用于简单二选一赋值，不宜嵌套过深。
4. **短路求值** 是 C 标准行为，可用于安全指针/数组访问的前置检查。
5. 分支在汇编层面对应**条件跳转指令**，`switch` 可能被优化为**跳转表**。
6. **分支预测错误** 在嵌入式实时场景下会带来性能惩罚，但无分支优化应仅在经 profile 证明必要时使用。
7. **防御式编程**：`if` 保护数组下标和指针解引用，将错误阻止在数据被使用之前。
8. 常见错误：`if (x = 5)`、`switch` 忘 `break`、浮点数做 `switch` 条件。
9. **编译时始终开启** `gcc -std=c11 -Wall -Wextra -Wpedantic`。
