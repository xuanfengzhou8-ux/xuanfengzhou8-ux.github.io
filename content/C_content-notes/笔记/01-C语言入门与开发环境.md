# C 语言入门与开发环境

### 学习目标

- 了解 C 语言的历史、标准化历程及其在现代工业中的核心地位
- 在 macOS / Ubuntu / Windows 上独立搭建 C 开发环境（GCC / Clang + VS Code）
- 逐行理解 Hello World 程序的每一处细节，包括标准对 main 签名的要求
- 掌握从源码到可执行文件的完整编译四阶段，能用 `gcc -E` / `-S` / `-c` 输出中间产物
- 熟悉 C 语言的基本语法要素：语句、注释、标识符、关键字
- 能够阅读编译器报错和警告信息，并独立排除常见编译错误
- 了解嵌入式交叉编译工具链的基本概念

### 本章与工作的关系

C 语言是嵌入式系统、操作系统内核、数据库引擎、编译器、物联网设备固件的"母语"。在嵌入式开发岗位的面试和日常工作中：

- **面试必考**：编译过程、链接错误分析、预处理行为是 C 语言岗位的高频面试题。
- **调试必备**：理解编译选项（`-Wall` `-g`）和编译阶段，能帮你快速定位段错误、链接错误等疑难问题。
- **嵌入式特殊性**：嵌入式开发中，你几乎一定会用到交叉编译工具链（如 `arm-none-eabi-gcc`），理解工具链的结构是入门嵌入式的基础。
- **工程规范**：大型 C 项目（如 Linux 内核、RTOS）依赖多文件编译和 Makefile / CMake 构建系统，本章的编译链接知识是后续学习的基础。

学完本章，你将具备从零配置 C 开发环境、编写并编译第一个程序、以及读懂常见编译器报错的能力——这是所有 C 语言相关岗位的起点。

### C 语言概述

#### 定义

> C 语言是一种**静态类型、编译型、结构化**的通用编程语言，以高效、灵活和接近硬件的能力著称。

#### 历史

| 年份 | 里程碑 |
|------|--------|
| 1972 | Dennis Ritchie 在贝尔实验室为开发 UNIX 操作系统设计了 C 语言 |
| 1978 | Kernighan 和 Ritchie 出版《The C Programming Language》（即 K&R C），成为事实标准 |
| 1989 | ANSI 发布第一个官方标准 **C89**（也称 ANSI C） |
| 1990 | ISO 采纳为 **C90**（ISO/IEC 9899:1990），与 C89 内容一致 |
| 1999 | **C99** 标准发布：引入 `//` 注释、`inline` 关键字、`long long`、可变长数组（VLA）、指定初始化器 |
| 2011 | **C11** 标准发布：引入泛型表达式（`_Generic`）、多线程支持（`<threads.h>`）、匿名结构体/联合体、`_Static_assert` |
| 2018 | **C17** 标准发布：主要是缺陷修复，没有引入新的语言特性 |
| 2024 | **C23** 标准发布（ISO/IEC 9899:2023）：引入 `#elifdef` / `#elifndef`、`bool` 成为内置关键字、`nullptr`、`constexpr`、`static_assert` 不再需要 `<assert.h>`、删除了 K&R 函数定义等过时特性 |

> **面试提示**：C89 / C99 / C11 / C17 / C23 的主要区别是面试中常见的知识题。C11 的多线程支持和 C23 的 `bool` / `constexpr` 尤其值得关注。

#### C 语言的主要应用场景

| 领域 | 代表项目 |
|------|----------|
| **操作系统内核** | Linux 内核（约 95% 代码为 C）、Windows 内核、FreeBSD |
| **嵌入式系统** | 物联网固件、RTOS（FreeRTOS、Zephyr）、单片机程序（STM32、ESP32） |
| **数据库引擎** | SQLite（全部用 C 编写）、PostgreSQL（C 为主体） |
| **编译器与解释器** | GCC 本身、Python 解释器（CPython）、Lua 解释器 |
| **高性能计算** | 数值计算库（BLAS、LAPACK）、科学计算软件 |
| **网络协议栈** | Linux 网络子系统、lwIP（轻量级 TCP/IP 协议栈） |

#### C 语言的核心特征

| 特征 | 含义 | 带来的优势 |
|------|------|------------|
| 简洁高效 | 仅 30 多个关键字，编译后机器码执行效率接近汇编 | 适合对性能要求苛刻的场景（嵌入式、OS） |
| 静态类型 | 每个变量在编译时必须有确定的类型 | 类型错误在编译期发现，运行时无类型开销 |
| 直接操作内存 | 通过指针直接访问任意内存地址 | 可实现底层硬件控制、内存池管理 |
| 可移植 | ANSI/ISO 标准保证了跨平台编译的能力 | 一套代码可在 x86 / ARM / RISC-V 等架构上重新编译 |
| 系统级能力 | 可编写操作系统、驱动、内存管理代码 | 与操作系统 API 无缝交互 |

### 第一个程序详解

#### 完整代码

创建文件 `hello.c`：

```c
#include <stdio.h>

int main(void)
{
    printf("Hello, World!\n");
    return 0;
}
```

#### 逐行分析

##### 第 1 行：`#include <stdio.h>`

| 要素 | 含义 |
|------|------|
| `#include` | **预处理指令**，告诉预处理器将指定文件的内容"粘贴"到这里 |
| `<stdio.h>` | **标准输入输出头文件**，声明了 `printf`、`scanf` 等函数 |
| `< >` | 在**系统标准路径**（如 `/usr/include`）中搜索头文件 |
| `" "`（双引号） | 先在**当前目录**搜索，找不到再去系统路径 |

> **深度理解**：`#include` 不是 C 语言的"语句"，它没有分号，由预处理器处理。预处理器在处理完 `#include <stdio.h>` 后，会将 `/usr/include/stdio.h` 中数百行内容全部插入到你的源文件中。展开后的文件可用 `gcc -E hello.c -o hello.i` 查看，你会发现你的 6 行代码变成了数百行。

##### 第 3 行：`int main(void)`

这是程序的入口函数。C 标准对 `main` 的签名有明确定义：

**C11 标准 (5.1.2.2.1) 规定的两种合法形式：**

```c
int main(void)                       // 不接受命令行参数
int main(int argc, char *argv[])     // 接受命令行参数
```

| 要素 | 含义 |
|------|------|
| `int` | 返回类型：返回一个整型值给操作系统 |
| `main` | 函数名，程序启动时自动被调用 |
| `(void)` | 参数列表：`void` 明确表示不接受任何参数 |
| 其他形式（如 `void main()`） | **非标准**，在有些平台上可能编译通过，但不符合 C 标准。面试中应回答标准形式 |

> **面试提示**："`main` 函数应该返回什么类型？"——答 `int`，不是 `void`。`void main()` 在 C 标准中被列为 未定义行为 (undefined behavior)。

##### 第 5 行：`printf("Hello, World!\n");`

| 要素 | 含义 |
|------|------|
| `printf` | 格式化输出函数，在 `stdio.h` 中声明 |
| `"Hello, World!\n"` | **字符串字面量**，`\n` 是换行转义符 |
| `;` | **语句结束符**，每条 C 语句必须以分号结尾 |

##### 第 6 行：`return 0;`

向操作系统返回程序的退出状态码：

- **`return 0;`** —— 告诉操作系统程序正常结束
- **`return 非 0;`** —— 表示异常退出，具体值通常表示错误类型
- 在 shell 中可以用 `echo $?` 查看上一个程序的返回值

```bash
./hello
echo $?    # 输出 0
```

> **深度理解**：`return 0;` 中的 `0` 被返回给程序的调用者（shell 或父进程）。脚本和 Makefile 利用这个值判断程序是否运行成功。如果省略 `return 0;`，在 C99 及之后的标准中，`main` 函数执行到末尾会自动返回 `0`（这是对 `main` 的特殊规定，其他函数不行）。

#### 完整编译和运行

```bash
## 编译：生成可执行文件 hello
gcc -Wall -std=c11 hello.c -o hello

## 运行
./hello

## 预期输出
Hello, World!
```

> **推荐编译命令**：日常开发中建议始终加上 `-Wall -Wextra -std=c11` 以便在编译期发现潜在问题。

### 编译过程深度解析

C 编译器将源文件转换为可执行文件需要经过四个阶段。理解每个阶段是调试和优化的基础。

#### 总体流程

```
hello.c ───[预处理]──→ hello.i ───[编译]──→ hello.s ───[汇编]──→ hello.o ───[链接]──→ hello
源文件         预处理器    预处理后    编译器    汇编代码    汇编器    目标文件    链接器    可执行文件
              (cpp)       的代码     (cc1)                (as)                (ld)
```

#### 阶段一：预处理（Preprocessing）

**命令**：`gcc -E hello.c -o hello.i`

**做的事情**：
1. **展开宏定义**：将 `#define` 定义的宏替换为对应内容
2. **处理 `#include`**：将头文件内容递归插入到源文件中
3. **处理条件编译**：根据 `#if` / `#ifdef` / `#ifndef` 的条件决定保留或删除代码块
4. **删除注释**：所有 `//` 和 `/* */` 注释被替换为空格
5. **处理 `#line` / `#error` / `#pragma`** 等指令

**示例**：

创建 `macro.c`：

```c
#define PI 3.14159
#define AREA(r) (PI * (r) * (r))

int main(void)
{
    double r = 5.0;
    double area = AREA(r);
    return 0;
}
```

运行 `gcc -E macro.c -o macro.i`，查看 `macro.i` 会发现 PI 和 AREA 已被替换：

```c
int main(void)
{
    double r = 5.0;
    double area = (3.14159 * (r) * (r));
    return 0;
}
```

#### 阶段二：编译（Compilation）

**命令**：`gcc -S hello.i -o hello.s`（或一步到位 `gcc -S hello.c`）

**做的事情**：将预处理后的 C 代码翻译为**汇编语言**。这是复杂度最高的阶段，包括：

- **词法分析**：将源代码拆分为 token（标识符、关键字、运算符等）
- **语法分析**：根据 C 语法规则构建语法树（AST）
- **语义分析**：检查类型匹配、作用域规则
- **中间代码生成与优化**：生成平台无关的中间表示并优化
- **目标汇编代码生成**：从中间表示生成特定 CPU 架构的汇编指令

**示例**（查看 hello.s 的部分内容）：

```asm
main:
    pushq   %rbp
    movq    %rsp, %rbp
    leaq    .LC0(%rip), %rdi
    call    puts@PLT
    movl    $0, %eax
    popq    %rbp
    ret
```

> **嵌入式意义**：在嵌入式开发中，有时需要阅读汇编代码来验证编译器生成的代码是否高效，或者排查 C 代码无法表达的底层问题（中断延迟、指令顺序）。

#### 阶段三：汇编（Assembly）

**命令**：`gcc -c hello.s -o hello.o`（或一步到位 `gcc -c hello.c`）

**做的事情**：将汇编代码转换为**机器码**（CPU 可直接执行的 0/1 序列），生成**目标文件**（.o 或 .obj）。

目标文件的结构（ELF 格式为例）：

```
┌─────────────────┐
│  ELF 头          │ ← 文件类型、目标架构、入口地址等信息
├─────────────────┤
│  .text 段        │ ← 程序代码（机器指令）
├─────────────────┤
│  .data 段        │ ← 已初始化的全局变量
├─────────────────┤
│  .bss 段         │ ← 未初始化的全局变量
├─────────────────┤
│  符号表           │ ← 符号（函数名、全局变量名）及其地址
├─────────────────┤
│  重定位表         │ ← 需要链接器修正的地址信息
└─────────────────┘
```

**验证**：运行 `file hello.o` 会显示目标文件类型，`nm hello.o` 列出符号表。

```bash
gcc -c hello.c -o hello.o
nm hello.o
```

输出示例：

```
0000000000000000 T main
                 U printf
```

- `T main`：`main` 函数在 .text 段中已定义（T）
- `U printf`：`printf` 是**未定义符号**（U），需要在链接阶段解析

#### 阶段四：链接（Linking）

**命令**：`gcc hello.o -o hello`

**做的事情**：将多个目标文件和库文件合并为一个可执行文件。

##### 链接解决的核心问题

| 问题 | 说明 | 错误示例 |
|------|------|----------|
| **符号解析** | 将符号引用与定义匹配 | `undefined reference to 'xxx'` |
| **重定位** | 将目标文件中的相对地址修正为最终地址 | - |
| **库链接** | 从标准库中提取用到的函数（如 printf） | `undefined reference to 'printf'`（少见） |

##### 静态链接 vs 动态链接

| 特性 | 静态链接 | 动态链接 |
|------|----------|----------|
| 库集成方式 | 库代码被拷贝到可执行文件中 | 运行时加载 .dll / .so / .dylib |
| 文件大小 | 更大 | 更小 |
| 部署 | 不需要依赖库文件 | 需要系统上有对应共享库 |
| 更新库 | 需重新链接 | 只需替换共享库文件 |
| GCC 参数 | `-static` | 默认（动态链接） |

**验证动态链接**：

```bash
gcc hello.c -o hello
ldd hello          # Linux 下查看动态库依赖
## macOS 用 otool -L hello
```

输出示例：

```
linux-vdso.so.1 (0x00007ffe...)
libc.so.6 => /lib/x86_64-linux-gnu/libc.so.6 (0x00007f...)
/lib64/ld-linux-x86-64.so.2 (0x00007f...)
```

##### 常见链接错误

**错误示例 1：未定义引用**

```c
// file: test.c
int main(void)
{
    func();   // func 未声明、未定义
    return 0;
}
```

```bash
gcc test.c -o test
## 输出：
## /usr/bin/ld: /tmp/ccXXXX.o: in function 'main':
## test.c:(.text+0x14): undefined reference to 'func'
## collect2: error: ld returned 1 exit status
```

**错误分析**：链接器在所有目标文件和库中都找不到 `func` 的定义。解决方案是补全函数定义或链接相应的库。

**错误示例 2：多重定义**

```c
// file: a.c
int counter = 0;
int main(void)
{
    return 0;
}
```

```c
// file: b.c
int counter = 0;    // 与 a.c 中同名，重复定义
```

```bash
gcc a.c b.c -o test
## 输出：
## /usr/bin/ld: b.o:(.data+0x0): multiple definition of 'counter'
## a.o:(.data+0x0): first defined here
## collect2: error: ld returned 1 exit status
```

**解决方案**：一个符号在整个程序中只能定义一次。多文件项目中，在头文件中使用 `extern` 声明，在唯一的 .c 文件中定义。

#### 一步到位

日常开发中，通常直接用一条命令完成全部四个阶段：

```bash
gcc file1.c file2.c -o program
```

这条命令等价于：

```bash
## 1. 预处理 + 编译 + 汇编（一步生成目标文件）
gcc -c file1.c -o file1.o
gcc -c file2.c -o file2.o
## 2. 链接
gcc file1.o file2.o -o program
```

### 基本语法要素

#### 语句与分号

C 程序由语句构成，**每条语句以分号 `;` 结尾**。

```c
int a = 10;           // 声明语句：声明变量并初始化
a = a + 1;            // 表达式语句：执行运算
printf("%d\n", a);    // 函数调用语句
;                     // 空语句：合法，什么都不做（有时在循环中使用）
```

> **错误示例**（缺少分号）：
> ```c
> int a = 10
> int b = 20;    // 编译错误：expected ';' after expression
> ```

#### 注释

C 语言支持两种注释方式：

```c
// 这是单行注释（C99 标准引入），从 // 到行尾都被忽略

/* 这是传统多行注释（自 C89 起支持）
   可以跨越多行
   注意：不能嵌套！
*/

/* 错误示例：嵌套注释会导致编译错误 */
/* 外层注释开始
    /* 内层注释 */
    这行代码会被当作未注释的代码，导致编译错误
*/
```

> **编码规范提示**：在嵌入式项目中，单行注释 `//` 更常见，因为它不容易出现嵌套问题且更安全。

#### 标识符命名规则

**标识符**（变量名、函数名、类型名）必须遵循以下规则：

| 规则 | 正确示例 | 错误示例 |
|------|----------|----------|
| 由字母、数字、下划线组成 | `count`, `_val`, `item1` | `my-var`（含连字符） |
| 不能以数字开头 | `var2` | `2var` |
| 区分大小写 | `Count` 和 `count` 不同 | - |
| 不能与关键字同名 | `value` | `int` |
| 以下划线开头的名称通常保留给系统 | 避免使用 `_` 前缀 | `_reserved` |

```c
int student_age;     // 规范：snake_case 命名风格（C 社区主流）
int studentAge;      // 可行但少见（camelCase 在 C 中不流行）
int _private;        // 可行但应避免（编译器可保留此类标识符）
```

#### 关键字

关键字是 C 语言保留的、有特殊含义的单词，不能用作标识符名。

**C11 标准的 44 个关键字：**

```
auto        break       case        char        const        continue
default     do          double      else        enum         extern
float       for         goto        if          inline       int
long        register    restrict    return      short        signed
sizeof      static      struct      switch      typedef      union
unsigned    void        volatile    while       _Alignas     _Alignof
_Atomic     _Bool       _Complex    _Generic    _Imaginary   _Noreturn
_Static_assert _Thread_local
```

其中 C89 定义了 32 个，C99 新增 `inline` `restrict` `_Bool` `_Complex` `_Imaginary`，C11 新增 `_Alignas` `_Alignof` `_Atomic` `_Generic` `_Noreturn` `_Static_assert` `_Thread_local`。

#### 空白符与代码风格

C 编译器忽略多余的空白符（空格、制表符、换行），它们只影响代码的可读性。

```c
// 以下三种写法对编译器来说完全相同：
int a = 0; a = a + 1; printf("%d", a);

int a = 0;
a = a + 1;
printf("%d", a);

int  a  =  0  ;
a = a + 1 ;
printf( "%d" , a ) ;
```

> **注意**：虽然编译器不关心，但良好的代码缩进和分行对团队协作和排错至关重要。推荐使用 4 空格缩进（或制表符），保持一致的风格。

### 常见编译错误与警告

编译器报错和警告是开发者的日常。学会阅读它们，比记住所有语法规则更重要。

#### 编译器报错信息的通用格式

```
文件名:行号:列号: 错误/警告类型: 错误描述
    代码所在行
    指向具体位置的提示 ^
```

#### 常见错误类型

##### 1. 缺少分号

```c
#include <stdio.h>

int main(void)
{
    int a = 10
    int b = 20;    // ← 报错在这里
    return 0;
}
```

编译输出：

```
test.c: In function 'main':
test.c:6:5: error: expected ';' before 'int'
     int b = 20;
     ^~~
```

> **解读**：编译器在第 5 行末尾没找到分号，在第 6 行发现 `int` 关键字，推断出前面缺少分号。实际上错误在第 5 行，但编译器报在第 6 行——**报错行号有时是"发现错误的位置"，不一定是错误发生的位置**。

##### 2. 未声明的函数（隐式声明）

```c
#include <stdio.h>

int main(void)
{
    foo();      // foo 未声明
    return 0;
}
```

编译输出（C99 之前仅警告，C99 之后为错误）：

```
test.c:5:5: warning: implicit declaration of function 'foo' [-Wimplicit-function-declaration]
     foo();
     ^~~
test.c:5:5: error: incompatible implicit declaration of built-in function 'foo' (if GCC thinks it's a built-in)
```

> **注意**：隐式函数声明是 C89 允许但在 C99 中移除的特性。在 `-std=c99` 或更严格的模式下，隐式声明是错误。面试中常被问到："C99 和 C89 在函数声明上的区别？"

##### 3. 未使用的变量

```c
#include <stdio.h>

int main(void)
{
    int x = 10;    // 声明但从未使用
    return 0;
}
```

编译（需开启 `-Wall`）：

```
test.c:5:9: warning: unused variable 'x' [-Wunused-variable]
     int x = 10;
         ^
```

> **工程意义**：未使用的变量通常意味着逻辑遗漏或未完成的代码重构。在嵌入式项目中，未使用的变量可能浪费栈空间。

##### 4. 返回类型不匹配

```c
int func(void)
{
    return 3.14;    // double 隐式转换为 int，丢失小数部分
}

int *get_ptr(void)
{
    int x = 10;
    return &x;      // 返回局部变量地址，严重错误！
}
```

编译输出：

```
test.c:3:12: warning: return makes integer from pointer without a cast [-Wint-conversion]
     return 3.14;
            ^~~~
test.c:8:12: warning: function returns address of local variable [-Wreturn-local-addr]
     return &x;
            ^~
```

第二个错误（返回局部变量地址）极为危险：函数返回后，局部变量 `x` 的内存被回收，指针变成**悬空指针**，解引用时行为未定义。

#### 警告 vs 错误

| 类型 | 编译器行为 | 是否需要修复 |
|------|-----------|-------------|
| **错误（error）** | 不生成目标文件/可执行文件 | **必须修复** |
| **警告（warning）** | 仍生成可执行文件 | **强烈建议修复** |

> **工程实践**：严格要求零警告。很多嵌入式项目（如汽车电子、航空航天）的编码规范要求开启 `-Werror` 将警告升级为错误。

### GCC/Clang 编译选项详解

#### 核心编译选项速查表

| 选项 | 作用 | 使用场景 |
|------|------|----------|
| `-o <文件>` | 指定输出文件名 | 所有编译 |
| `-E` | 只进行预处理 | 调试宏展开、查看 `#include` 展开 |
| `-S` | 只进行预处理 + 编译，生成汇编 | 调试或学习汇编代码 |
| `-c` | 只生成目标文件（不链接） | 多文件项目分步编译 |
| `-std=c11` | 指定 C 语言标准版本 | 确保代码符合特定标准 |
| `-Wall` | 开启大多数常见警告 | 几乎所有项目 |
| `-Wextra` | 开启额外警告 | 更严格的项目 |
| `-Wpedantic` | 对非标准扩展发出警告 | 追求严格标准兼容 |
| `-Werror` | 将警告当作错误处理 | 嵌入式项目、CI 环境 |
| `-g` | 生成调试信息 | 配合 GDB 调试 |
| `-O0` | 不优化（默认） | 调试阶段 |
| `-O1` | 基本优化 | 一般发布 |
| `-O2` | 进一步优化（推荐） | 发布版本 |
| `-O3` | 激进优化，可能增大体积 | 性能敏感场景 |
| `-Os` | 优化体积 | ROM 有限的嵌入式设备 |
| `-D 宏名=值` | 在命令行定义宏 | 条件编译、调试开关 |

#### 选项详解

##### 警告控制家族

```bash
## 日常开发推荐的最小配置
gcc -Wall -Wextra -std=c11 program.c -o program

## 追求严格标准兼容（嵌入式项目常用）
gcc -Wall -Wextra -Wpedantic -Werror -std=c11 program.c -o program

## 最激进的警告集（适合在 CI 中使用）
gcc -Wall -Wextra -Wpedantic -Werror -Wconversion -Wshadow -Wcast-align \
    -Wstrict-overflow=5 -std=c11 program.c -o program
```

##### 优化级别对比

```bash
## 调试时：无优化，调试体验最好
gcc -O0 -g program.c -o program

## 发布时：平衡性能与体积
gcc -O2 program.c -o program

## 内存受限的嵌入式设备
gcc -Os program.c -o program
```

> **注意**：优化级别越高，调试体验越差（变量可能被优化掉、代码顺序被重排）。`-O0` 和 `-g` 是调试期的最佳组合。

### 嵌入式开发中的编译工具链

#### 什么是工具链

**工具链**（Toolchain）是一套用于将源代码转换为可在目标设备上运行的程序的工具集合，包括编译器、汇编器、链接器、调试器、库文件等。

#### 交叉编译

**交叉编译**（Cross-compilation）指在一种架构（主机，如 x86 PC）上编译出在另一种架构（目标机，如 ARM 单片机）上运行的代码。

```
                     编译
  x86 PC (主机) ───────────→ ARM 单片机 (目标)
  运行交叉编译器             运行生成的机器码
```

#### ARM GCC 工具链

嵌入式开发最常用的交叉编译工具链：

```bash
## 安装 ARM 交叉编译器（Linux）
sudo apt install gcc-arm-none-eabi

## 常用命令
arm-none-eabi-gcc --version
arm-none-eabi-gcc -c main.c -o main.o    # 编译 ARM 目标文件
arm-none-eabi-objdump -d main.o          # 反汇编查看 ARM 指令
arm-none-eabi-size main.o                # 查看各段大小
```

工具链名称含义：

| 名称段 | 含义 |
|--------|------|
| `arm` | 目标架构是 ARM |
| `none` | 没有操作系统（bare-metal） |
| `eabi` | 嵌入式应用二进制接口（Embedded ABI） |

#### Make 与 CMake 基础

##### Make 基础

`Makefile` 定义规则，告诉 `make` 命令如何编译和链接：

```makefile
## 最简单的 Makefile
hello: hello.c
    gcc -Wall -std=c11 hello.c -o hello

clean:
    rm -f hello
```

```bash
make      # 编译 hello
make clean  # 清除编译产物
```

##### CMake 基础

CMake 是更高级的构建系统生成器，跨平台支持更好：

```cmake
## CMakeLists.txt
cmake_minimum_required(VERSION 3.10)
project(hello C)
set(CMAKE_C_STANDARD 11)

add_executable(hello hello.c)
```

```bash
mkdir build && cd build
cmake ..
make
```

> **嵌入式场景**：STM32CubeMX、ESP-IDF 等嵌入式 SDK 底层都使用 CMake 或 Makefile 组织构建。

### 面试直连

以下 Q&A 覆盖 C 语言入门章节的最高频面试题。

#### Q1: 简述 C 语言编译的四个阶段

**考察点**：对编译过程的理解深度。

**参考答案**：

C 语言从源码到可执行文件经历四个阶段：

1. **预处理**（Preprocessing）：预处理器处理 `#include`、`#define`、条件编译等指令。可用 `gcc -E` 观察。
2. **编译**（Compilation）：将预处理后的 C 代码翻译为汇编代码。进行词法分析、语法分析、语义分析、优化。可用 `gcc -S` 观察。
3. **汇编**（Assembly）：将汇编代码转换为机器码，生成目标文件 (.o)。可用 `gcc -c` 执行。
4. **链接**（Linking）：将多个目标文件和库文件合并为可执行文件。解决符号引用和地址重定位。

**追问**：如果不加 `-c`，GCC 是分步执行还是一步完成的？——从用户视角看是一步完成，但内部按顺序执行上述四个阶段。

#### Q2: `#include <stdio.h>` 发生了什么？

**考察点**：对预处理机制的理解。

**参考答案**：

`#include` 是一条预处理指令。当预处理器遇到 `#include <stdio.h>` 时：

1. 在系统标准头文件路径（Linux 下通常是 `/usr/include`）搜索 `stdio.h`。
2. 将 `stdio.h` 的全部内容**递归插入**到当前源文件中 `#include` 所在的位置。
3. 如果 `stdio.h` 内部又有 `#include`，同样递归展开。

使用 `gcc -E hello.c -o hello.i` 可以查看展开后的文件，原本几行的代码会变成数百行。

`#include <...>` 与 `#include "..."` 的区别：尖括号只在系统路径搜索；双引号先在当前目录搜索，找不到再去系统路径。

#### Q3: 声明（Declaration）和定义（Definition）的区别是什么？

**考察点**：C 语言编译链接的核心概念。

**参考答案**：

- **声明**（Declaration）：告诉编译器**存在**这样一个变量或函数，但不分配内存或提供实现。以 `extern` 关键字开头。
- **定义**（Definition）：**实际创建**变量（分配内存）或函数（提供函数体）。

```c
extern int x;        // 声明：告诉编译器 x 存在，但不在本文件中定义
int x = 10;          // 定义：分配内存并初始化

int func(void);      // 函数声明（也称函数原型）
int func(void)       // 函数定义：提供函数体
{
    return 42;
}
```

**关键规则**：
- 变量/函数可以声明**多次**，但只能定义**一次**（one definition rule）。
- 违反了就是 `multiple definition` 链接错误。

#### Q4: 什么是 "undefined reference" 错误？如何解决？

**考察点**：链接阶段错误的排查能力。

**参考答案**：

`undefined reference to 'xxx'` 是**链接阶段**错误，表示链接器在所有目标文件和库中都无法找到符号 `xxx` 的定义。

**常见原因与解决**：

| 原因 | 解决 |
|------|------|
| 调用了函数但未实现 | 补全函数定义 |
| 忘记链接某个源文件 | `gcc main.c helper.c` 而不是 `gcc main.c` |
| 忘记链接第三方库 | 加 `-lm`（数学库）、`-lpthread` 等 |
| C++ 代码中调用 C 函数未加 `extern "C"` | 添加 `extern "C"` |
| 函数声明与定义不匹配 | 检查参数列表是否一致 |

#### Q5: `main` 函数中 `return 0` 的含义是什么？

**考察点**：对程序退出机制的理解。

**参考答案**：

`return 0;` 表示向操作系统返回退出码（exit code）。

- `0` 表示程序成功执行（正常退出）
- 非零值表示某种错误（不同值可对应不同错误类型）
- 在 shell 中使用 `echo $?` 查看返回码
- 脚本和 Makefile 利用返回码判断程序执行结果

C 标准（C99 起）规定：如果 `main` 函数末尾没有显式 `return`，编译器会自动返回 `0`（这是对 `main` 的特例处理）。

> **延伸**：在嵌入式环境下，`main` 返回意味着什么？——在裸机（bare-metal）系统中，`main` 函数通常不应该返回，因为返回后没有操作系统来回收资源。一般的做法是用 `while(1)` 无限循环。

### 代码阅读题

#### 题目 1：找出代码中的错误

```c
#include <stdio.h>

int main()
{
    int a = 5
    int b = 10;
    int sum = a + b;

    printf("Sum is: %d\n" sum);

    return 0;
}
```

**提示**：代码中有两处语法错误。

<details>
<summary>点击查看答案</summary>

1. 第 5 行末尾缺少分号：`int a = 5` 应为 `int a = 5;`
2. 第 8 行 `printf` 调用中，格式字符串和参数之间缺少逗号：应为 `printf("Sum is: %d\n", sum);`

> 编译器会报 `expected ';'` 和 `expected ')'` 错误。注意第一个错误在第 6 行被"发现"（因为第 5 行缺少分号，编译器在第 6 行才察觉）。
</details>

#### 题目 2：预测程序输出

```c
#include <stdio.h>

#define SQUARE(x) x * x

int main(void)
{
    int a = 5;
    int result = SQUARE(a + 1);
    printf("result = %d\n", result);
    return 0;
}
```

**问题**：这个程序的输出是什么？为什么？

<details>
<summary>点击查看答案</summary>

**输出**：
```
result = 11
```

**原因**：宏只是文本替换，不是函数调用。`SQUARE(a + 1)` 展开为 `a + 1 * a + 1`，按照优先级计算为 `5 + 1*5 + 1 = 5 + 5 + 1 = 11`。

**正确做法**：宏定义中应为 `#define SQUARE(x) ((x) * (x))`，这样 `SQUARE(a+1)` 展开为 `((a+1)*(a+1))`，结果为 `36`。

> **面试提示**：宏展开的细节是 C 语言面试经典题，尤其需要注意运算符优先级和参数多次求值的问题。
</details>
