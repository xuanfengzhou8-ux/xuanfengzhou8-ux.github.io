## 一、作用域详解

### 1.1 直觉理解

**作用域（Scope）** 决定了变量在程序哪个范围内"可见"（可以访问）。

**生活中的类比**：
- **块作用域** = 你的房间：你在房间里说话，只有房间里的人能听到
- **函数作用域** = 你家的房子：房子里的人能听到，外面的人要敲门（函数参数声明）
- **文件作用域** = 你的日记本：你写的内容只有你自己能看到（除非你选择"公开"）
- **函数原型作用域** = 电话簿上的名字：只有打电话时才有用

### 1.2 四种作用域

#### （1）块作用域（Block Scope）

在 `{ }` 内部声明的变量，从声明处到 `}` 结束可见。**最常见的作用域**。

```c
#include <stdio.h>

int main(void) {
    int x = 10;              // x 从声明处到 main 函数结束可见

    {
        int y = 20;          // y 只在这个内层块中可见
        printf("%d %d\n", x, y);  // 内层块可以访问外层变量
    }

    // printf("%d\n", y);    // 错误：y 已超出作用域
    printf("%d\n", x);       // 正确：x 仍在作用域内
    return 0;
}
```

**同名变量遮蔽规则**：

```c
#include <stdio.h>

int main(void) {
    int n = 1;

    {
        int n = 2;           // 遮蔽外层 n
        {
            int n = 3;       // 遮蔽更外层的 n
            printf("最内层: %d\n", n);  // 3
        }
        printf("中层: %d\n", n);        // 2
    }
    printf("外层: %d\n", n);            // 1
    return 0;
}
```

> **规则**：内层块中的同名变量会遮蔽（Shadowing）外层变量。C 允许这种行为，但良好的编码规范（如 MISRA-C）禁止过度的遮蔽，因为容易引发混淆。

#### （2）文件作用域（File Scope）

在所有函数之外声明的变量或函数，从声明处到文件末尾可见。

```c
#include <stdio.h>

int global_count = 0;         // 文件作用域，从这行开始到文件结束

void increment(void) {
    global_count++;           // 可以访问
}

int main(void) {
    increment();
    increment();
    printf("%d\n", global_count);  // 2
    return 0;
}
```

#### （3）函数作用域（Function Scope）

**仅适用于 `goto` 标签**。标签在整个函数中可见，即使标签定义在 goto 语句之后。

```c
#include <stdio.h>

int main(void) {
    goto cleanup;             // 可以向前跳转

    // ... 一些代码 ...

cleanup:                      // 标签在整个函数中可见
    printf("清理完成\n");
    return 0;
}
```

这是唯一一种不会"从声明点到块结束"的作用域——标签的作用域是整个函数。

#### （4）函数原型作用域（Function Prototype Scope）

在函数原型（声明）的参数列表中声明的变量名，只在原型声明的作用域内有效。**参数名在原型作用域中实际上被忽略，编译器只看类型**。

```c
// x, y 在原型作用域中——可以省略，或使用任何名字
int add(int x, int y);

// 以下声明与上面等价（参数名不同也无所谓）
int add(int a, int b);

// 甚至完全省略参数名
int add(int, int);
```

**为什么理解这个重要**：
- 编写头文件时，函数原型中的参数名不是签名的一部分
- 头文件中的参数名只起到文档作用
- 函数原型中的参数名不会与外部变量冲突（它们只在这个"狭窄"的作用域中存在一瞬间）

```c
// 下面这种代码是合法的：原型中的参数名不参与编译
int foo(int bar);             // 声明

int main(void) {
    int bar = 42;             // 与原型中的 bar 没有冲突
    return foo(bar);
}

int foo(int baz) {            // 定义中可以使用不同的参数名
    return baz * 2;
}
```

## 二、存储类说明符

### 2.1 概述

存储类说明符（Storage Class Specifiers）决定了变量的**存储位置**、**生命周期**和**链接属性**。

C11 标准定义了五种存储类说明符：

| 说明符 | 存储位置 | 生命周期 | 链接属性 | 典型用途 |
|--------|---------|---------|---------|---------|
| `auto` | 栈 | 块作用域内 | 无链接 | 局部变量（默认，极少显式使用） |
| `register` | 寄存器（建议） | 块作用域内 | 无链接 | 高频访问的局部变量（现代编译器自动优化） |
| `static` | 静态区 | 程序全程 | 内部链接 | 隐藏实现细节、函数内持久状态 |
| `extern` | 静态区 | 程序全程 | 外部链接 | 引用其他文件的变量或函数 |
| `typedef` | — | — | — | 创建类型别名 |

### 2.2 auto —— 默认存储类

```c
int main(void) {
    auto int x = 10;   // 等价于 int x = 10，auto 几乎从不使用
    return 0;
}
```

`auto` 是块作用域变量的默认存储类，显式写出来只是语法冗余。C++11 后 `auto` 被重新用作类型推导，含义完全不同。

### 2.3 register —— 建议放入寄存器

```c
void heavy_loop(void) {
    register int i;           // 建议编译器将 i 放入寄存器
    for (i = 0; i < 100000; i++) {
        // ...
    }
}
```

**限制**：
- 不能对 `register` 变量取地址（&），因为它可能没有内存地址
- 现代编译器对寄存器分配比程序员更智能，`register` 实际上已很少使用

### 2.4 static —— 多功能关键字（详细见第五节）

### 2.5 extern —— 外部引用（详细见第六节）

### 2.6 typedef —— 创建类型别名

```c
typedef unsigned long long uint64;   // 定义类型别名
typedef int (*FuncPtr)(int, int);    // 函数指针类型别名

uint64 data = 100ULL;               // 等价于 unsigned long long
FuncPtr fp = &add;                  // 函数指针变量
```

`typedef` 虽被归类为存储类说明符，但它并不控制存储或生命周期——它只是创建类型别名。

## 三、链接属性

### 3.1 三种链接属性

链接属性（Linkage）决定了一个标识符（变量或函数）在**多个编译单元**之间如何共享。

| 链接属性 | 关键字控制 | 可见范围 | 典型场景 |
|---------|-----------|---------|---------|
| **外部链接（External Linkage）** | 默认（或 `extern`） | 所有文件 | 全局变量、API 函数 |
| **内部链接（Internal Linkage）** | `static` | 仅本文件 | 文件内辅助函数、私有数据 |
| **无链接（No Linkage）** | 默认 | 仅本块 | 局部变量 |

### 3.2 默认链接属性

- **函数**：默认具有外部链接（除非用 `static` 限制）
- **全局变量**：默认具有外部链接（除非用 `static` 限制）
- **局部变量**：无链接（即使是 `static` 局部变量也是无链接——它只在本函数内可见，但生命周期延长）

### 3.3 static 和 extern 对链接的影响

```c
// file1.c
int global_var = 10;          // 外部链接 —— 其他文件可以通过 extern 访问
static int hidden_var = 20;   // 内部链接 —— 仅 file1.c 可见

void public_func(void) {      // 外部链接 —— API
    // ...
}

static void helper(void) {    // 内部链接 —— 文件内部使用
    // ...
}
```

```c
// file2.c
extern int global_var;        // 正确：引用 file1.c 中的全局变量
// extern int hidden_var;     // 错误：hidden_var 是内部链接

void public_func(void);       // 正确：引用 file1.c 中的函数

int main(void) {
    return global_var;
}
```

**核心原则**：
- `static` 将链接属性从"外部"降级为"内部"
- `extern` 声明一个已经在其他文件中定义的外部链接标识符
- 编译器检查作用域，链接器检查链接属性

## 四、.h 与 .c 的分工

### 4.1 核心原则

| 文件类型 | 放什么 | 不放什么 |
|---------|-------|---------|
| **.h（头文件）** | 函数声明、类型定义、宏、extern 变量声明 | 函数定义、变量定义 |
| **.c（源文件）** | 函数定义、变量定义 | （合理的例外：static 内联函数可放在 .h 中） |

### 4.2 声明放 .h，定义放 .c

```c
// ============ math_ops.h ============
#ifndef MATH_OPS_H
#define MATH_OPS_H

// 类型定义（可以放在头文件）
typedef struct {
    int numerator;
    int denominator;
} Fraction;

// 函数声明
Fraction add_fraction(Fraction a, Fraction b);
Fraction subtract_fraction(Fraction a, Fraction b);
void print_fraction(Fraction f);

#endif
```

```c
// ============ math_ops.c ============
#include "math_ops.h"
#include <stdio.h>

// 函数定义
Fraction add_fraction(Fraction a, Fraction b) {
    Fraction result;
    result.numerator = a.numerator * b.denominator + b.numerator * a.denominator;
    result.denominator = a.denominator * b.denominator;
    return result;
}

void print_fraction(Fraction f) {
    printf("%d/%d\n", f.numerator, f.denominator);
}
```

```c
// ============ main.c ============
#include "math_ops.h"

int main(void) {
    Fraction a = {1, 2};
    Fraction b = {1, 3};
    Fraction c = add_fraction(a, b);
    print_fraction(c);   // 5/6
    return 0;
}
```

### 4.3 #include guard

**为什么需要**：一个头文件可能被多个源文件间接包含多次，导致重复声明错误。

**两种主流方式**：

**方式一：#ifndef 守卫（传统方法，可移植性最好）**
```c
#ifndef MATH_OPS_H       // 如果还没有定义 MATH_OPS_H
#define MATH_OPS_H       // 定义它

// ... 头文件内容 ...

#endif                   // 结束 #ifndef
```

**方式二：#pragma once（现代方法，更简洁）**
```c
#pragma once              // 告诉编译器：本文件只被包含一次

// ... 头文件内容 ...
```

| 对比 | `#ifndef` | `#pragma once` |
|------|-----------|---------------|
| 可移植性 | 所有 C 编译器都支持 | 大多数主流编译器支持（GCC、Clang、MSVC、IAR） |
| 防止重复包含的机制 | 宏定义标记 | 编译器内部记录文件路径 |
| 误用风险 | 宏名冲突可能导致意外跳过 | 无宏名冲突风险 |
| 代码简洁性 | 需要三行模板代码 | 一行即可 |

**最佳实践**：对于需要最高可移植性的项目（如跨平台库）使用 `#ifndef`；新项目推荐使用 `#pragma once`（大多数嵌入式交叉编译器支持）。

## 五、多文件编译

### 5.1 编译单元概念

**编译单元（Translation Unit）** 是编译器一次处理的基本单位：一个 `.c` 文件 + 它所 `#include` 的所有头文件（经过预处理后）。

```
编译单元 = 源文件 + 所有 #include 展开后的文本
```

```bash
# 查看预处理后的编译单元
gcc -E main.c -o main.i     # 展开所有 #include 和宏
gcc -c main.i -o main.o     # 编译为机器码（目标文件）
```

### 5.2 编译与链接过程

```
源文件 (.c)     → 预处理 → 编译 (.s 汇编) → 汇编 (.o 目标文件)
                 （展开#include、宏）       （生成机器码）

目标文件 (.o)   → 链接 → 可执行文件
                 （解析符号引用、地址重定位）
```

### 5.3 常见链接错误

#### 错误 1：undefined reference

```bash
/usr/bin/ld: /tmp/ccxxxxxx.o: undefined reference to `function_name'
collect2: error: ld returned 1 exit status
```

**原因**：链接器找到了声明，但找不到定义。常见场景：
- 忘记编译某个 .c 文件
- 忘记链接某个库（如 `-lm` 链接数学库）
- 函数定义在其他文件中但编译时未包含

**修复**：
```bash
# 错误：未链接数学库
gcc main.c -o main
# undefined reference to `sqrt'

# 正确：链接数学库
gcc main.c -o main -lm
```

#### 错误 2：multiple definition

```bash
/usr/bin/ld: /tmp/ccxxxxxx.o: multiple definition of `global_var'
/tmp/ccyyyyyy.o: first defined here
```

**原因**：同一个全局变量在多个 .c 文件中定义了。

**修复**：
- 在一个 .c 文件中定义，其他文件用 `extern` 声明
- 或者使用 `static` 限制为内部链接

```c
// 错误：两个文件都定义了同一个全局变量
// file1.c: int counter = 0;
// file2.c: int counter = 0;

// 正确：
// file1.c: int counter = 0;         // 定义
// file2.c: extern int counter;      // 声明（引用 file1.c 的）
```

### 5.4 编译多文件项目的完整流程

```bash
# 步骤1：将每个 .c 文件编译为 .o 目标文件
gcc -std=c11 -Wall -Wextra -Wpedantic -c main.c -o main.o
gcc -std=c11 -Wall -Wextra -Wpedantic -c math_ops.c -o math_ops.o
gcc -std=c11 -Wall -Wextra -Wpedantic -c io_utils.c -o io_utils.o

# 步骤2：链接所有目标文件为可执行文件
gcc main.o math_ops.o io_utils.o -o program

# 或者一步到位
gcc -std=c11 -Wall -Wextra -Wpedantic main.c math_ops.c io_utils.c -o program

# 使用 Makefile 自动化（推荐）
```

## 六、static 的三种用法

`static` 是 C 语言中多义性最强的关键字之一，在不同语境下含义不同。

### 6.1 用法一：静态局部变量

```c
#include <stdio.h>

int counter(void) {
    static int count = 0;   // 只初始化一次，函数返回后不销毁
    count++;                // 每次调用时值被保留
    return count;
}

int main(void) {
    printf("%d\n", counter());  // 1
    printf("%d\n", counter());  // 2
    printf("%d\n", counter());  // 3
    return 0;
}
```

**特征**：
- 生命周期：程序运行全程（存储在静态区）
- 链接属性：无链接（仅在其定义的函数内可见）
- 初始化：只初始化一次，之后的调用跳过初始化语句
- 默认初始值：0（如果不显式初始化）

**与普通局部变量的对比**：

| 特性 | 普通局部变量 | static 局部变量 |
|------|-------------|----------------|
| 存储位置 | 栈 | 静态区 |
| 生命周期 | 函数调用期间 | 程序全程 |
| 初始化 | 每次调用都执行 | 仅第一次调用时执行 |
| 默认初值 | 不确定（垃圾值） | 0 |
| 多线程安全 | 安全（每次独立） | 不安全（共享） |

### 6.2 用法二：内部链接函数

限制了函数只在当前文件内可见，其他文件无法调用。

```c
// ============ internal_utils.c ============
// 仅在此文件内部使用的辅助函数
static void validate_input(int value) {
    if (value < 0) {
        // 错误处理
    }
}

void public_api(int x) {
    validate_input(x);   // 内部使用
    // ...
}

// ============ other_file.c ============
// extern void validate_input(int value);  // 错误：链接不到
```

### 6.3 用法三：内部链接全局变量

```c
// ============ module.c ============
static int internal_state = 0;  // 仅本文件可见的全局变量

static int get_state(void) {    // 仅本文件可见的函数
    return internal_state;
}

int module_do_something(void) {
    internal_state++;
    return get_state();
}
```

**工程意义**：
- **信息隐藏（封装）**：外部只能通过 API 函数交互，不能直接操作内部状态
- **减少命名冲突**：不同文件的 `static` 变量可以同名而不会冲突
- **降低耦合**：修改内部实现不影响外部代码

## 七、extern 详解

### 7.1 引用其他文件的变量

```c
// counter.c
int total = 0;                // 定义

void increment(void) {
    total++;
}
```

```c
// main.c
#include <stdio.h>

extern int total;             // 声明：total 在其他文件中定义

int main(void) {
    increment();              // total++
    printf("%d\n", total);    // 1
    return 0;
}
```

**区分定义和声明**：
```c
int x;               // 定义（在文件作用域时，有试探性定义 tentativedefinition，最终被分配空间）
extern int x;        // 声明（只是告知编译器 x 存在，不分配空间）
extern int x = 10;   // 定义（因为显式初始化了，extern 被忽略）
```

**正确做法**：
- 在**一个** .c 文件中定义变量（`int var;` 或 `int var = 0;`）
- 在**头文件**中用 `extern` 声明（`extern int var;`）
- 其他文件包含头文件即可使用

### 7.2 引用其他文件的函数

```c
// utils.h
void print_hello(void);       // 函数声明默认具有 extern 语义

// utils.c
#include <stdio.h>
void print_hello(void) {      // 定义
    printf("Hello\n");
}

// main.c
#include "utils.h"            // 包含声明
// 或直接写 extern void print_hello(void);

int main(void) {
    print_hello();            // 调用其他文件的函数
    return 0;
}
```

函数声明默认就是 `extern` 的，所以 `extern` 关键字通常省略。

### 7.3 extern "C"

**问题**：C++ 编译器会对函数名进行名字修饰（Name Mangling）以支持函数重载，而 C 编译器不做。如果 C 代码编译的库被 C++ 项目调用，链接器找不到修饰后的名字。

**解决方案**：使用 `extern "C"` 告诉 C++ 编译器：这部分代码按 C 的链接规则处理。

```c
// 一个被 C 和 C++ 共同使用的头文件
#ifdef __cplusplus
extern "C" {                   // 如果是 C++ 编译器，启用 C 链接
#endif

void c_function(int x);
int another_c_func(void);

#ifdef __cplusplus
}
#endif
```

**平台声明**：`extern "C"` 是 C++ 特有的语法。在纯 C 编译器中 `__cplusplus` 宏未定义，所以 `extern "C"` 部分不会被 C 编译器看到。如果项目中不涉及 C++，可以完全忽略此特性。

## 八、const 与链接

### 8.1 C 语言中 const 全局变量的链接属性

C 语言中的 **`const` 全局变量默认具有外部链接**（与 C++ 不同，C++ 中 const 全局变量默认内部链接）。

```c
// config.c
const int MAX_SIZE = 1024;    // C：外部链接；C++：内部链接
```

```c
// main.c
extern const int MAX_SIZE;    // 在 C 中可以正确引用
```

### 8.2 在 C 中模拟 C++ 的 const 内部链接

```c
// 使用 static 将 const 全局变量限制为内部链接
// constants.h
static const int BUFFER_SIZE = 256;   // 每个包含此头文件的文件都有自己的副本
```

**注意**：这会导致每个包含此头文件的 .c 文件各有一份 `BUFFER_SIZE` 的副本，增加了代码体积。更好的方法是在一个 .c 中定义，在头文件中 `extern` 声明。

```c
// constants.h
extern const int BUFFER_SIZE;

// constants.c
const int BUFFER_SIZE = 256;
```

## 九、头文件设计原则

### 9.1 最小包含原则

```c
// 好的做法：只包含必要的头文件
#include <stdint.h>          // 需要 uint32_t
#include "my_types.h"        // 需要自定义类型

// 不好的做法：包含不需要的头文件
#include <stdio.h>           // 如果头文件中不需要 I/O 功能
#include <stdlib.h>          // 不必要的包含会拖慢编译
```

**规则**：
- 只在头文件中包含它**必须依赖**的头文件（如定义中用到的类型）
- 如果只是**指针或引用**某个类型，使用前向声明（`struct MyType;`）而非包含头文件
- 实现文件（.c）可以包含所有需要的头文件

### 9.2 避免循环依赖

```c
// 循环依赖示例（错误设计）
// a.h: #include "b.h"
// b.h: #include "a.h"
// 这会导致编译错误：类型未定义

// 修复：使用前向声明
// a.h: struct B;      // 前向声明，不包含 b.h
// b.h: struct A;      // 前向声明，不包含 a.h
```

**循环依赖的检测**：
- 编译时出现"类型未定义"或"结构体不完整"错误
- 在大型项目中，可以用工具（如 `cpp-dependencies`）生成包含关系图

### 9.3 只放声明，不放定义

| 可以放在 .h 中 | 不应放在 .h 中 |
|---------------|---------------|
| 函数声明 | 函数定义（inline 函数除外） |
| 类型定义（struct、union、enum、typedef） | 变量定义 |
| 宏定义 | 函数定义中的逻辑 |
| extern 变量声明 |
| static inline 函数定义 |

**原因**：头文件被多个 .c 包含后，变量定义会导致"multiple definition"链接错误。

### 9.4 头文件模板

```c
/*
 * filename:   module_name.h
 * description: 模块功能的简要描述
 * author:     作者
 * date:       创建日期
 */

#ifndef MODULE_NAME_H
#define MODULE_NAME_H

#include <stdint.h>          // 标准库包含
#include "dependent.h"       // 项目内依赖

#ifdef __cplusplus
extern "C" {
#endif

/* ========== 类型定义 ========== */
typedef struct {
    uint32_t id;
    uint8_t status;
} ModuleState;

/* ========== 宏常量 ========== */
#define MODULE_MAX_COUNT  100

/* ========== 函数声明 ========== */
void module_init(void);
int module_process(ModuleState *state, uint32_t timeout_ms);
void module_shutdown(void);

/* ========== extern 变量声明 ========== */
extern int module_global_counter;

#ifdef __cplusplus
}
#endif

#endif /* MODULE_NAME_H */
```

## 十、嵌入式中的多文件编程

### 10.1 启动文件（Startup File）

嵌入式程序启动时，执行环境还不完整（如全局变量未初始化、堆栈未设置）。**启动文件**（通常用汇编编写）负责：

1. 设置栈指针（SP）
2. 初始化 `.bss` 段（清零未初始化的全局变量）
3. 初始化 `.data` 段（将初始值从 Flash 复制到 RAM）
4. 调用 `main` 函数
5. 如果 `main` 返回，进入死循环或调用 `exit`

```asm
; ARM Cortex-M 启动文件示意（伪代码）
    Reset_Handler:
        LDR   R0, =_estack      ; 设置栈指针
        MOV   SP, R0
        BL    SystemInit         ; 系统时钟初始化
        BL    __libc_init_array  ; 初始化 C 运行时
        BL    main               ; 调用 main
        B     .                  ; 死循环
```

**平台声明**：启动文件的实现完全依赖于具体 MCU 架构和工具链。上述是 ARM Cortex-M 的典型流程。

### 10.2 链接脚本（Linker Script）

链接脚本告诉链接器如何将不同的段（Section）映射到目标芯片的内存地址上。

```ld
/* 链接脚本示意 —— GNU LD 语法 */
MEMORY
{
    FLASH (rx)  : ORIGIN = 0x08000000, LENGTH = 512K
    RAM   (rwx) : ORIGIN = 0x20000000, LENGTH = 128K
}

SECTIONS
{
    .text :                     /* 代码段 */
    {
        *(.isr_vector)          /* 中断向量表 */
        *(.text)                /* 程序代码 */
        *(.rodata)              /* 只读数据 */
    } > FLASH

    .data :                     /* 已初始化数据 */
    {
        *(.data)
    } > RAM AT > FLASH

    .bss :                      /* 未初始化数据 */
    {
        *(.bss)
    } > RAM
}
```

**平台声明**：上述语法是 GNU LD（GCC 工具链）的链接脚本格式，IAR、Keil 等商业工具有不同的语法。

### 10.3 向量表（Vector Table）

中断向量表是 MCU 启动时查找中断处理函数入口地址的表格，通常定义在启动文件中。

```c
// ARM Cortex-M 向量表示意
typedef void (*handler_t)(void);

// 向量表被放置在 Flash 的最开头（0x08000000）
handler_t vector_table[] __attribute__((section(".isr_vector"))) = {
    (handler_t)&_estack,       // 初始栈指针
    Reset_Handler,             // 复位向量
    NMI_Handler,               // 不可屏蔽中断
    HardFault_Handler,         // 硬件错误
    // ... 其他中断处理函数 ...
    TIM2_IRQHandler,           // 定时器 2 中断
    USART1_IRQHandler,         // 串口 1 中断
};
```

**嵌入式多文件项目的典型结构**：

```
project/
├── startup_stm32f103.s      # 启动文件（汇编）
├── stm32f103.ld             # 链接脚本
├── main.c                   # 主函数
├── gpio.h / gpio.c          # GPIO 驱动模块
├── uart.h / uart.c          # UART 驱动模块
├── timer.h / timer.c        # 定时器驱动模块
├── interrupt_handlers.c     # 中断处理函数（C 语言）
└── Makefile                 # 构建脚本
```

## 十一、面试直连

### Q1: static 关键字的三种用法是什么？

**A**: （1）修饰局部变量——延长生命周期为程序全程，但作用域不变；（2）修饰全局变量——限制为内部链接，仅本文件可见；（3）修饰函数——限制为内部链接，仅本文件可调用。面试加分：能现场写出每种用法的代码示例，并说出对应的链接属性变化。

### Q2: 头文件中的 #include guard 是做什么的？如果不写会怎样？

**A**: 防止头文件被同一个编译单元多次 `#include`，导致重复定义或声明错误。如果不写，当一个头文件被间接包含两次时（如 a.h 包含 b.h，而 c.h 也包含 b.h，最终 main.c 同时包含 a.h 和 c.h），编译器会报重复定义结构体、重复声明函数等错误。面试加分：能区分 `#ifndef` 和 `#pragma once` 的优缺点。

### Q3: extern 的作用是什么？

**A**: `extern` 声明一个变量或函数是在其他文件中定义的，告诉编译器"这个名字已经在别处定义了，不要分配空间，链接阶段再找"。函数声明默认就是 extern 的，所以 extern 主要是用来声明其他文件的全局变量（如 `extern int global;`）。

### Q4: 声明（Declaration）和定义（Definition）的根本区别？

**A**: 声明告诉编译器"这个标识符存在以及它的类型"（不分配存储空间）；定义告诉编译器"这个标识符的具体内容"（分配存储空间）。一个变量或函数可以有多次声明，但只能有一次定义。判断标准：看是否分配了存储空间——函数的花括号、变量的初始化都会触发定义。

### Q5: undefined reference 和 multiple definition 链接错误的区别和解决方法？

**A**: `undefined reference` 是链接器找到了声明但没找到定义——添加缺少的 .o 文件或库。`multiple definition` 是链接器发现同一个符号被定义了多次——检查是否在头文件中定义了变量（只应在 .c 中定义），或使用 static 限定。面试加分：能说出在头文件中 `int var;` 和 `extern int var;` 的区别。

### Q6: const 全局变量在不同文件中的链接属性如何？C 和 C++ 有区别吗？

**A**: 在 C 中，`const` 全局变量默认具有外部链接，其他文件可以用 `extern` 引用。在 C++ 中，`const` 全局变量默认具有内部链接（类似 `static`），每个文件得到自己的副本。所以 C 代码的 `const` 全局变量如果需要在 C++ 中使用，可能需要显式加 `extern`。

### Q7: 函数的声明带有参数名和省略参数名有什么区别？

**A**: 对编译器来说没有区别——`int foo(int x, int y)` 和 `int foo(int, int)` 是同一个函数原型。参数名只在函数定义中必须存在（因为函数体需要访问它们），在声明中仅起文档作用。这也体现了函数原型作用域的特性——原型中的参数名在原型结束后即不可见。

### Q8: 编译多个 .c 文件时，头文件中的内容会被重复处理吗？如何保证效率？

**A**: 是的，每个 .c 文件（编译单元）独立地包含和处理头文件。如果头文件很大，会显著拖慢编译速度。优化方法：（1）使用预编译头文件（PCH）；（2）在头文件之间减小不必要的包含依赖（最小包含原则）；（3）使用增量编译（只重新编译修改过的 .c 文件）。

## 十二、代码阅读题

### 题1

```c
// file1.c
static int hidden = 42;

int get_hidden(void) {
    return hidden;
}

// file2.c
#include <stdio.h>

extern int hidden;      // 这行能通过编译吗？
extern int get_hidden(void);

int main(void) {
    printf("%d\n", get_hidden());
    return 0;
}
```

**问题**：上述代码能成功编译和链接吗？为什么？如果第 2 行的 `static` 去掉，结果又如何？

<details>
<summary>答案</summary>
`extern int hidden;` 在链接时会导致 `undefined reference` 错误，因为 `hidden` 在 file1.c 中是 `static`（内部链接），其他文件无法访问。如果去掉 `static`，`hidden` 变成外部链接，则编译链接成功。但更规范的写法是在 file1.c 中定义 `int hidden = 42;`，在头文件中 `extern int hidden;`。
</details>

### 题2

```c
// header.h
int global_counter = 0;
void increment(void);

// a.c
#include "header.h"
void increment(void) { global_counter++; }

// b.c
#include "header.h"
int main(void) {
    increment();
    return 0;
}
```

**问题**：分别编译 `a.c` 和 `b.c` 后链接，会发生什么？为什么？如何修复？

<details>
<summary>答案</summary>
出现 `multiple definition of 'global_counter'` 链接错误。因为 `header.h` 中 `int global_counter = 0;` 是变量定义，被 a.c 和 b.c 都包含后产生了两个定义。修复：在 .h 中改为 `extern int global_counter;`，在 a.c 中定义 `int global_counter = 0;`。这是 C 编程中最常见的错误之一。
</details>

### 题3

```c
#include <stdio.h>

int x = 10;

int main(void) {
    int x = 20;

    {
        int x = 30;
        printf("块内: %d\n", x);
    }

    printf("main内: %d\n", x);
    return 0;
}

void func(void) {
    // printf("x = %d\n", x);
}
```

**问题**：输出结果是什么？如果取消 `func` 中的注释，它会输出什么值？这段代码体现了什么规则？

<details>
<summary>答案</summary>
输出：`块内: 30`、`main内: 20`。如果取消注释，`func` 会输出 `10`（文件作用域的全局变量）。这体现了：内层变量遮蔽外层同名变量；各函数有独立的作用域链。
</details>

## 本章总结

1. **四种作用域**：块作用域（最常见）、文件作用域（全局变量）、函数作用域（仅用于标签）、函数原型作用域（参数名可省略）
2. **五种存储类说明符**：auto（默认）、register（寄存器建议）、static（内部链接/延长生命周期）、extern（外部引用）、typedef（类型别名）
3. **三种链接属性**：外部链接（跨文件共享）、内部链接（仅本文件）、无链接（块范围内）
4. **.h 声明，.c 定义**是模块化编程的核心约定，#include guard 防止重复包含
5. **多文件编译**：先各自编译为 .o，再链接为可执行文件；了解 undefined reference 和 multiple definition 的排查
6. **static 三种用途**：延长局部变量生命周期、限制函数为内部链接、限制全局变量为内部链接
7. **extern** 引用其他文件的变量和函数，`extern "C"` 是 C++ 调用 C 代码的桥梁
8. **const 全局变量**在 C 中默认外部链接（与 C++ 不同）
9. **头文件设计原则**：最小包含、避免循环依赖、只放声明
10. **嵌入式多文件**涉及启动文件（汇编）、链接脚本、中断向量表等特殊概念
