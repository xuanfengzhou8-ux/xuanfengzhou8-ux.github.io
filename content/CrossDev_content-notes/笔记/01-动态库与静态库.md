# 动态库与静态库

> 本章目标：理解“库”如何复用代码，并知道静态库和动态库在交叉开发中的部署差异。

## 1. 为什么需要库

当多个程序都需要使用同一组函数时，不应该把相同代码复制到每个项目里。更好的方式是把这些函数编译成库，再由其他程序链接使用。

库的好处：

- **复用代码**：多个程序共享同一套函数接口。
- **隐藏实现**：用户只需要头文件和库文件，不必看到内部源码。
- **便于维护**：接口稳定时，可以独立修改库的内部实现。
- **适合模块化**：把数学、通信、协议、驱动适配等功能分离出来。

## 2. 从源码到库的基本过程

假设有两个源文件：

```c
// sum.c
int sum(int a, int b) {
    return a + b;
}
```

```c
// sub.c
int sub(int a, int b) {
    return a - b;
}
```

头文件：

```c
// mymath.h
#ifndef MYMATH_H
#define MYMATH_H

int sum(int a, int b);
int sub(int a, int b);

#endif
```

使用库的程序：

```c
// main.c
#include <stdio.h>
#include "mymath.h"

int main(void) {
    printf("sum = %d\n", sum(3, 2));
    printf("sub = %d\n", sub(3, 2));
    return 0;
}
```

## 3. 动态库 `.so`

动态库在程序运行时被加载。多个程序可以共享同一份动态库代码。

### 3.1 生成目标文件

```bash
gcc -c -fPIC sum.c -o sum.o
gcc -c -fPIC sub.c -o sub.o
```

`-fPIC` 表示生成位置无关代码，动态库通常需要它。

### 3.2 生成动态库

```bash
gcc -shared -o libmymath.so sum.o sub.o
```

库名通常遵循：

```text
lib<库名>.so
```

例如 `libmymath.so` 的库名是 `mymath`。

### 3.3 链接动态库

```bash
gcc main.c -I . -L . -lmymath -o app
```

含义：

| 选项 | 含义 |
|---|---|
| `-I .` | 头文件搜索路径 |
| `-L .` | 库文件搜索路径 |
| `-lmymath` | 链接 `libmymath.so` 或 `libmymath.a` |
| `-o app` | 输出可执行文件 |

### 3.4 运行时库路径

如果运行时报错找不到动态库，可以临时设置：

```bash
export LD_LIBRARY_PATH=$LD_LIBRARY_PATH:.
./app
```

查看程序依赖的动态库：

```bash
ldd app
```

## 4. 静态库 `.a`

静态库在链接时会把用到的目标代码合入可执行文件。程序运行时通常不再依赖 `.a` 文件。

### 4.1 生成目标文件

```bash
gcc -c sum.c -o sum.o
gcc -c sub.c -o sub.o
```

### 4.2 打包静态库

```bash
ar -rc libmymath.a sum.o sub.o
```

查看静态库内容：

```bash
ar -t libmymath.a
```

### 4.3 链接静态库

```bash
gcc main.c -I . -L . -lmymath -o app
```

如果当前目录同时存在 `.so` 和 `.a`，链接器可能优先选择动态库。需要强制静态链接时，可以使用：

```bash
gcc main.c -I . -L . -Wl,-Bstatic -lmymath -Wl,-Bdynamic -o app
```

## 5. 静态库与动态库对比

| 对比项 | 静态库 `.a` | 动态库 `.so` |
|---|---|---|
| 链接时机 | 编译链接时合入程序 | 运行时加载 |
| 可执行文件大小 | 通常更大 | 通常更小 |
| 运行时依赖 | 通常不依赖 `.a` | 需要找到 `.so` |
| 更新库实现 | 需要重新链接程序 | 接口兼容时可替换库 |
| 部署复杂度 | 简单 | 需要处理库路径 |
| 内存占用 | 多个程序可能各有一份 | 多个程序可共享 |

## 6. 交叉开发中的注意点

交叉编译时，编译器和库必须属于同一目标平台。不能把主机上的库直接拿到开发板程序里链接。

示例：

```bash
arm-linux-gcc main.c -I ./include -L ./lib -lmymath -o app
```

需要确认：

- `arm-linux-gcc` 是目标平台对应的交叉编译器。
- `./lib/libmymath.so` 或 `.a` 是用同一工具链编译出来的。
- 部署动态库时，要把 `.so` 一起复制到目标系统。
- 运行时要配置库搜索路径，例如 `/lib`、`/usr/lib` 或 `LD_LIBRARY_PATH`。

## 7. 推荐学习顺序

1. 先手动写两个 `.c` 文件和一个 `.h` 文件。
2. 分别生成 `.so` 和 `.a`。
3. 用同一个 `main.c` 链接它们。
4. 删除动态库后运行程序，观察错误。
5. 用 `ldd` 查看依赖，理解运行时链接。

## 8. 自学任务

1. 编写 `sum.c`、`sub.c`、`mymath.h`、`main.c`。
2. 生成一个动态库 `libmymath.so` 并链接运行。
3. 生成一个静态库 `libmymath.a` 并链接运行。
4. 使用 `ldd` 查看动态库依赖。
5. 模拟部署：把可执行文件和 `.so` 放到另一个目录，设置 `LD_LIBRARY_PATH` 后运行。
