## 时间复杂度

### O(n) — 线性阶

```c
for(i = 0; i < n/2 - 4; i++)
{
    // 这个循环要执行 n 次
}
// 时间复杂度 O(n)
```

### O(n²) — 平方阶

```c
for(j = 0; j < m; j++)
{
    for(i = 0; i < n/2 - 5; i++)
    {
        // 语句执行 n² 次
    }
}
// 时间复杂度 O(n²)
```

> (n²/5 + n) == O(n²)，取最高次项

### O(log n) — 对数阶

```c
n = 1;
while(n < m)
{
    n = n * 2;  // log₂m 次
}
// 时间复杂度 O(log n)
```

### O(n log n) — 线性对数阶

```c
for(i = 0; i < m; i++)
{
    n = 1;
    while(n < m)
    {
        n = n * 2;  // m × log₂m
    }
}
// 时间复杂度 O(n log n)
```

## 空间复杂度

- 要求空间复杂度为 O(1)：不能开辟与问题规模相关的额外空间
- **以时间换空间** vs **以空间换时间**
- 限制一种方法：**暴力破解法**

### 示例：数组移位

```
1 4 3 2 5  →  2 5 1 4 3    // O(n) 时间, O(1) 空间（原地逆置）
                           // 或 O(n) 空间（开辟新数组 data[n]）
```

## 时间复杂度与空间复杂度的权衡

### 嵌入式场景下的时间复杂度分析

在嵌入式系统中，时间复杂度分析不仅关乎程序运行得快慢，更关乎系统能否满足**实时性要求**：

- **硬实时系统**（如汽车刹车控制、飞行控制系统）：必须在规定时间内完成计算，否则造成灾难性后果 → 需要**最坏情况时间复杂度（WCET, Worst-Case Execution Time）**保证
- **软实时系统**（如音频播放、传感器数据采集）：偶尔超时可接受，但频繁超时会影响用户体验

#### 不同量级在嵌入式 CPU 上的具体表现（假设 MCU 主频 72MHz，每条指令约 1~2 个时钟周期）

| 数据规模 n | O(log n) | O(n) | O(n log n) | O(n²) |
|-----------|----------|------|------------|-------|
| 10        | ~4 条指令 | ~10 条 | ~40 条 | ~100 条 |
| 100       | ~7 条指令 | ~100 条 | ~700 条 | ~10,000 条 |
| 1,000     | ~10 条指令 | ~1,000 条 | ~10,000 条 | ~1,000,000 条 |
| 10,000    | ~14 条指令 | ~10,000 条 | ~140,000 条 | ~100,000,000 条 |

> 在 72MHz MCU 上，100 万条指令约需 14ms。对于 1ms 中断周期、O(n²) 算法处理 1000 个数据点，单次执行就需要 14ms，**远超中断周期**，必须优化。

### 为什么数据结构选择对嵌入式系统至关重要

| 因素 | 说明 | 影响 |
|------|------|------|
| **内存限制** | RAM 可能只有几 KB~几百 KB | 链表的指针开销（每个节点额外 4~8 字节）可能不可接受 |
| **实时约束** | 必须在截止时间前完成操作 | 哈希表 O(1) 平均但最坏 O(n)；数组 O(1) 随机访问更可预测 |
| **功耗** | CPU 运行时间越长功耗越大 | 高效的算法意味着更长的休眠时间 |
| **确定性** | 操作时间是否恒定 | 数组/FIFO 适合中断处理；动态内存分配应尽量避免 |
| **代码复杂度** | 影响可维护性和 Bug 率 | 简化代码往往更可靠，但可能牺牲性能 |

### 常用数据结构在嵌入式场景中的对比

| 数据结构 | 访问 | 查找 | 插入（头/尾） | 删除 | 内存开销 | 嵌入式适用场景 |
|---------|------|------|-------------|------|---------|--------------|
| **数组（静态）** | O(1) | O(n) | O(1)/O(1) | O(1)（尾部） | 最小，无额外开销 | 传感器数据缓冲区、查找表、固定大小的队列 |
| **链表** | O(n) | O(n) | O(1)/O(1) | O(1) | 大，每个节点额外指针 | 动态任务管理、内存池块管理（很少推荐） |
| **栈** | O(1)（顶） | O(n) | O(1) | O(1) | 小 | 函数调用栈、状态机状态保存、括号匹配 |
| **队列（环形缓冲）** | O(1) | O(n) | O(1) | O(1) | 最小（无需动态分配） | UART/SPI 接收缓冲、RTOS 消息队列 |
| **哈希表** | O(1) 平均 | O(1) 平均 | O(1) 平均 | O(1) 平均 | 较大（需预留空桶） | 命令解析表、配置键值查找（需静态分配） |
| **二叉树/堆** | O(log n) | O(log n) | O(log n) | O(log n) | 中等 | 优先级队列（堆）、任务调度、数据索引 |
| **位图（BitMap）** | O(1) | O(1) | O(1) | O(1) | 极小 | 内存分配管理、事件标志组、大量开关量存储 |

#### 嵌入式选型黄金法则

1. **优先使用静态分配**：嵌入式系统中 `malloc`/`free` 应尽量避免，或在初始化阶段一次分配完毕
2. **优先使用数组（环形缓冲）**：确定大小、无碎片、存取时间恒定
3. **避免递归**：深度递归可能导致栈溢出，改为循环实现
4. **考虑 Cache 友好性**：数组元素连续存储，cache 命中率远高于链表
5. **位运算替代复杂结构**：能用 uint32 位标记的，不要用链表或树

## 数据结构的四种基本类型

数据结构不仅要保存数据，还要保存数据之间的**逻辑关系**。

```
Data_structure = (D, S)
```

- **D (Data)**：数据元素的集合
- **S (Structure)**：建立在数据元素上的关系（物理关系、逻辑关系）

### 四种基本结构

1. **集合**（并查集）
   - 结构中的元素之间除了同属一个集合外，没有其他关系

2. **线性结构**
   - 就是一条直线，数据元素之间的关系是线性的

3. **树形结构**（层次结构）

4. **网状结构**（图）

## 逻辑结构 vs 存储结构

| | 逻辑结构 | 存储结构（物理结构） |
|---|---|---|
| **定义** | 数据存放的逻辑关系 | 数据元素在计算机存储器中的存储映像 |
| **特点** | 可以有多种逻辑关系 | 指数据在内存中的对应关系 |
| **关系** | 逻辑结构会影响存储结构 | 数据存放地址固定了，逻辑结构不一定固定 |

## 线性表

### 定义

线性表是**相同类型数据**的有限序列：
1. 存在唯一一个被称为"第一个元素"的元素
2. 存在唯一一个被称为"最后一个元素"的元素
3. 除了最后一个元素，每个元素都有一个**后继**元素
4. 除了第一个元素，每个元素都有一个**前驱**元素

### 线性表的两种物理结构实现

| | 顺序结构（数组） | 链式结构（链表） |
|---|---|---|
| **物理结构** | 连续 | 不连续 |
| **逻辑结构** | 连续 | 连续 |
| **数据保存** | 通过数组下标 | 通过数据域 |
| **关系保存** | 通过相邻位置 | 通过指针指向下一个数据 |

## 面试练习题

### 题目 1：分析以下代码的时间复杂度

（虚拟互联网公司甲 2022 校招）

```c
int func(int n) {
    int count = 0;
    for (int i = 1; i <= n; i *= 2) {
        for (int j = 0; j < i; j++) {
            count++;
        }
    }
    return count;
}
```

**答案与解析：**

外层循环变量 `i` 按 2 的幂次增长：1, 2, 4, 8, ..., n，共执行 log₂n 次。内层循环执行次数由当前的 `i` 值决定，分别是 1, 2, 4, 8, ... 次。总执行次数为：

```
T(n) = 1 + 2 + 4 + ... + n = 2×n - 1 = O(n)
```

所以时间复杂度为 **O(n)**，而不是 O(n log n)。这是一个经典的陷阱题，考察对循环嵌套累加求和的理解。

### 题目 2：空间换时间——如何用 O(1) 时间删除数组中的某个元素？

（虚拟生活服务公司戊 2023 秋招）

给定一个无序数组和要删除的元素下标 `idx`，要求在 O(1) 时间内完成删除（不考虑元素顺序）。

**答案与解析：**

通常删除数组元素需要将后续元素前移，时间复杂度 O(n)。若要达到 O(1)，可以用"覆盖末尾法"——将要删除的元素与数组最后一个元素交换，然后 `size--` 即可。

```c
void deleteBySwap(int arr[], int *size, int idx) {
    if (idx < 0 || idx >= *size) return;
    arr[idx] = arr[*size - 1];  // 用最后一个元素覆盖
    (*size)--;                   // 逻辑删除
}
```

**思路分析**：这是典型的"以空间换时间"的反面——**以时间换空间**的逆向思维。这里我们**牺牲了元素的有序性（额外"空间"代价）来换取 O(1) 的删除时间**。在嵌入式场景中，当数据无序且只需快速删除时，这个技巧非常实用。

### 题目 3：嵌入式场景——实时系统中应选择哪种数据结构？

（大疆 2022 校招）

在一个实时系统中，MCU 每隔 1ms 触发一次中断，将传感器数据（8 字节）存入缓冲区，主循环随后以 FIFO 顺序读取并处理。系统的 RAM 仅 64KB，且要求中断服务函数（ISR）执行时间不超过 10μs。请选择合适的数据结构并说明理由。

**答案与解析：**

**最佳选择：环形缓冲区（Circular Buffer / Ring Buffer）**

```c
#define BUF_SIZE 256
uint8_t ring_buf[BUF_SIZE][8];  // 256 个数据槽，每个 8 字节
volatile int head = 0, tail = 0;   // volatile 防止编译器优化

// ISR — 写入数据
void sensor_ISR(void) {
    int next = (head + 1) % BUF_SIZE;
    if (next != tail) {          // 缓冲区未满
        memcpy(ring_buf[head], sensor_data, 8);
        head = next;
    }
}

// 主循环 — 读取数据
void process_data(void) {
    if (tail != head) {
        process(ring_buf[tail]);
        tail = (tail + 1) % BUF_SIZE;
    }
}
```

**理由：**
1. **O(1) 插入和删除**：ISR 和主循环各只需几条指令，远小于 10μs
2. **无动态内存分配**：数组静态分配，无碎片问题
3. **RAM 占用可控**：仅 256 × 8 = 2KB，对 64KB 来说非常充裕
4. **确定性**：每次操作恒定时间，无最坏情况退化
5. **避免锁竞争**：单生产者单消费者模式下无需互斥锁

**为什么不选其他结构：**
- **链表**：动态分配 `malloc` 不可在 ISR 中使用，且指针碎片化
- **队列（动态）**：依赖堆分配，有碎片风险
- **数组 + 移位**：O(n) 删除不符合实时约束

### 题目 4：分析递归函数的时间复杂度

（虚拟通信公司己 2021 秋招）

```c
int fibonacci(int n) {
    if (n <= 1) return n;
    return fibonacci(n - 1) + fibonacci(n - 2);
}
```

(1) 分析上述代码的时间复杂度和空间复杂度。
(2) 如何优化？

**答案与解析：**

**(1) 复杂度分析**

该递归展开后形成一棵二叉树，树高为 n，节点数约为 2ⁿ，因此：
- **时间复杂度**：O(2ⁿ) — 指数级，n=45 时已经需要数十秒
- **空间复杂度**：O(n) — 递归调用栈深度为 n，而非 O(2ⁿ)。注意递归栈会复用，任一时刻最多 n 层

**(2) 优化方案**

**方案 A：记忆化搜索（以空间换时间）**

```c
int memo[100] = {0};
int fibonacci_memo(int n) {
    if (n <= 1) return n;
    if (memo[n] != 0) return memo[n];
    memo[n] = fibonacci_memo(n - 1) + fibonacci_memo(n - 2);
    return memo[n];
}
// 时间复杂度 O(n)，空间复杂度 O(n)
```

**方案 B：迭代法（以时间换空间）**

```c
int fibonacci_iter(int n) {
    if (n <= 1) return n;
    int a = 0, b = 1, c;
    for (int i = 2; i <= n; i++) {
        c = a + b;
        a = b;
        b = c;
    }
    return b;
}
// 时间复杂度 O(n)，空间复杂度 O(1)
```

**嵌入式启示**：在资源受限的嵌入式 MCU 上，递归深度过大会导致栈溢出。迭代法 O(n)/O(1) 是 Fibonacci 在嵌入式中的唯一合理选择。

### 题目 5：如何选择数据结构和算法？——"两数之和"问题

（LeetCode 经典题，虚拟互联网公司甲 2022 春招改编）

给定一个整数数组和一个目标值 target，找出数组中和为 target 的两个数，返回它们的下标。要求在嵌入式环境下实现，从"空间换时间"和"时间换空间"两个角度分别给出方案。

**答案与解析：**

**方案 1：暴力法（时间换空间）**

```c
void twoSum_bruteforce(int arr[], int n, int target, int *idx1, int *idx2) {
    for (int i = 0; i < n - 1; i++) {
        for (int j = i + 1; j < n; j++) {
            if (arr[i] + arr[j] == target) {
                *idx1 = i;
                *idx2 = j;
                return;
            }
        }
    }
}
// 时间复杂度 O(n²)，空间复杂度 O(1)
```

**适用场景**：RAM 极小（<1KB），n 很小（如 n≤50），实时性要求不高。

**方案 2：哈希表法（空间换时间）**

```c
// 假设数值范围已知，用数组模拟哈希表
#define MAX_VAL 1000
int hash[MAX_VAL * 2 + 1];  // 支持负数，偏移映射

void twoSum_hash(int arr[], int n, int target, int *idx1, int *idx2) {
    for (int i = 0; i < n; i++) {
        int complement = target - arr[i];
        if (complement >= -MAX_VAL && complement <= MAX_VAL &&
            hash[complement + MAX_VAL] != 0) {
            *idx1 = hash[complement + MAX_VAL] - 1;  // 存储时 +1 避免 0 冲突
            *idx2 = i;
            return;
        }
        hash[arr[i] + MAX_VAL] = i + 1;
    }
}
// 时间复杂度 O(n)，空间复杂度 O(range)
```

**适用场景**：n 较大（如 n>1000）、实时性要求高、已知数值范围。

**嵌入式决策树：**
- RAM < 1KB 或 n < 50 → 暴力法（时间换空间）
- RAM ≥ 对应数组大小且需要高性能 → 哈希表法（空间换时间）
- 搜索空间有限且已知 → 查表法（最快，O(1)）

### 题目 6：用栈实现括号匹配的复杂度分析

（虚拟互联网公司丙 2023 秋招）

实现一个函数，判断给定的括号字符串是否合法（包含 `()`, `[]`, `{}`），并分析时间复杂度和空间复杂度。

**答案与解析：**

```c
#include <stdbool.h>

bool isValid(char *s) {
    char stack[1000];
    int top = -1;

    for (int i = 0; s[i] != '\0'; i++) {
        char c = s[i];
        if (c == '(' || c == '[' || c == '{') {
            stack[++top] = c;  // 左括号入栈
        } else {
            if (top == -1) return false;  // 无左括号匹配
            char left = stack[top--];     // 右括号出栈匹配
            if ((c == ')' && left != '(') ||
                (c == ']' && left != '[') ||
                (c == '}' && left != '{')) {
                return false;
            }
        }
    }
    return top == -1;  // 栈空则全部匹配
}
```

**复杂度分析：**
- **时间复杂度**：O(n)，只需一次遍历，每个字符入栈/出栈一次
- **空间复杂度**：O(n)，最坏情况全部为左括号（如 `((((...`），栈深度等于字符串长度

**嵌入式考量**：若字符串长度固定且已知（如配置文件中的括号检查），可使用静态数组模拟栈。若需节省空间，也可用数字计数器替代栈（仅对单一类型括号有效），但本题涉及三种类型括号，必须用栈保存括号类型信息，体现了"空间换时间"中必要的空间开销。

### 题目 7：分析以下循环的时间复杂度（含特殊边界）

（虚拟电商公司乙 2021 校招）

```c
int func(int n) {
    int sum = 0;
    for (int i = 1; i <= n; i++) {
        for (int j = i; j <= n; j += i) {
            sum++;
        }
    }
    return sum;
}
```

**答案与解析：**

外层循环 i 从 1 到 n，执行 n 次。内层循环 j 从 i 开始，步长为 i，即 j = i, 2i, 3i, ... ≤ n，因此内层执行次数为 n/i。

总执行次数：
```
T(n) = n/1 + n/2 + n/3 + ... + n/n
     = n × (1 + 1/2 + 1/3 + ... + 1/n)
     = n × H(n)         // H(n) 为调和数
```

调和数 H(n) ≈ ln n + γ（γ ≈ 0.577，欧拉常数），因此：

**时间复杂度：O(n log n)**

**嵌入式启示**：这种"跳跃式内层循环"的模式在筛法（如素数筛选）中常见。当 n=10⁵ 时，实际执行次数约 n×ln(10⁵) ≈ 1.15×10⁶，远小于 O(n²) 的 10¹⁰，对嵌入式场景是可接受的。这也说明了**大 O 表示法的常数项不可忽视**——同样的 O(n log n) 可能比另一个 O(n log n) 快数倍。
